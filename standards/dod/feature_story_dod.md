## How to Use This Checklist

1. **Copy this checklist** into every feature story's Jira ticket or GitHub issue.
2. **Review [L4] criteria** during story grooming with PO and Tech Lead.
3. **Check off criteria** as you complete them during development.
4. **All criteria must be checked** before the PR can be approved and merged.
5. **Exception process**: Layer 2+ criteria can be deferred with EM approval and written justification. Layer 1 criteria cannot be waived.

**Legend:**
- **[L1]** = Universal gate, applies to all work types, cannot be overridden
- **[L2]** = Work type-specific gate, can be exempted by EM for one sprint with justification
- **[L3]** = Team-specific gate based on tech stack/domain, requires Tech Lead approval to modify
- **[L4]** = Story-specific gate, added during grooming by PO or Tech Lead

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR shows 2+ approvals with at least 1 from senior engineer (visible in reviewers list).  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.1-SEC] PRs modifying authentication, authorization, payment processing, or PII handling have Security Champion approval.
**Verification:** Security Champion tagged in PR and has approved (visible in PR reviewers).  
**Exception:** Not applicable if PR does not touch security-critical paths.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub displays "Verified" badge on all commits in the PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** commitlint GitHub Action passes in CI checks.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR is configured for squash merge; merge commits to main are blocked by branch protection.
**Verification:** GitHub PR merge button shows "Squash and merge" as only option; branch protection rules visible in repo settings.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY/LOC/DEAD] SonarQube quality gate passes: cyclomatic complexity ≤10 per method, no methods >50 LOC, 0 dead code issues.
**Verification:** SonarQube status check passes in GitHub Actions; quality gate status visible in SonarQube dashboard.  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-SPRING-BOOT] Spring Boot services use constructor injection (not field injection) for all dependencies.
**Verification:** Code review confirms no @Autowired field annotations; SonarQube custom rule enforces this.  
**Exception:** Tech Lead can approve field injection for @Value properties only.

## Security

### [ ] [L1] [SEC-3.1-SNYK] Snyk scan reports 0 Critical or High severity findings.
**Verification:** Snyk GitHub Actions check passes; Snyk report in CI shows 0 Critical/High vulnerabilities.  
**Exception:** No exceptions. Findings must be fixed or have CISO-accepted risk waiver ticket.

### [ ] [L1] [SEC-3.1-SNYK] All Medium severity findings from Snyk have corresponding Jira tickets linked in PR.
**Verification:** Snyk report shows Medium findings; PR description includes Jira ticket links (format: SEC-XXX).  
**Exception:** No exceptions if Medium findings exist. No action required if 0 Medium findings.

### [ ] [L1] [SEC-3.2-SECRETS] Gitleaks scan passes in CI with 0 secrets detected.
**Verification:** Gitleaks GitHub Actions check passes; no leaked secrets reported in CI logs.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-4.2-SECRETS-MGMT] All secrets stored in AWS Secrets Manager or GitHub Actions secrets; verified by Gitleaks scan.
**Verification:** Code review confirms secrets retrieved from AWS SDK or GitHub context; Gitleaks passes; no hardcoded credentials in diff.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] mvn dependency:check reports 0 Critical CVE findings in CI.
**Verification:** Maven dependency check GitHub Actions step passes; OWASP dependency-check report shows 0 Critical CVEs.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS-APPROVAL] All new dependencies are listed in approved dependency registry; CI checks compliance.
**Verification:** Custom GitHub Action (check-dependencies.yml) passes; pom.xml or package.json changes reviewed against approved-dependencies.yaml.  
**Exception:** No exceptions. New dependencies require Security Champion approval before adding to registry.
