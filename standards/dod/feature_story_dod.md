## How to Use This Checklist

Every feature story must satisfy **all applicable criteria** before being marked as "Done" and merged to `main`.

- **[L1-UNIVERSAL]** — Applies to ALL work items. Cannot be overridden. Requires EM + CISO sign-off to modify.
- **[L2-WORKTYPE]** — Applies to ALL feature stories. EM can grant one-sprint exemption with written justification.
- **[L3-TEAM]** — Team-specific additions. Tech Lead approval required for exemptions. Reviewed quarterly.
- **[L4-STORY]** — Story-specific criterion added by PO or Tech Lead during grooming. Optional.

**Escaped Defect Criteria** — Tagged `[From INC-NNN]` — derived from production incidents. Mandatory for all future work.

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR page shows 2+ approvals, at least 1 with "Senior Engineer" or "Tech Lead" role label.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.1-SEC] Security-critical PRs have approval from Security Champion documented in PR comments.
**Verification:** If PR touches authentication, authorization, payment, or data encryption code, PR shows approval comment from designated Security Champion.  
**Exception:** EM can grant one-sprint exemption with written justification if Security Champion unavailable.

### [ ] [L1] [ENG-4.2-SIGNING] All commits are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit list shows "Verified" badge on all commits in PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-FORMAT] All commit messages follow Conventional Commits format verified by commitlint in GitHub Actions.
**Verification:** GitHub Actions check "commitlint" passes with green status.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR merged using squash merge strategy (GitHub branch protection enforces this).
**Verification:** GitHub branch protection rules show "Require squash merge" enabled; merge button shows "Squash and merge" only.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube dashboard shows quality gate "Passed" status; Complexity tab shows 0 methods exceeding complexity threshold 10.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.3-LENGTH] SonarQube reports 0 methods exceeding 50 lines of code.
**Verification:** SonarQube Issues tab filtered by "Rule: Methods should not have too many lines" shows 0 issues.  
**Exception:** Tech Lead approval. Reviewed quarterly.

### [ ] [L1] [ENG-4.3-DEADCODE] SonarQube reports 0 dead code issues; manual PR review confirms no commented-out code blocks.
**Verification:** SonarQube Issues tab filtered by "Tag: unused" shows 0 issues; PR reviewer confirms in approval comment "No commented-out code found".  
**Exception:** No exceptions.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥80% line coverage on all changed modules in CI.
**Verification:** GitHub Actions "JaCoCo Report" job shows "Line Coverage: 80% or higher" for all changed Java packages.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥75% branch coverage on changed modules in CI.
**Verification:** GitHub Actions "JaCoCo Report" job shows "Branch Coverage: 75% or higher" for all changed Java packages.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] CI build verifies no existing covered code has lost coverage (coverage regression check passes).
**Verification:** GitHub Actions "Coverage Regression Check" job passes with green status; diff comment shows "No coverage lost on existing files".  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present for all changed production code; JUnit 5 test suite passes in CI.
**Verification:** GitHub Actions "Unit Tests" job shows green status; test report shows new tests added in same packages as changed production code.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [QA-2.2-INTEGRATION] Integration tests present and passing in CI (JUnit 5).
**Verification:** GitHub Actions "Integration Tests" job shows green status; test classes with @SpringBootTest annotation present in src/test/java covering feature flow.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [QA-2.2-E2E] Playwright E2E test covers happy path and passes in CI.
**Verification:** GitHub Actions "E2E Tests" job shows green status; Playwright test report shows test case named with feature story ticket ID covering primary user journey.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [QA-2.2-E2E] Playwright E2E test covers at least 1 error path and passes in CI.
**Verification:** GitHub Actions "E2E Tests" job shows green status; Playwright test report shows test case covering validation error or system error scenario.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [From INC-001] Integration test verifies SSO login flow for all configured authentication methods (JUnit 5).
**Verification:** Integration test class SSOLoginFlowTest exists in src/test/java with test methods covering all auth providers listed in application.yml (OAuth2, SAML, LDAP).  
**Exception:** EM can grant one-sprint exemption with written justification.

## Security

### [ ] [L1] [SEC-3.1-SAST] Snyk scan shows 0 Critical/High findings.
**Verification:** GitHub Actions "Snyk Security Scan" job shows green status with summary "0 Critical, 0 High vulnerabilities".  
**Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver.

### [ ] [L1] [SEC-3.1-SAST] All Medium severity Snyk findings have tracked Jira tickets attached to PR.
**Verification:** If Snyk report shows Medium findings, PR description contains "Security findings: JIRA-XXX, JIRA-YYY" with valid ticket links.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2-SECRETS] Gitleaks scan passes with 0 secrets detected in GitHub Actions CI.
**Verification:** GitHub Actions "Gitleaks Scan" job shows green status with output "No leaks found".  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] npm audit (React) or mvn dependency:check (Java) produces 0 Critical CVE findings in CI.
**Verification:** GitHub Actions "Dependency Audit" job shows green status; npm audit output shows "0 vulnerabilities (Critical)" OR mvn dependency-check-report.html shows "0 Critical CVEs".  
**Exception:** No exceptions.

### [ ] [L2] [SEC-3.3-DEPS] All dependencies listed in approved dependency registry (verified by PR checklist).
**Verification:** PR author confirms in PR checklist comment: "All new dependencies approved via deps.yaml registry" OR "No new dependencies added".  
**Exception:** Tech Lead approval
