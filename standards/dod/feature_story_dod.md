## Overview

This Definition-of-Done checklist defines the quality gates that **every Feature Story** must pass before being considered complete and ready for production deployment.

**Layer Key:**
- **[L1-UNIVERSAL]** — Applies to ALL work items of any type. Cannot be overridden without EM + CISO sign-off.
- **[L2-WORKTYPE]** — Applies to all Feature Stories. EM can grant one-sprint exemption with written justification.
- **[L3-TEAM]** — Commerce Platform team-specific. Tech Lead approval required for exemption. Reviewed quarterly.
- **[L4-STORY]** — Story-specific additions defined by PO or Tech Lead during grooming.

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead
**Verification:** GitHub PR approval count visible in PR UI shows ≥2 approvals with at least 1 from senior engineer  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.1-SEC] PRs touching security-critical code paths have additional approval from Security Champion
**Verification:** GitHub PR shows approval from user with Security Champion role (if PR modifies auth, encryption, or payment flows)  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L1] [ENG-4.2] All commits are signed with GPG or SSH key registered in GitHub

**Exception:** No exceptions.

**Verification:** GitHub branch protection rules enforce squash merge; PR merge button shows "Squash and merge" only  
**Exception:** No exceptions.

**Verification:** SonarQube dashboard shows Quality Gate = PASSED with 0 complexity violations  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] No method exceeds 50 lines of code
