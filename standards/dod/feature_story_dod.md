## 📋 How to Use This Checklist

This Definition of Done must be satisfied before a **Feature Story** can be merged to `main` and deployed to production.

### Layer Legend
- **[L1-UNIVERSAL]** — Applies to ALL work items. Cannot be skipped. Requires EM + CISO sign-off to modify.
- **[L2-WORKTYPE]** — Specific to Feature Stories. EM can grant one-sprint exemption with written justification.
- **[L3-TEAM]** — Commerce Platform team-specific based on our tech stack (Java, Spring Boot, React, PostgreSQL, Kafka). Tech Lead approval required to modify. Reviewed quarterly.
- **[L4-STORY]** — Story-specific additions defined by PO or Tech Lead during grooming. Optional—delete if not needed.

### Policy Traceability
Every criterion is tagged with its source policy reference (e.g., `[ENG-4.1]`, `[QA-2.1-LINE]`, `[SEC-3.1-SNYK]`). See **Policy Traceability Matrix** at end of document.

## 1️⃣ Code Quality

### [ ] [L1-UNIVERSAL] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR shows 2+ approvals with at least 1 reviewer having "Senior Engineer" or "Tech Lead" role in GitHub team settings.  
**Exception:** No exceptions.

---

### [ ] [L1-UNIVERSAL] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub shows "Verified" badge on all commits in the PR commit list.  
**Exception:** No exceptions.

---

### [ ] [L1-UNIVERSAL] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** commitlint check passes in GitHub Actions workflow. All commit messages match pattern: `^(feat|fix|docs|style|refactor|test|chore)(\(.+\))?: .+$`  
**Exception:** No exceptions.

---

### [ ] [L1-UNIVERSAL] [ENG-4.2-MERGE] PR merged using squash merge (verified by GitHub branch protection).
**Verification:** GitHub branch protection settings enforce "Require linear history" and "Allow squash merging" only. Merge commit option disabled.  
**Exception:** No exceptions.

---

### [ ] [L1-UNIVERSAL] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube CI check shows Quality Gate status PASSED. SonarQube dashboard shows 0 methods exceeding complexity threshold of 10.  
**Exception:** No exceptions.

---

### [ ] [L1-UNIVERSAL] [ENG-4.3-LOC] No method exceeds 50 lines of code (enforced by SonarQube).
**Verification:** SonarQube CI check shows 0 code smells with rule "Methods should not be too long" (threshold: 50 lines).  
**Exception:** No exceptions.

---

### [ ] [L1-UNIVERSAL] [ENG-4.3-DEAD] No dead code, unreachable code, or commented-out code present (SonarQube detects).
**Verification:** SonarQube CI check shows 0 issues with tags "unused" or "dead-code". Manual code review confirms no commented-out code blocks.  
**Exception:** No exceptions.

---

### [ ] [L2-WORKTYPE] [ENG-4.1-SEC] Security-critical PRs have approval from Security Champion in addition to standard 2 approvals.
**Verification:** If PR modifies files in `src/main/java/com/acme/auth/`, `src/main/java/com/acme/payment/`, or `application-security.yml`: GitHub PR shows approval from user with `@security-champion` team membership.  
**Exception:** No exceptions for security-critical paths.
