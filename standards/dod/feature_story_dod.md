## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR approval list shows 2+ approvals, with at least 1 from user tagged as Senior Engineer or Tech Lead in team roster.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.1-SEC] Security-critical PRs include approval from designated Security Champion.
**Verification:** GitHub PR approval list includes approval from user designated as Security Champion (if PR touches authentication, authorization, cryptography, PII handling, or payment processing).  
**Exception:** Skip if PR does not touch security-critical paths. Security Champion approval required otherwise.

### [ ] [L1] [ENG-4.2] All commits are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit history shows "Verified" badge on all commits in the PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions workflow "commitlint" passes, validating all commit messages match pattern: `^(feat|fix|docs|style|refactor|test|chore)(\(.+\))?: .+$`  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR uses squash merge strategy (not merge commit).
**Verification:** GitHub PR merge button configured to "Squash and merge". Merge commit option disabled in repository settings.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube dashboard shows Quality Gate status = PASSED. Complexity metric for all changed methods ≤10 (visible in SonarQube Issues tab filtered by type:CODE_SMELL, tag:brain-overload).  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] No method exceeds 50 lines of code (verified by SonarQube quality gate).
**Verification:** SonarQube dashboard shows 0 issues with rule "squid:S138" (Methods should not have too many lines). Threshold configured at 50 LOC.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports zero dead code issues (unreachable or commented-out code).
**Verification:** SonarQube dashboard shows 0 issues with tags:unused,unused-private-method,commented-out-code. Check Issues tab filtered by these tags.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present and passing for all new/changed business logic (JUnit 5).
**Verification:** GitHub Actions workflow "unit-tests" passes. JUnit 5 test report shows 0 failures, 0 skipped tests. All new/changed @Service, @Component, and business logic classes have corresponding *Test.java files in src/test/.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-INT] Integration tests present and passing for service-to-service interactions (JUnit 5 + Mockito or TestContainers).
**Verification:** GitHub Actions workflow "integration-tests" passes. Tests in src/test/**/integration/ or annotated with @SpringBootTest verify interactions with PostgreSQL, Kafka, or external service mocks. Test report shows 0 failures.  
**Exception:** Skip if feature does not involve service-to-service or database interactions.

### [ ] [L2] [QA-2.2-E2E] E2E test covers happy path and at least 1 error path scenario (Playwright).

Playwright test file in e2e-tests/ directory covers: (1) happy path user journey from login to feature completion, (2) at least 1 error scenario (e.g., invalid input, network timeout, permission denied). Test report artifact shows both scenarios passing.  
**Exception:** No exceptions.
