## Test Coverage & Quality

- [ ] **[L1] [QA-2.1-COVERAGE-LINE]** JaCoCo reports ≥80% line coverage on all changed modules.  
  **Verification:** GitHub Actions JaCoCo check passes. CI comment shows line coverage ≥80% for each modified Java package.  
  **Exception:** No exceptions.

- [ ] **[L1] [QA-2.1-COVERAGE-BRANCH]** JaCoCo reports ≥75% branch coverage on all changed modules.  
  **Verification:** GitHub Actions JaCoCo check passes. CI comment shows branch coverage ≥75% for each modified Java package.  
  **Exception:** No exceptions.

- [ ] **[L1] [QA-2.1-NO-REGRESSION]** CI coverage check passes with no regression on existing covered code (JaCoCo diff shows no coverage loss).  
  **Verification:** GitHub Actions JaCoCo diff check passes. No previously covered lines show as uncovered in diff report.  
  **Exception:** No exceptions.

- [ ] **[L2] [QA-2.2-UNIT]** Unit tests present using JUnit 5 and Mockito covering changed code paths.  
  **Verification:** New test files present in src/test/java/ matching changed classes. Tests use @Test (JUnit 5) and @Mock/@InjectMocks (Mockito). All tests pass in CI.  
  **Exception:** Engineering Manager can grant one-sprint exemption with written justification if refactoring existing fully-covered code with no logic changes.

- [ ] **[L2] [QA-2.2-INTEGRATION]** Integration tests present covering service interactions and data flow.  
  **Verification:** Tests present in src/test/java/**/integration/ using @SpringBootTest. Tests verify API-to-database flow or inter-service calls. All tests pass in CI.  
  **Exception:** Engineering Manager can grant one-sprint exemption with written justification if feature is pure UI with no backend changes.

- [ ] **[L2] [QA-2.2-E2E]** E2E tests present using Playwright covering happy path plus minimum 1 error path scenario.  
  **Verification:** Tests present in e2e/tests/ using Playwright test framework. At least 2 test cases: 1 happy path (test("happy path")) and 1 error path (test("error: ..."). All tests pass in CI.  
  **Exception:** Engineering Manager can grant one-sprint exemption with written justification if feature is backend-only with no UI changes.

- [ ] **[L2] [QA-2.4-PERF]** k6 load test present in CI for endpoint, reporting P95 < 500ms and P99 < 2000ms under normal load.  
  **Verification:** If PR adds or modifies API endpoint expected to handle >1000 RPS, k6 test present in tests/performance/. GitHub Actions k6 check passes with summary showing p(95)<500ms and p(99)<2000ms.  
  **Exception:** Engineering Manager can grant one-sprint exemption with written justification if endpoint is internal-only or low-traffic (<100 RPS expected).

- [ ] **[L2] [From INC-001]** Integration test present verifying SSO login flow for all configured authentication providers.  
  **Verification:** If PR modifies authentication or login functionality, integration test present in src/test/java/**/auth/integration/ verifying OAuth flow for each provider in application.yml (auth.providers list). Tests use @SpringBootTest with WireMock for OAuth server simulation.  
  **Exception:** Tech Lead approval if feature does not touch authentication flow.
