## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR approval count visible in PR header. Verify 1 approval has "Senior Engineer" or "Tech Lead" role badge.  
**Exception:** No exceptions.

### [ ] [L3] [ENG-4.1-SEC] PR touching security-critical code (authentication, authorization, payment, PII handling) has 3rd approval from Security Champion.
**Verification:** GitHub PR shows approval from user with "Security Champion" role. Security Champion list maintained in CODEOWNERS file.  
**Exception:** Tech Lead approval. Security Champion approval can be obtained post-merge within 24 hours if urgent production fix required.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key verified by GitHub.
**Verification:** GitHub displays "Verified" badge next to each commit SHA in PR commits tab. No commits show "Unverified".  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MSG] All commit messages follow Conventional Commits format verified by commitlint in GitHub Actions CI.
**Verification:** GitHub Actions workflow "commitlint" passes with green checkmark. Format: type(scope): description. Valid types: feat, fix, docs, style, refactor, test, chore.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR merged to main using squash merge strategy enforced by GitHub branch protection.
**Verification:** GitHub branch protection settings: "Require linear history" enabled. PR merge button shows only "Squash and merge" option.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube dashboard shows "Quality Gate: Passed" status. Complexity metrics tab shows 0 methods exceeding complexity threshold of 10.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] SonarQube reports no methods exceeding 50 lines of code in changed files.
**Verification:** SonarQube Issues tab filtered by "Rule: Methods should not have too many lines" shows 0 issues for changed files.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports 0 dead code findings (unreachable code, commented-out code blocks) in changed files.
**Verification:** SonarQube Issues tab filtered by "Tag: unused" and "Tag: commented-out-code" shows 0 issues for changed files.  
**Exception:** No exceptions.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-LINE] JaCoCo reports ≥80% line coverage on all changed modules in GitHub Actions CI.
**Verification:** GitHub Actions workflow "test" job shows JaCoCo coverage report. Changed modules listed with line coverage percentage ≥80%.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-BRANCH] JaCoCo reports ≥75% branch coverage on all changed modules in GitHub Actions CI.
**Verification:** JaCoCo coverage report shows branch coverage column with ≥75% for all changed modules.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-REGRESS] GitHub Actions CI coverage check passes with no coverage regression on existing covered code.
**Verification:** GitHub Actions workflow "coverage-check" job passes. Coverage diff report shows no red-highlighted decreases in coverage percentages.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present using JUnit 5 for all new/changed business logic in service layer.
**Verification:** Test files matching pattern *Test.java exist in src/test/java/ for each changed service class. Tests use @Test annotation from org.junit.jupiter.api.Test.  
**Exception:** EM can grant one-sprint exemption with written justification if work is pure infrastructure configuration.

### [ ] [L2] [QA-2.2-INTEGRATION] Integration tests present using JUnit 5 covering service/database/Kafka integration points changed by this feature.
**Verification:** Test files matching pattern *IntegrationTest.java exist. Tests use @SpringBootTest annotation. Tests verify database persistence or Kafka message production/consumption.  
**Exception:** EM can grant one-sprint exemption with written justification if feature has no integration points.

### [ ] [L2] [QA-2.2-E2E] E2E tests using Playwright cover happy path and minimum 1 error path for user-facing React components.
**Verification:** Test files matching pattern *.spec.ts exist in tests/e2e/. Tests use Playwright test() and expect() assertions. Minimum 2 test cases: 1 happy path, 1 error scenario.  
**Exception:** EM can grant one-sprint exemption with written justification if feature has no UI component.

### [ ] [L2] [From INC-001] Integration test verifies SSO login flow using JUnit 5 for all configured authentication methods (OAuth, SAML) before merge.
**Verification:** Test file SSOAuthenticationIntegrationTest.java exists with @SpringBootTest. Tests verify OAuth token exchange and SAML assertion validation. Tests pass in CI.  
**Exception:** No exceptions. Directly relates to production incident INC-001.

### [ ] [L2] [QA-2.4-PERF] k6 load test included in GitHub Actions CI for endpoints expecting >1000 RPS, verifying P95 <500ms and P99 <2000ms under load.
**Verification:** k6 script exists in tests/performance/. GitHub Actions workflow "performance" job runs k6 with --summary-export flag. Summary JSON shows http_req_duration p(95) <500 and p(99) <2000.  
**Exception:** EM can grant one-sprint exemption if endpoint not expected to handle >1000 RPS. Document expected RPS in PR description.
