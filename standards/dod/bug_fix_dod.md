## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR approval count shows 2+ approvals, with at least 1 reviewer marked as Senior Engineer or Tech Lead in org chart.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2] All commits are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit history shows "Verified" badge on all commits in PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions commitlint check passes. All commit messages match pattern: `fix(scope): description`.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] Branch merged to main using squash merge (no merge commits).
**Verification:** GitHub merge button set to "Squash and merge". Branch protection rules enforce squash merge only.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube analysis in GitHub Actions reports Quality Gate status: PASSED. Zero methods exceed complexity threshold of 10.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] No method exceeds 50 lines of code (verified by SonarQube).
**Verification:** SonarQube analysis reports zero violations of "Methods should not be too long" rule (threshold: 50 lines).  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports zero dead code (unreachable or commented-out code removed).
**Verification:** SonarQube analysis reports zero "Dead store" or "Commented-out code" issues. Quality Gate status: PASSED.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.1-SEC] PRs touching security-critical paths have additional approval from Security Champion.
**Verification:** If PR modifies files in `auth/`, `payment/`, or `pii/` directories, PR comments show approval from user with "Security Champion" role.  
**Exception:** Not applicable if PR does not touch security-critical paths (auth, payment, PII handling).

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports 80%+ line coverage on all changed modules in CI.
**Verification:** GitHub Actions JaCoCo report shows line coverage ≥ 80% for all modified Java classes. Build log displays "Coverage: XX% (threshold: 80%)".  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports 75%+ branch coverage on all changed modules in CI.
**Verification:** GitHub Actions JaCoCo report shows branch coverage ≥ 75% for all modified Java classes. Build log displays "Branch coverage: XX% (threshold: 75%)".  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] CI coverage check passes with no coverage regression on existing covered code.
**Verification:** GitHub Actions coverage diff check passes. Build log shows "Coverage delta: +X% (no regression)" or "Coverage maintained at XX%".  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-BUG] Unit tests present and passing in JUnit 5 for bug fix code path.
**Verification:** GitHub Actions test execution log shows JUnit 5 test class named `*BugFixTest.java` or `*RegressionTest.java` with test method covering fixed code path. Test execution status: PASSED.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-BUG] Integration tests present and passing if bug involves integration between services/components.
**Verification:** If bug report references inter-service communication or database integration, GitHub Actions shows integration test execution in `test-integration/` directory. Test execution status: PASSED.  
**Exception:** Not applicable if bug is contained within single service with no external dependencies.

### [ ] [L2] [QA-2.2-BUG] Playwright E2E test present and passing if bug involves UI behavior.
**Verification:** If bug report describes UI rendering issue or user interaction failure, GitHub Actions shows Playwright test execution with test name matching bug ticket ID. Test execution status: PASSED.  
**Exception:** Not applicable if bug is backend-only with no UI impact.

### [ ] [L2] [QA-2.3-REGRESSION] Regression test covering exact reproduction path from original bug report present in test suite.
**Verification:** Test file named `tests/regression/{BUG-ID}_test.java` exists in repository. Test method name matches bug ticket ID. Test execution log shows test present in CI run.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.3-REGRESSION] Regression test verified to fail on pre-fix code and pass on fixed code.
**Verification:** PR description or comments include evidence of test execution showing: (1) Test FAILED on commit before fix (git SHA referenced), (2) Test PASSED on commit with fix applied.  
**Exception:** No exceptions.

### [ ] [L2] [From INC-003] Regression test covering exact reproduction path from original bug report must be present in CI.
**Verification:** GitHub Actions test execution log shows regression test for this bug ticket running in CI pipeline. Test name includes bug ticket ID (e.g., `testBugFix_BUG123`).  
**Exception:** No exceptions.  
**Source:** Escaped defect INC-003 — Bug INC-001 reappeared in the next sprint because no regression test was added for the original fix.

## Security

### [ ] [L1] [SEC-3.1-SNYK] Snyk scan shows 0 Critical or High severity findings in GitHub Actions CI.
**Verification:** GitHub Actions Snyk workflow status: SUCCESS. Snyk report displays "Critical: 0, High: 0".  
**Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver documented in PR.

### [ ] [L1] [SEC-3.1-SNYK] Medium severity findings from Snyk have tracked Jira tickets linked in PR description.
**Verification:** If Snyk report shows Medium severity findings, PR description contains Jira ticket links (format: "SEC-XXX") for each finding. Jira ticket status: Open or In Progress.  
**Exception:** Not applicable if Snyk reports zero Medium findings.

### [ ] [L1] [SEC-3.2-SECRETS] Gitleaks scan passes in GitHub Actions CI with zero secrets detected.
**Verification:** GitHub Actions Gitleaks workflow status: SUCCESS. Build log displays "No leaks detected" or "Secrets scan: PASSED".  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] mvn dependency:check runs in GitHub Actions CI and reports zero Critical CVE findings.
**Verification:** GitHub Actions Maven dependency-check workflow status: SUCCESS. Build log displays "Critical vulnerabilities: 0".  
**Exception:** No exceptions. Critical CVEs must be upgraded or removed before merge.

### [ ] [L1] [SEC-3.3-DEPS] All new third-party dependencies are listed in approved dependency registry.
**Verification:** If `pom.xml` or `package.json` modified, PR description lists new dependencies. Each dependency has corresponding entry in `docs/approved_dependencies.md` or approval comment from Security Champion.  
**Exception:** Not applicable if no new dependencies added.
