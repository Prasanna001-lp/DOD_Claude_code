## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR page shows 2+ approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.1-SEC] If PR touches security-critical code paths, approval from designated Security Champion is documented in review comments.
**Verification:** GitHub review comments include explicit Security Champion approval if authentication, authorization, encryption, or PII handling modified.  
**Exception:** No exceptions for security-critical changes.

### [ ] [L1] [ENG-4.2] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit list shows "Verified" badge on all commits.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions commitlint check passes. All commits match pattern: `fix(scope): description`.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2] PR is configured for squash merge (merge commits prohibited).
**Verification:** GitHub PR merge button shows "Squash and merge" option selected; "Create a merge commit" disabled.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3] SonarQube quality gate passes with cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube report in GitHub Actions shows "Quality Gate: Passed" with zero methods exceeding cyclomatic complexity 10.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3] SonarQube reports zero methods exceeding 50 lines of code.
**Verification:** SonarQube report shows 0 violations for "Methods should not have too many lines" rule.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3] SonarQube reports zero dead code (unreachable or commented-out code blocks).
**Verification:** SonarQube report shows 0 violations for "Dead code" and "Commented out code" rules.  
**Exception:** No exceptions.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1] JaCoCo reports ≥ 80% line coverage on all changed modules in CI.
**Verification:** GitHub Actions JaCoCo report shows line coverage ≥ 80% for all modified Java classes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1] JaCoCo reports ≥ 75% branch coverage on all changed modules in CI.
**Verification:** GitHub Actions JaCoCo report shows branch coverage ≥ 75% for all modified Java classes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1] CI build confirms zero coverage regression on existing covered code.
**Verification:** JaCoCo diff report shows no previously covered lines lost coverage. GitHub Actions check "Coverage Regression Check" passes.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-BUGFIX] Unit tests present covering fixed code path (JUnit 5).
**Verification:** New or modified unit test file present in `src/test/java` covering the exact method(s) modified by the bug fix. Test executes in CI.  
**Exception:** EM approval with written justification if fix is configuration-only with no code logic change.

### [ ] [L2] [QA-2.2-BUGFIX] Integration tests present if bug originated in API contract or database interaction.
**Verification:** If bug involved REST endpoint or SQL query, integration test file present in `src/test/java` using `@SpringBootTest`. Test executes in CI.  
**Exception:** Not required if bug is purely internal business logic with no external integration points.

### [ ] [L2] [QA-2.2-BUGFIX] E2E test present if bug manifested in UI (Playwright).
**Verification:** If bug was visible to end user in React UI, Playwright test file present in `e2e/` directory reproducing user interaction. Test passes in CI.  
**Exception:** Not required if bug is backend-only with no UI manifestation.

### [ ] [L2] [QA-2.3, From INC-003] Regression test covering exact bug reproduction path present in CI.
**Verification:** Test file name or test method name explicitly references bug ticket ID. Test reproduces exact steps from bug report. Test executes in GitHub Actions.  
**Exception:** No exceptions.  
**⚠️ From Escaped Defect INC-003**

### [ ] [L2] [QA-2.3] PR description documents that regression test fails on pre-fix commit and passes on fixed commit.
**Verification:** PR description includes section "Regression Test Verification" with git commit SHA where test failed before fix, and confirmation test passes on current HEAD.  
**Exception:** No exceptions.

**Verification:** GitHub Actions Maven dependency check shows "Critical CVEs: 0".  
**Exception:** No exceptions.

### [ ] [L3] [COMMERCE-PLATFORM-SEC] If bug fix touches payment processing, PCI-DSS code review checklist completed and attached to PR.
**Verification:** For fixes in payment module (`com.acme.commerce.payment.*`), PCI-DSS checklist document attached as PR comment or linked in description.  
**Exception:** Tech Lead approval if bug fix is purely logging or monitoring with no PCI scope impact.

### [ ] [L2] [ENG-HANDBOOK-BUGFIX] PR description includes "Fix Summary" section explaining technical approach to fix.
**Verification:** PR description contains paragraph explaining what code changed and why this prevents bug recurrence.  
**Exception:** No exceptions.

### [ ] [L3] [COMMERCE-PLATFORM-DOC] If bug impacts external API contracts, CHANGELOG.md updated with [Bugfix] entry under [Unreleased].
**Verification:** CHANGELOG.md contains new entry: `### Bugfix - Fixed [bug description] affecting [API endpoint]`.  
**Exception:** Not required if bug is internal-only with no API-visible behavior change.
