## Code Quality

### CODE-01 [L1-UNIVERSAL] [ENG-4.1]
**[ ] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.**

- **Verification:** GitHub PR page shows 2+ approvals, with at least 1 approval from an engineer with "Senior" or "Tech Lead" role in GitHub team settings.
- **Exception:** No exceptions.

---

### CODE-02 [L2-WORKTYPE] [ENG-4.1-SEC]
**[ ] Security-critical PRs have approval from Security Champion documented in PR comments.**

- **Verification:** If PR touches authentication, authorization, encryption, or payment code: PR comments show explicit approval from designated Security Champion. Non-security PRs: mark N/A.
- **Exception:** EM can grant one-sprint exemption with written justification in PR.

---

### CODE-03 [L1-UNIVERSAL] [ENG-4.2-SIGNING]
**[ ] All commits are signed with GPG or SSH key registered in GitHub.**

- **Verification:** GitHub commit list shows "Verified" badge on every commit in the PR.
- **Exception:** No exceptions.

---

### CODE-04 [L1-UNIVERSAL] [ENG-4.2-FORMAT]
**[ ] All commit messages follow Conventional Commits format: type(scope): description.**

- **Verification:** GitHub Actions commitlint check passes. All commits match pattern: `fix(scope): description` OR `refactor(scope): description`.
- **Exception:** No exceptions.

---

### CODE-05 [L1-UNIVERSAL] [ENG-4.2-MERGE]
**[ ] PR merged using squash merge strategy; no merge commits on main branch.**

- **Verification:** GitHub branch protection rules enforce squash merge. Post-merge: `git log --first-parent main` shows single squashed commit for this PR.
- **Exception:** No exceptions.

---

### CODE-06 [L1-UNIVERSAL] [ENG-4.3-COMPLEXITY]
**[ ] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.**

- **Verification:** SonarQube dashboard shows Quality Gate status = PASSED. Complexity metric shows no methods exceeding complexity 10.
- **Exception:** No exceptions.

---

### CODE-07 [L2-WORKTYPE] [ENG-4.3-LENGTH]

- **Verification:** SonarQube Issues tab filtered by "Type: Code Smell, Rule: Methods should not have too many lines" shows 0 issues.

### TEST-02 [L1-UNIVERSAL] [QA-2.1-COVERAGE]
**[ ] JaCoCo reports ≥75% branch coverage on all changed modules.**

- **Verification:** GitHub Actions JaCoCo report shows branch coverage ≥75% for every modified .java file. CI check "coverage/branch" passes.
- **Exception:** No exceptions.

---

### TEST-03 [L1-UNIVERSAL] [QA-2.1-COVERAGE]
**[ ] CI build verifies no existing covered code has lost coverage (coverage regression check passes).**

- **Verification:** GitHub Actions "coverage-diff" check passes. CI log shows: "Coverage delta: +X% (no regression detected)".
- **Exception:** No exceptions.

---

### TEST-04 [L2-WORKTYPE] [QA-2.2-UNIT]
**[ ] Unit tests present for all changed production code; JUnit 5 test suite passes in CI.**

- **Verification:** For every modified .java file in `src/main/`, corresponding test file exists in `src/test/` with @Test methods covering the change. GitHub Actions "test/unit" check passes.
- **Exception:** EM can grant one-sprint exemption with written justification if bug fix is exclusively configuration or data-only change.

---

### TEST-05 [L2-WORKTYPE] [QA-2.2-INTEGRATION]
**[ ] Integration tests present and passing in CI if bug was integration-level (documented in bug ticket).**

- **Verification:** If original bug ticket label contains "integration" OR involves cross-service communication: integration test present in `src/integration-test/` covering the bug reproduction path. GitHub Actions "test/integration" check passes. If not integration bug: mark N/A in PR checklist.
- **Exception:** EM can grant one-sprint exemption with written justification.

---

### TEST-06 [L2-WORKTYPE] [QA-2.2-E2E]
**[ ] Playwright E2E test present and passing if bug was UI-level (documented in bug ticket).**

- **Verification:** If original bug ticket label contains "ui" OR involves React components: Playwright test present in `e2e/tests/` covering the bug reproduction path. GitHub Actions "test/e2e" check passes. If not UI bug: mark N/A in PR checklist.
- **Exception:** EM can grant one-sprint exemption with written justification.

Test fails on pre-fix code (verified by checking out parent commit). Test passes in current PR. GitHub Actions test suite includes this test and passes.
