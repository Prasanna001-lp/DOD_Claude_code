## 🔍 Purpose
This Definition of Done checklist defines the quality gates for **bug fix** work items in the Commerce Platform team. Every criterion is verifiable, traceable to a source policy, and must be completed before a bug fix is merged to main.

**Layer Legend:**
- **[L1-UNIVERSAL]** — Applies to ALL work items, no exceptions. EM + CISO sign-off to modify.
- **[L2-WORKTYPE]** — Applies to ALL bug fixes. EM can grant one-sprint exemption with written justification.
- **[L3-TEAM]** — Team-specific addition. Tech Lead approval. Reviewed quarterly.
- **[L4-STORY]** — Story-specific criterion added during grooming. PO + Tech Lead agreement.

## 📝 Code Quality

### [ ] [L1-UNIVERSAL] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR page shows 2+ approved reviews, at least 1 from engineer with "Senior Engineer" or "Tech Lead" role in team roster.  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub PR commits page displays "Verified" badge on every commit.  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions workflow "commitlint" passes. All commit messages match regex: `^(fix|feat|chore|docs|test|refactor|perf|ci)(\(.+\))?: .{1,}$`  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [ENG-4.2-MERGE] PR uses squash merge strategy (no merge commits on main).
**Verification:** GitHub PR merge button set to "Squash and merge". Branch protection rule enforces squash-only merges.  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [ENG-4.3-COMPLEX] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube dashboard shows quality gate status "Passed" with no methods exceeding complexity threshold of 10.  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [ENG-4.3-LINES] No method exceeds 50 lines of code (enforced by SonarQube quality gate).
**Verification:** SonarQube dashboard shows 0 violations for rule "Methods should not have too many lines" (threshold: 50).  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [ENG-4.3-DEAD] SonarQube reports zero dead code issues (unreachable or commented-out code).
**Verification:** SonarQube dashboard shows 0 issues for rules: "Sections of code should not be commented out" and "Dead stores should be removed".  
**Exception:** No exceptions.

### [ ] [L2-WORKTYPE] [ENG-4.1-SEC] PR touching security-critical code has approval from Security Champion in addition to standard approvals.
**Verification:** If bug fix modifies files in paths: `src/**/auth/**`, `src/**/security/**`, `src/**/crypto/**`, or `src/**/payment/**`, GitHub PR shows approval from user with "Security Champion" role.  
**Exception:** Not applicable if bug fix does not touch security-critical paths. Otherwise no exceptions.

## 🧪 Test Coverage & Quality

### [ ] [L1-UNIVERSAL] [QA-2.1-COVERAGE-LINE] JaCoCo reports ≥80% line coverage on all changed modules.
**Verification:** GitHub Actions JaCoCo report shows line coverage ≥80% for each module modified in PR. CI check "coverage/jacoco" passes.  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [QA-2.1-COVERAGE-BRANCH] JaCoCo reports ≥75% branch coverage on all changed modules.
**Verification:** GitHub Actions JaCoCo report shows branch coverage ≥75% for each module modified in PR. CI check "coverage/jacoco" passes.  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [QA-2.1-NO-REGRESSION] CI coverage check passes with no regression on existing covered code (JaCoCo diff shows no coverage loss).
**Verification:** GitHub Actions workflow "coverage-diff" passes. PR comment from coverage bot shows no red (decreased coverage) on any previously-covered lines.  
**Exception:** No exceptions.

### [ ] [L2-WORKTYPE] [QA-2.2-UNIT] Unit tests present using JUnit 5 and Mockito covering changed code paths.
**Verification:** PR includes new or modified test files in `src/test/**` directories. Tests execute in GitHub Actions workflow "test" and pass. Changed Java classes have corresponding test classes.  
**Exception:** Engineering Manager can grant one-sprint exemption with written justification in PR description. Exemption requires follow-up ticket.

### [ ] [L2-WORKTYPE] [QA-2.2-INTEGRATION] Integration tests present covering the integration layer where bug occurred (if bug involved service interactions or database).
**Verification:** If bug occurred in service-to-service communication, database access, or external API integration: PR includes integration test in `src/integrationTest/**` using Spring Boot Test annotations. Test passes in CI.  
**Exception:** Not applicable if bug was isolated to single-class business logic. Otherwise Engineering Manager can grant one-sprint exemption with written justification.

### [ ] [L2-WORKTYPE] [QA-2.2-E2E] E2E test present using Playwright covering UI reproduction path of the bug (if bug was UI-related).
**Verification:** If bug manifested in React UI: PR includes Playwright test in `e2e/**` directory. Test reproduces exact user actions from bug report. Test passes in GitHub Actions workflow "e2e".  
**Exception:** Not applicable if bug was backend-only. Otherwise Engineering Manager can grant one-sprint exemption with written justification.

### [ ] [L2-WORKTYPE] [QA-2.3-REGRESSION] Regression test present in CI covering exact reproduction path from original bug report, verified to fail pre-fix and pass post-fix.
**Verification:** PR includes test file with comment referencing original bug ticket number. Engineer has documented in PR description: (1) Test fails on commit before fix, (2) Test passes on commit with fix. CI execution log confirms test passes.  
**Exception:** No exceptions.

### [ ] [L2-WORKTYPE] [From INC-003] Regression test present in CI covering exact reproduction path from original bug report.
**Verification:** Regression test file committed to repository in `src/test/**` or `src/integrationTest/**` or `e2e/**` directory. GitHub Actions test workflow includes and executes this test. Test name or file name includes original bug ticket ID.  
**Exception:** No exceptions.  
**Note:** This criterion reinforces QA-2.3-REGRESSION and was learnt from escaped defect INC-003 (P2 severity, 2024-10-22).

## 🔒 Security

### [ ] [L1-UNIVERSAL] [SEC-3.1-SNYK] Snyk scan shows 0 Critical or High severity findings. Medium findings have tracked Jira tickets linked in PR.
**Verification:** GitHub Actions workflow "snyk" passes. Snyk dashboard shows 0 Critical, 0 High. If Medium findings present: PR description contains Jira ticket links (e.g., SEC-1234) for each Medium finding.  
**Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver ticket linked.

### [ ] [L1-UNIVERSAL] [SEC-3.2-SECRETS] Gitleaks scan passes with 0 secrets detected in CI pipeline.
**Verification:** GitHub Actions workflow "gitleaks" passes. Gitleaks output shows "No leaks detected".  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [SEC-3.3-DEPS] npm audit and mvn dependency:check produce 0 Critical CVE findings in CI.
**Verification:** GitHub Actions workflow "dependency-check" passes. npm audit output shows "0 vulnerabilities" at Critical severity. Maven dependency-check-report.html shows 0 Critical CVEs.  
**Exception:** No exceptions.

### [ ] [L1-UNIVERSAL] [SEC-4.2-SECRETS-MGMT] No hardcoded secrets in code (Gitleaks enforces). All secrets reference AWS Secrets Manager or GitHub Actions secrets.
**Verification:** Gitleaks scan passes (enforces no hardcoded secrets). Code review confirms any new secrets are retrieved via AWS SDK (`SecretsManagerClient`) or referenced as GitHub Actions secrets (`${{ secrets.SECRET_NAME }}`).  
**Exception:** No exceptions.
