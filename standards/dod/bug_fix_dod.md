## Code Quality

**Verification:** GitHub PR review status shows 2+ approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit history shows "Verified" badge on all commits in PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions commit-lint check passes. Manual review confirms format compliance.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR uses squash merge strategy (merge commits prohibited on main).
**Verification:** GitHub branch protection rules enforce squash merge. PR merge button shows "Squash and merge" only.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEX] SonarQube quality gate passes: cyclomatic complexity ≤10 per method.
**Verification:** SonarQube dashboard shows Quality Gate status "Passed" with Complexity metric ≤10.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] No method exceeds 50 lines of code (verified by SonarQube).
**Verification:** SonarQube Code Smells report shows 0 violations for "Method has too many lines" rule.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports zero dead code violations (unreachable or commented-out code removed).
**Verification:** SonarQube Issues tab filtered by "Dead Code" type shows 0 issues.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.1-SEC] PR touching security-critical code paths has approval from Security Champion.
**Verification:** GitHub PR reviewers list includes Security Champion username if code touches authentication, authorization, encryption, or PII handling paths.  
**Exception:** EM can grant one-sprint exemption if Security Champion unavailable and compensating review occurs within 3 business days post-merge.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-LINE] JaCoCo reports ≥80% line coverage on all changed modules in CI.
**Verification:** GitHub Actions JaCoCo report artifact shows line coverage ≥80% for all modified Java packages.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-BRANCH] JaCoCo reports ≥75% branch coverage on changed modules in CI.
**Verification:** GitHub Actions JaCoCo report artifact shows branch coverage ≥75% for all modified Java packages.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-REGRESS] CI coverage check passes: no existing covered code has lost coverage.
**Verification:** GitHub Actions coverage-diff check passes showing 0 files with decreased coverage percentage.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present using JUnit 5 and Mockito, covering changed code paths.
**Verification:** src/test/java directory contains new or modified test classes with @Test annotations covering bug fix logic. GitHub Actions test report shows tests executed.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.3-REGR] [From INC-003] Regression test covering exact reproduction path from original bug report is present in CI, verified to fail pre-fix and pass post-fix.
**Verification:** Test class includes @Test method named after bug ticket (e.g., testBugJIRA123_reproPath). PR description includes screenshot or log showing test failed on pre-fix commit and passes on fix commit.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-INTEG-BUG] Integration tests present using JUnit 5 if bug involves service-to-service interaction (Kafka, PostgreSQL, REST calls).
**Verification:** If bug report mentions "integration", "service call", "database", or "message queue", then src/test/java contains @SpringBootTest annotated test class exercising the interaction. Otherwise, N/A.  
**Exception:** EM can grant one-sprint exemption with written justification if integration test environment unavailable.

### [ ] [L2] [QA-2.2-E2E-UI-BUG] E2E test present using Playwright if bug affects UI workflow (React components).
**Verification:** If bug report mentions "UI", "button", "form", "page", or "frontend", then tests/e2e directory contains .spec.ts file with Playwright test covering the bug scenario. Otherwise, N/A.  
**Exception:** EM can grant one-sprint exemption with written justification if Playwright test environment unstable.

### [ ] [L3] [TEAM-KAFKA] If bug involves Kafka message handling, test includes verification of message ordering and idempotency.
**Verification:** Test code includes assertions checking consumer offset progression and duplicate message handling (e.g., assertEquals expected order, verify idempotent key).  
**Exception:** Tech Lead approval required if message ordering not applicable to this consumer type.

## Documentation

### [ ] [L2] [BUGFIX-ROOT-CAUSE] Root cause analysis documented in PR description including why bug occurred and what prevents recurrence.
**Verification:** PR description contains "Root Cause:" section with minimum 2 sentences explaining underlying cause and "Prevention:" section explaining safeguards (e.g., new test, validation added).  
**Exception:** No exceptions.

### [ ] [L2] [ENG-6.1-API] CHANGELOG.md updated with entry under [Unreleased] section if bug fix affects user-facing behavior or API contract.
**Verification:** git diff shows modification to CHANGELOG.md with entry format: "### Fixed\n- [JIRA-123] Description of bug fixed." Entry present only if bug changes observable behavior.  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-POSTGRES] If bug fix includes database migration (Flyway/Liquibase), migration script reviewed by Database Admin and rollback script provided.
**Verification:** src/main/resources/db/migration contains new .sql file. PR includes comment from Database Admin approving schema change. Rollback .sql file present in same directory or documented in PR.  
**Exception:** Tech Lead approval if rollback not feasible (e.g., data type widening). Justification required in PR.
