## Code Quality

**[ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.**
- **Verification:** GitHub branch protection rules enforce 2 required reviews. GitHub PR shows at least 1 approval from user with "Senior Engineer" or "Tech Lead" role.
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.2a] All commits in PR are signed with GPG or SSH key registered in GitHub.**
- **Verification:** GitHub commit list shows "Verified" badge on all commits. GitHub Actions workflow checks commit signature status.
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.2b] All commit messages follow Conventional Commits format: type(scope): description.**
- **Verification:** GitHub Actions workflow runs commitlint check and passes. Expected types: fix, refactor, test, chore.
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.2c] PR merged via squash merge (no merge commits on main).**
- **Verification:** GitHub branch protection rules enforce squash merge only. Git history on main shows linear commit graph.
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.3a] SonarQube quality gate passes with cyclomatic complexity ≤ 10 per method.**
- **Verification:** SonarQube dashboard shows Quality Gate status = PASSED. No methods with complexity > 10 in changed files.
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.3b] No method exceeds 50 lines of code (verified by SonarQube).**
- **Verification:** SonarQube code smells report shows 0 violations for "Methods should not be too long" rule.
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.3c] No dead code present (unreachable code, commented-out code removed).**
- **Verification:** SonarQube dashboard shows 0 "Dead Store" and 0 "Commented Out Code" issues in changed files.
- **Exception:** No exceptions.

## Test Coverage & Quality

**[ ] [L1] [QA-2.1a] JaCoCo reports ≥80% line coverage on all changed modules.**
- **Verification:** GitHub Actions JaCoCo report shows line coverage >= 80% for all modified packages. CI check passes.
- **Exception:** No exceptions.

**[ ] [L1] [QA-2.1b] JaCoCo reports ≥75% branch coverage on all changed modules.**
- **Verification:** GitHub Actions JaCoCo report shows branch coverage >= 75% for all modified packages. CI check passes.
- **Exception:** No exceptions.

**[ ] [L1] [QA-2.1c] CI build verifies no existing covered code has lost coverage (coverage delta ≥ 0).**
- **Verification:** GitHub Actions coverage report shows coverage change = 0% or positive for all previously covered files.
- **Exception:** No exceptions.

**[ ] [L2] [QA-2.2-BUG-a] Unit tests present for bug fix code path (JUnit 5).**
- **Verification:** CI test report shows passing JUnit 5 unit tests covering the fixed code path. Test names reference bug ticket ID.
- **Exception:** No exceptions.

**[ ] [L2] [QA-2.2-BUG-b] Integration tests present if bug involves service interaction or data layer (JUnit 5).**
- **Verification:** If bug affects REST API calls, Kafka message handling, or PostgreSQL queries: CI shows passing JUnit 5 integration tests covering those interactions.
- **Exception:** Not required if bug is purely in-memory logic with no external dependencies.

**[ ] [L2] [QA-2.2-BUG-c] E2E tests present if bug is UI-related (Playwright).**
- **Verification:** If bug affects React UI rendering or user interaction flow: CI shows passing Playwright E2E tests covering affected user journey.
- **Exception:** Not required if bug is backend-only.

**[ ] [L2] [QA-2.3] Regression test present covering exact reproduction path from original bug report (motivated by escaped defect INC-003).**
- **Verification:** CI test suite includes new test with name referencing bug ticket ID. Test reproduces exact steps from bug report. Test verified to fail on pre-fix branch and pass on fixed branch.
- **Exception:** No exceptions.
- **🚨 From Escaped Defect:** INC-003 (P2 severity) — Bug reappeared in next sprint due to missing regression test.

## Acceptance & Sign-off

**[ ] [L2] [BUG-FIX-ACC-1] Bug reporter or QA engineer verifies fix in staging environment and confirms original issue no longer reproduces.**
- **Verification:** Jira bug ticket shows comment from reporter or QA with "Verified in staging" or equivalent confirmation statement.
- **Exception:** If original reporter unavailable, QA Lead approval sufficient.

**[ ] [L3] [TEAM-ACC-1] If bug affected payment processing or order flow, manual smoke test performed by Product Owner in staging.**
- **Verification:** PO confirmation comment in Jira or PR with "Payment flow smoke test passed" or "Order flow verified in staging".
- **Exception:** Not required if bug does not touch payment or order domains.
