## Purpose

This Definition of Done ensures every bug fix:
1. **Prevents regression** through comprehensive test coverage of the exact reproduction path
2. **Documents root cause** to enable learning and process improvement
3. **Meets security standards** with zero Critical/High vulnerabilities
4. **Maintains code quality** with no technical debt accumulation
5. **Provides traceability** from reported bug through fix verification

Bug fixes require special attention to regression testing and root cause documentation to prevent recurrence (see INC-003 in policy traceability).

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR approval count shows ≥2 approvals, at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key verified by GitHub.
**Verification:** GitHub shows "Verified" badge on all commits in PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MSG] All commit messages follow Conventional Commits format verified by CI lint.
**Verification:** GitHub Actions workflow "commitlint" job passes with status green.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR merged to main using squash merge strategy (GitHub branch protection enforced).
**Verification:** GitHub branch protection rule on main requires squash merge. PR merge button shows "Squash and merge" only.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube dashboard shows Quality Gate status = PASSED. Complexity metric shows 0 methods exceeding threshold 10.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] SonarQube reports no methods exceeding 50 lines of code.
**Verification:** SonarQube dashboard shows 0 issues with rule "Methods should not have too many lines" on changed files.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports 0 dead code findings in changed files.
**Verification:** SonarQube dashboard shows 0 issues tagged "unused" or "dead-code" in PR diff.  
**Exception:** No exceptions.

### [ ] [L3] [ENG-4.1-SEC] PR touching security-critical code has 3rd approval from Security Champion.
**Verification:** If PR modifies files under `src/auth/`, `src/payments/`, or `src/crypto/`, GitHub PR shows approval from user with "Security Champion" team membership.  
**Exception:** Not applicable if PR does not touch security-critical paths. Tech Lead confirms non-applicability in PR comment.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-LINE] JaCoCo reports ≥80% line coverage on all changed modules in CI.
**Verification:** GitHub Actions workflow "Test & Coverage" job shows JaCoCo report with line coverage ≥80% for each module in git diff.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-BRANCH] JaCoCo reports ≥75% branch coverage on all changed modules in CI.
**Verification:** GitHub Actions workflow "Test & Coverage" job shows JaCoCo report with branch coverage ≥75% for each module in git diff.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-REGRESS] CI coverage check passes with no coverage regression on existing covered code.
**Verification:** GitHub Actions workflow "Coverage Diff" job passes with status green. Job comment on PR shows "No coverage regression detected" or delta ≥0% for all existing files.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present using JUnit 5 for all new/changed business logic.
**Verification:** Test files matching pattern `*Test.java` exist in `src/test/` for each modified class in `src/main/` containing business logic. Tests use JUnit 5 annotations (`@Test`, `@ParameterizedTest`).  
**Exception:** EM can grant one-sprint exemption with written justification in PR description.

### [ ] [L2] [QA-2.2-INTEGRATION] Integration tests present covering the integration layer where bug occurred.
**Verification:** If bug occurred at service/database/API integration boundary, test files matching pattern `*IntegrationTest.java` exist covering that integration point using `@SpringBootTest` or equivalent.  
**Exception:** Not applicable if bug is isolated to single unit. Tech Lead confirms non-applicability in PR comment.

### [ ] [L2] [QA-2.2-E2E] E2E test using Playwright covers UI flow where bug occurred.
**Verification:** If bug manifested in UI, test file in `e2e/` directory exists with Playwright test covering affected user flow from bug report.  
**Exception:** Not applicable if bug is backend-only. Tech Lead confirms non-applicability in PR comment.

### [ ] [L2] [QA-2.3-REGRESSION] Regression test present covering exact reproduction path from original bug report, verified to fail pre-fix and pass post-fix.
**Verification:** Test file includes comment `// Regression test for [TICKET-ID]`. PR description includes screenshot or log showing test FAILED on commit before fix and PASSED on commit after fix.  
**Exception:** No exceptions.

### [ ] [L2] [From INC-003] Regression test covering exact reproduction path from original bug report is present in CI.
**Verification:** GitHub Actions test run includes test name matching pattern `test.*regression.*[ticket-id]` or similar. Test appears in test report with status PASSED.  
**Exception:** No exceptions.  
**Incident Context:** Bug INC-001 reappeared in the next sprint because no regression test was added for the original fix. This criterion prevents recurrence.

## Security

### [ ] [L1] [SEC-3.1-SNYK] Snyk scan shows 0 Critical or High severity findings in GitHub Actions CI.
**Verification:** GitHub Actions workflow "Snyk Security Scan" job passes with status green. Snyk dashboard shows 0 issues with severity Critical or High for this PR.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.1-SNYK] All Medium severity Snyk findings have tracked Jira tickets linked in PR description.
**Verification:** PR description includes section "Medium Severity Findings" with Jira ticket links (format: PROJ-1234) for each Medium finding reported by Snyk.  
**Exception:** No exceptions. If 0 Medium findings, state "No Medium findings" in PR description.

### [ ] [L1] [SEC-3.2-SECRETS] Gitleaks scan passes in GitHub Actions CI with 0 secrets detected.
**Verification:** GitHub Actions workflow "Gitleaks Secret Scan" job passes with status green. Job log shows "No leaks detected".  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] All new dependencies listed in approved dependency registry before merge.
**Verification:** If `pom.xml` or `package.json` modified, PR description includes section "New Dependencies" listing each new dependency. Each dependency has approval comment from Tech Lead or appears in `docs/approved-dependencies.md`.  
**Exception:** No exceptions. If no new dependencies, state "No new dependencies" in PR description.

### [ ] [L1] [SEC-3.3-DEPS] npm audit or mvn dependency:check reports 0 Critical CVE findings in CI.
**Verification:** GitHub Actions workflow "Dependency Audit" job passes. For Java: `mvn dependency:check` shows 0 Critical CVEs. For JavaScript: `npm audit --audit-level=critical` exits with code 0.  
**Exception:** No exceptions.

## Documentation

### [ ] [L2] [BUG-FIX-ROOT-CAUSE] Root cause analysis documented in PR description or linked ticket.
**Verification:** PR description includes section "Root Cause Analysis" with explanation of why bug occurred, or Jira ticket linked in PR has "Root Cause" field populated.  
**Exception:** No exceptions.

### [ ] [L2] [BUG-FIX-REPRO] Exact reproduction steps from original bug report referenced in PR.
**Verification:** PR description includes section "Reproduction Steps" with numbered steps or link to original bug ticket showing reproduction path.  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-CHANGELOG] CHANGELOG.md updated if bug fix affects user-facing behavior or API contract.
**Verification:** If bug affected end users or external API consumers, `CHANGELOG.md` includes entry under `[Unreleased]` section describing fix.  
**Exception:** Not applicable for internal-only bugs with no user impact. Tech Lead confirms non-applicability in PR comment.

## CI / Deployment Gate

### [ ] [L1] [CI-ALL-CHECKS] All GitHub Actions CI checks pass with status green before merge.
**Verification:** GitHub PR shows "All checks have passed" with green checkmark. No failed or skipped required checks.  
**Exception:** No exceptions.

### [ ] [L2] [BUG-FIX-VERIFICATION] Bug verified as fixed in staging or pre-prod environment before merge to main.
**Verification:** PR description includes section "Verification" with link to staging deployment or screenshot showing bug no longer reproduces in staging environment.  
**Exception:** EM can grant one-sprint exemption for hotfixes requiring immediate production deployment. Exemption must be documented in PR with EM approval comment.

## Acceptance & Sign-off

### [ ] [L2] [BUG-FIX-REPORTER] Original bug reporter or Product Owner confirms fix resolves reported issue.
**Verification:** PR includes comment from original bug reporter or PO stating "Verified fixed" or equivalent confirmation after testing in staging.  
**Exception:** If original reporter unavailable, Tech Lead may verify and document reason in PR comment.

### [ ] [L3] [TEAM-QA-SIGNOFF] QA team member has verified regression test passes and no side effects introduced.
**Verification:** PR includes approval from user with "QA" team membership or comment from QA stating "Test coverage verified, no regressions detected".  
**Exception:** For P3/P4 bugs with isolated scope, Tech Lead may self-verify. Exemption reason documented in PR comment.
