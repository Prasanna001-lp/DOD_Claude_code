## Code Quality

**[L1] Universal — applies to all work items**

- [ ] **[L1] [ENG-4.1]** PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.  
  **Verification:** GitHub branch protection shows 2 approvals with at least 1 from @senior-engineers team.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.2-SIGN]** All commits in PR are signed with GPG or SSH key registered in GitHub.  
  **Verification:** GitHub shows "Verified" badge on all commits in PR.  
  **Exception:** No exceptions. Branch protection enforces signed commits.

- [ ] **[L1] [ENG-4.2-CONV]** All commit messages follow Conventional Commits format: type(scope): description.  
  **Verification:** GitHub Actions workflow "Commit Lint" passes.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.2-MERGE]** PR uses squash merge strategy (verified in GitHub branch protection settings).  
  **Verification:** GitHub PR merge button shows only "Squash and merge" option enabled.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.3-COMPLEX]** SonarQube quality gate passes with cyclomatic complexity ≤10 per method.  
  **Verification:** SonarQube CI check in GitHub Actions reports "Quality Gate Passed".  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.3-LOC]** SonarQube quality gate passes with no methods exceeding 50 lines of code.  
  **Verification:** SonarQube CI check shows 0 violations for "Method length" rule.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.3-DEAD]** SonarQube reports zero dead code violations (unreachable or commented-out code).  
  **Verification:** SonarQube CI check shows 0 "Dead code" issues.  
  **Exception:** No exceptions.

**[L2] Bug Fix Specific**

- [ ] **[L2] [QA-2.3-REGRESS]** Root cause analysis documented in PR description or linked ticket, explaining why the bug occurred.  
  **Verification:** PR description contains "Root Cause" section with explanation of underlying issue.  
  **Exception:** No exceptions for bug_fix work type.

## Test Coverage & Quality

**[L1] Universal — applies to all work items**

- [ ] **[L1] [QA-2.1-COV-LINE]** JaCoCo reports ≥80% line coverage on all changed modules in CI.  
  **Verification:** GitHub Actions "Coverage Check" job passes with JaCoCo report showing ≥80% line coverage.  
  **Exception:** No exceptions. Coverage gate is mandatory.

- [ ] **[L1] [QA-2.1-COV-BRANCH]** JaCoCo reports ≥75% branch coverage on all changed modules in CI.  
  **Verification:** GitHub Actions "Coverage Check" job passes with JaCoCo report showing ≥75% branch coverage.  
  **Exception:** No exceptions. Coverage gate is mandatory.

- [ ] **[L1] [QA-2.1-COV-REGRESS]** CI coverage check passes with no coverage regression on any existing covered code.  
  **Verification:** GitHub Actions "Coverage Diff" job shows 0% regression (green check).  
  **Exception:** No exceptions. Coverage regression blocks merge.

**[L2] Bug Fix Specific**

- [ ] **[L2] [QA-2.2-UNIT]** JUnit 5 unit tests present and passing for all changed business logic.  
  **Verification:** GitHub Actions "Unit Tests" job passes with JUnit 5 report showing 100% pass rate.  
  **Exception:** No exceptions for bug_fix work type.

- [ ] **[L2] [QA-2.3-REGRESS] [Reinforced by INC-003]** Regression test present covering exact reproduction path from bug report, verified to fail before fix and pass after fix.  
  **Verification:** PR description includes link to test file and evidence test failed before fix (e.g., CI run link showing test failure on parent commit).  
  **Exception:** No exceptions for bug_fix work type.  
  **🔴 From Escaped Defect:** INC-003 (Bug reappeared — no regression test)

**[L3] Team-Specific**

- [ ] **[L3] [TEAM-BUGFIX-INT]** If bug involves cross-component interaction (e.g., Spring Boot service + PostgreSQL + Kafka), integration test using Spring Boot Test passes.  
  **Verification:** GitHub Actions "Integration Tests" job passes with test report showing cross-component coverage.  
  **Exception:** Tech Lead approval if bug is purely isolated to single component with no external dependencies.

## Security

**[L1] Universal — applies to all work items**

- [ ] **[L1] [SEC-3.1-SNYK]** Snyk scan in GitHub Actions reports 0 Critical or High severity findings.  
  **Verification:** GitHub Actions "Snyk Security" job passes with 0 Critical/High findings.  
  **Exception:** No exceptions for Critical/High findings.

- [ ] **[L1] [SEC-3.1-SNYK-MEDIUM]** All Medium severity Snyk findings have linked Jira tickets in PR description.

  **Exception:** No exceptions. Medium findings must be tracked.

- [ ] **[L1] [SEC-3.3-DEP-NPM]** npm audit in GitHub Actions reports 0 Critical CVE findings.  
  **Verification:** GitHub Actions "NPM Audit" job passes with 0 Critical CVEs.  
  **Exception:** No exceptions for Critical CVEs.

## Documentation

**[L2] Bug Fix Specific**

- [ ] **[L2] [TEAM-BUGFIX-JIRA]** Original bug ticket (Jira) updated with link to PR and summary of fix approach.  
  **Verification:** Jira ticket referenced in PR title contains comment with PR link and fix summary.  
  **Exception:** No exceptions for bug_fix work type.

**[L3] Team-Specific**

- [ ] **[L3] [TEAM-BUGFIX-CHANGELOG]** If bug is customer-visible (UI/API behavior change), CHANGELOG.md updated under [Unreleased] section with "Fixed" entry.  
  **Verification:** Git diff shows new entry in CHANGELOG.md under [Unreleased] with format: "- Fixed: [description]".  
  **Exception:** Tech Lead approval if bug is internal-only (e.g., refactoring, build issue).

## CI / Deployment Gate

**[L1] Universal**

- [ ] **[L1] [TEAM-CI-ALL-GREEN]** All GitHub Actions CI checks pass: lint, build, unit tests, integration tests, coverage, SonarQube, Snyk, Gitleaks, dependency checks.  
  **Verification:** GitHub PR shows all required status checks green (no red X or yellow warning).  
  **Exception:** No exceptions. CI gate is mandatory.

**[L2] Bug Fix Specific**

- [ ] **[L2] [TEAM-BUGFIX-STAGING]** Fix deployed to staging environment and manually verified by engineer or QA.  
  **Verification:** PR description includes staging deployment link and verification checklist (e.g., "Tested in staging: [link], reproduction steps no longer occur").  
  **Exception:** EM approval if bug cannot be reproduced in staging (e.g., production-data-specific issue).

## Acceptance & Sign-off

**[L2] Bug Fix Specific**

- [ ] **[L2] [TEAM-BUGFIX-PO-VERIFY]** If bug was reported by Product Owner or customer, PO has verified fix in staging and approved PR.  
  **Verification:** GitHub PR shows approval from @product-owner or comment confirming verification.  
  **Exception:** Not required if bug was internal-only or caught in development.

**[L3] Team-Specific**

- [ ] **[L3] [TEAM-BUGFIX-QA-VERIFY]** If bug is P1 or customer-visible, QA engineer has independently verified fix in staging.  
  **Verification:** GitHub PR includes comment from @qa-team confirming independent verification.  
  **Exception:** Tech Lead approval if QA bandwidth unavailable and engineer verification is documented.
