## Code Quality

### CODE-01 [L1] [ENG-4.1]
**[ ] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.**

**Verification:** GitHub PR page shows 2+ approvals with at least 1 from senior engineer role.

**Exception:** No exceptions.

---

### CODE-02 [L2] [ENG-4.1-SEC]
**[ ] PRs touching security-critical code paths (authentication, authorization, payment processing, PII handling) have approval from Security Champion.**

**Verification:** GitHub PR approvals include @security-champion username if security-critical paths modified.

**Exception:** EM can waive for one sprint with written justification if Security Champion unavailable.

---

### CODE-03 [L1] [ENG-4.2-SIGN]
**[ ] All commits in PR are signed with GPG or SSH key registered in GitHub.**

**Verification:** GitHub shows "Verified" badge on all commits in PR.

**Exception:** No exceptions.

---

### CODE-04 [L1] [ENG-4.2-FORMAT]
**[ ] All commit messages follow Conventional Commits format: type(scope): description.**

**Verification:** GitHub Actions commitlint check passes in CI pipeline.

**Exception:** No exceptions.

---

### CODE-05 [L1] [ENG-4.2-MERGE]
**[ ] PR is merged using squash merge strategy only.**

**Verification:** GitHub merge button set to "Squash and merge". Main branch history shows single commit per PR.

**Exception:** No exceptions.

---

### CODE-06 [L1] [ENG-4.3-COMPLEXITY]
**[ ] SonarQube quality gate passes: cyclomatic complexity ≤ 10 per method.**

**Verification:** SonarQube check in GitHub Actions reports "Quality Gate: Passed" with 0 complexity violations.

**Exception:** No exceptions.

---

### CODE-07 [L1] [ENG-4.3-LENGTH]
**[ ] No method exceeds 50 lines of code (verified by SonarQube).**

**Verification:** SonarQube analysis reports 0 "Method too long" issues.

**Exception:** No exceptions.

---

### CODE-08 [L1] [ENG-4.3-DEAD]
**[ ] SonarQube reports 0 dead code issues (unreachable code, commented-out code removed).**

**Verification:** SonarQube analysis shows 0 "Dead Code" or "Commented Out Code" issues.

**Exception:** No exceptions.

## Test Coverage & Quality

### TEST-01 [L1] [QA-2.1-COVERAGE]
**[ ] JaCoCo reports ≥80% line coverage on all changed modules.**

**Verification:** GitHub Actions JaCoCo report shows line coverage ≥80% for all modified Java classes. React coverage via Jest shows ≥80% for modified components.

**Exception:** No exceptions.

---

### TEST-02 [L1] [QA-2.1-COVERAGE]
**[ ] JaCoCo reports ≥75% branch coverage on changed modules.**

**Verification:** GitHub Actions JaCoCo report shows branch coverage ≥75% for all modified Java classes.

**Exception:** No exceptions.

---

### TEST-03 [L1] [QA-2.1-COVERAGE]
**[ ] No existing covered code has lost coverage (CI build enforces no coverage regression).**

**Verification:** GitHub Actions coverage-check job passes. JaCoCo diff report shows 0 files with decreased coverage.

**Exception:** No exceptions.

---

### TEST-04 [L2] [QA-2.2-UNIT]
**[ ] Unit tests present and passing (JUnit 5 for Java, Jest for React) for all changed code.**

**Verification:** GitHub Actions test job shows all unit tests passing. New test files present in PR for modified classes/components.

**Exception:** EM can grant one-sprint exemption with written justification for trivial changes.

---

### TEST-05 [L2] [QA-2.2-INTEGRATION]
**[ ] Integration tests present and passing covering the integration failure path if bug involved service-to-service or database interaction.**

**Verification:** GitHub Actions integration-test job passes. New integration test file added if bug affected API calls, Kafka messaging, or database queries.

**Exception:** Not required if bug was isolated to single-class logic with no external dependencies.

---

### TEST-06 [L2] [QA-2.2-E2E]
**[ ] E2E test (Playwright) covers UI bug reproduction and fix verification if bug affected user-facing UI.**

**Verification:** GitHub Actions e2e-test job passes. New Playwright test added under tests/e2e/ reproducing exact user interaction from bug report.

**Exception:** Not required if bug was backend-only (no UI impact).

---

### TEST-07 [L2] [QA-2.3-REGRESSION]
**[ ] Regression test present covering exact reproduction path from original bug report, verified to fail on pre-fix code and pass on fixed code.**

**Verification:** Test file named test/regression/BUG-{ticket-number}.test.java or .spec.ts exists. PR description includes statement: "Regression test fails on main, passes on branch."

**Exception:** No exceptions.

---

### TEST-08 [L2] [From INC-003]
**[ ] Regression test covering exact reproduction path from original bug report must be present in CI.**

**Verification:** CI pipeline includes regression test suite run. Test file committed under src/test/regression/ or tests/regression/.

**Exception:** No exceptions.

**Note:** This criterion prevents recurrence of escaped defect INC-003 where Bug INC-001 reappeared due to missing regression test.

## Security

### SEC-01 [L1] [SEC-3.1-SNYK]
**[ ] Snyk scan shows 0 Critical or High severity findings.**

**Verification:** GitHub Actions Snyk check passes. Snyk report shows "0 Critical, 0 High" vulnerabilities.

**Exception:** No exceptions. Findings must be fixed or have CISO-accepted risk waiver documented in Jira.

---

### SEC-02 [L1] [SEC-3.1-SNYK]
**[ ] All Medium severity Snyk findings have tracked Jira tickets before merge.**

**Verification:** Snyk report shows Medium findings. PR description includes Jira ticket links (format: SEC-####) for each Medium finding.

**Exception:** No exceptions.

---

### SEC-03 [L1] [SEC-3.2-SECRETS]
**[ ] Gitleaks scan passes with 0 secrets detected in CI.**

**Verification:** GitHub Actions gitleaks check passes. No secrets, API keys, tokens, or passwords found in commit history.

**Exception:** No exceptions.

---

### SEC-04 [L1] [SEC-3.3-DEPS]
**[ ] npm audit (React) or mvn dependency:check (Java) produces 0 Critical findings in CI.**

**Verification:** GitHub Actions dependency-check job passes. npm audit shows "0 critical" or mvn dependency:check reports "0 critical CVEs".

**Exception:** No exceptions. Critical CVE dependencies must be upgraded or removed before merge.

## Documentation

### DOC-01 [L2] [IMPLICIT-ROOTCAUSE]
**[ ] Root cause documented in bug ticket or PR description.**

**Verification:** Bug ticket (Jira) includes "Root Cause" section with analysis. PR description includes "Root Cause Analysis" explaining why bug occurred.

**Exception:** EM can waive for one sprint if root cause analysis deferred to post-fix retrospective (must document deferral reason).

---

### DOC-02 [L3] [TEAM-COMMERCE]
**[ ] If bug affected Kafka event schema or PostgreSQL data model, updated docs/data-contracts/ with schema change details.**

**Verification:** Git diff shows updates to docs/data-contracts/kafka-events.md or docs/data-contracts/postgres-schema.md if relevant tables/events modified.

**Exception:** Not required if bug fix did not alter data contracts.

---

## CI / Deployment Gate

### CI-01 [L1] [IMPLICIT-CI]
**[ ] All CI checks pass in GitHub Actions (build, lint, test, security scans).**

**Verification:** GitHub PR page shows all required checks green: build, test, lint, snyk, gitleaks, sonarqube, jacoco.

**Exception:** No exceptions.

---

### CI-02 [L1] [IMPLICIT-LINT]
**[ ] Code passes linting checks (ESLint for React, Checkstyle/SpotBugs for Java).**

**Verification:** GitHub Actions lint job passes. ESLint reports 0 errors for React code. Checkstyle/SpotBugs report 0 errors for Java code.

**Exception:** No exceptions.

## Acceptance & Sign-off

### ACC-01 [L2] [TEAM-BUG-VERIFICATION]
**[ ] Bug reporter or QA engineer verified fix in staging environment using exact reproduction steps from original bug report.**

**Verification:** Bug ticket shows comment from original reporter or QA with format: "Verified in staging: [reproduction steps] now work as expected." GitHub PR tagged with label "verified-in-staging".

**Exception:** Tech Lead approval required if original reporter unavailable. QA verification substitutes.
