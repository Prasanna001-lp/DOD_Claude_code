## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR page shows 2+ approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L3] [ENG-4.1-SEC] PR touching security-critical paths (auth, crypto, secrets, IAM, data protection) has additional approval from Security Champion.
**Verification:** GitHub PR shows Security Champion approval when security-critical files modified.  
**Exception:** No exceptions for security-critical changes.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub PR shows "Verified" badge on all commits.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions commitlint check passes.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR merge strategy set to "Squash and merge". Merge commits are not used on main branch.
**Verification:** GitHub PR settings show "Squash and merge" selected.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-CYCLO] SonarQube quality gate passed with cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube status check green in GitHub Actions.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] No method exceeds 50 lines of code.
**Verification:** SonarQube quality gate passes method length check.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports zero dead code issues (unreachable or commented-out code removed).
**Verification:** SonarQube quality gate passes dead code check.  
**Exception:** No exceptions.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COV] JaCoCo reports 80%+ line coverage and 75%+ branch coverage on all changed modules. No existing covered code has lost coverage.
**Verification:** GitHub Actions JaCoCo check passes. Coverage report shows thresholds met and no regression.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present using JUnit 5 and Mockito covering all changed code paths.
**Verification:** GitHub Actions test results show JUnit tests executed and passed.  
**Exception:** EM approval required with written justification.

### [ ] [L2] [QA-2.2-INTEG] Integration tests present and passing in CI if bug involves integration between services or external systems.
**Verification:** GitHub Actions shows integration test suite execution and pass when integration bug identified in bug report.  
**Exception:** EM approval for one sprint if integration test environment unavailable.

### [ ] [L2] [QA-2.2-E2E] E2E test using Playwright covering UI bug reproduction path if bug involves user interface.
**Verification:** GitHub Actions Playwright test results show UI bug reproduction path executed and passed.  
**Exception:** EM approval for one sprint with written justification.

### [ ] [L2] [QA-2.3-REGR] [Reinforced by INC-003] Regression test covering exact reproduction path from original bug report present in CI. Test verifiably fails on pre-fix code and passes on fixed code.
**Verification:** GitHub Actions test results show regression test present and passing. PR description links to bug report and confirms test failure on pre-fix commit.  
**Exception:** No exceptions.

### [ ] [L2] [BUG-ROOT-CAUSE] Root cause documented in PR description or linked bug ticket explaining why bug occurred and how fix addresses it.
**Verification:** PR description contains "Root Cause:" section or bug ticket has root cause analysis documented.  
**Exception:** No exceptions.

### [ ] [L3] [COMMERCE-KAFKA] If bug involves Kafka event processing, verify event schema validation and error handling with Spring Boot Kafka test container.
**Verification:** JUnit tests show Kafka test container usage. Test cases cover schema validation and error scenarios.  
**Exception:** N/A if bug does not involve Kafka.

### [ ] [L3] [COMMERCE-DB] If bug involves PostgreSQL data operations, verify database transaction boundaries and rollback behavior with test database.
**Verification:** JUnit tests show PostgreSQL test database usage. Test cases verify transaction handling and data consistency.  
**Exception:** N/A if bug does not involve database operations.

**Verification:** Bug ticket (Jira/GitHub Issue) shows "Resolution:" section with fix details and PR link.

**Verification:** GitHub PR shows all status checks green.
