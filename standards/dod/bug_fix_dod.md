## 🔧 Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR approval count visible in PR page. Minimum 2 approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2] All commits are signed with GPG or SSH signing key registered in GitHub.
**Verification:** GitHub commit list shows "Verified" badge on all commits in the PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions workflow "commitlint" passes. All commit messages match pattern: `fix(scope): description`.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR merged using squash merge strategy only; merge commits prohibited on main branch.
**Verification:** GitHub branch protection rule enforces squash merge. PR merge button shows only "Squash and merge" option.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube check in GitHub Actions reports "Quality Gate: Passed" with 0 complexity violations exceeding threshold 10.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] No method exceeds 50 lines of code (verified by SonarQube).
**Verification:** SonarQube report shows 0 "method too long" violations. Maximum method length = 50 lines.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports 0 dead code violations (unreachable or commented-out code removed).
**Verification:** SonarQube scan shows 0 issues tagged "dead-code", "unreachable", or "commented-out".  
**Exception:** No exceptions.

### [ ] [L2] [TEAM-STANDARD] Root cause analysis documented in PR description or linked Jira ticket.
**Verification:** PR description contains "Root Cause" section or Jira ticket linked in PR has "Root Cause Analysis" field completed.  
**Exception:** Engineering Manager can waive for trivial bugs (typos, UI text) with written justification in PR comment.

## 🧪 Test Coverage & Quality

### [ ] [L1] [QA-2.1-LINE] JaCoCo reports ≥80% line coverage on all changed modules in CI build.
**Verification:** GitHub Actions JaCoCo report shows line coverage ≥80% for all changed Java modules. Report attached as PR comment.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-BRANCH] JaCoCo reports ≥75% branch coverage on all changed modules in CI build.
**Verification:** GitHub Actions JaCoCo report shows branch coverage ≥75% for all changed Java modules.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-REGRESS] CI build verifies no coverage regression on existing covered code (JaCoCo diff check passes).
**Verification:** GitHub Actions workflow "coverage-diff" passes. No previously covered lines lost coverage.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-BUG] Unit tests present and passing in CI (JUnit 5) for bug fix.
**Verification:** GitHub Actions test report shows JUnit 5 tests executed with 0 failures. Minimum 1 new or modified unit test present.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-BUG] Integration tests present if bug is integration-related (JUnit 5).
**Verification:** If bug involves cross-service communication or database interaction, GitHub Actions shows integration tests executed. Otherwise marked N/A in PR checklist.  
**Exception:** Not required if bug is pure business logic within single service boundary.

### [ ] [L2] [QA-2.2-BUG] E2E tests present if bug is UI-related (Playwright).
**Verification:** If bug affects React UI, GitHub Actions shows Playwright tests executed covering affected UI flow. Otherwise marked N/A.  
**Exception:** Not required if bug is backend-only (API, Kafka consumer, database).

### [ ] [L2] [QA-2.3] **[From INC-003]** Regression test covering exact reproduction path from original bug report present in CI (fails on pre-fix code, passes on fixed code).
**Verification:** PR description links to new test file (JUnit 5 or Playwright) with test name matching bug ticket ID. CI shows test passing. Test must fail when run against commit immediately before fix.  
**Exception:** No exceptions.  
**Incident Reference:** INC-003

## 🔒 Security

### [ ] [L1] [SEC-3.1] Snyk scan shows 0 Critical or High severity findings in CI before merge to main.
**Verification:** GitHub Actions workflow "snyk-security" passes with status "No critical or high severity issues found".  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.1] All Medium severity findings from Snyk acknowledged with tracked Jira ticket referenced in PR.
**Verification:** If Snyk reports Medium findings, PR description contains section "Medium Security Findings" with Jira ticket links (format: SEC-NNNN).  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2] Gitleaks scan passes in CI with zero secrets detected before merge to main.
**Verification:** GitHub Actions workflow "gitleaks" completes with exit code 0 and message "No leaks detected".  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-APPROVED] All third-party dependencies are listed in approved dependency registry (verified in CI).
**Verification:** GitHub Actions workflow "dependency-check" passes. All dependencies in pom.xml (Java) and package.json (React) appear in approved-dependencies.yaml in repository root.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-CVE] No dependencies with Critical CVEs older than 5 business days present (npm audit / mvn dependency:check passes).
**Verification:** GitHub Actions runs `npm audit --audit-level=critical` for React and `mvn dependency:check` for Java. Both exit with code 0 (no critical CVEs found or all < 5 business days old).  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-AUDIT] npm audit (for React) and mvn dependency:check (for Java) run in CI and report 0 Critical findings.
**Verification:** GitHub Actions shows both "npm audit" and "mvn dependency:check" steps with green checkmarks and "0 critical vulnerabilities" in output.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-4.2] All secrets stored in AWS Secrets Manager or GitHub Actions secrets (verified via code review).
**Verification:** Code review confirms no hardcoded credentials. All secrets referenced via environment variables sourced from AWS Secrets Manager or GitHub Actions secrets.  
**Exception:** No exceptions.
