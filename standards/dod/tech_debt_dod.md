## 🛠️ Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR shows 2+ approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key verified by GitHub.
**Verification:** GitHub PR commit list shows "Verified" badge on all commits.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MSG] All commit messages follow Conventional Commits format verified by CI lint.
**Verification:** GitHub Actions workflow "commitlint" check passes.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR merged to main using squash merge strategy (GitHub branch protection enforced).
**Verification:** GitHub branch protection rule requires squash merge; merge button shows "Squash and merge".  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube project dashboard shows Quality Gate = PASSED with 0 complexity violations.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] SonarQube reports no methods exceeding 50 lines of code.
**Verification:** SonarQube Issues tab filtered by "Methods should not be too long" shows 0 findings on changed files.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports 0 dead code findings in changed files.
**Verification:** SonarQube Issues tab filtered by "Remove this unused" or "Unreachable code" shows 0 findings.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-6.2-ARCH] ADR created in docs/adr/ following ADR template if change affects architecture, data model, or service contracts.
**Verification:** PR includes new ADR file in docs/adr/ if architectural change detected, or PR description states "No architectural impact".  
**Exception:** EM can waive if refactor is purely internal with no cross-service impact (document in PR).

## 🧪 Test Coverage & Quality

### [ ] [L1] [QA-2.1-LINE] JaCoCo reports ≥80% line coverage on all changed modules in CI.
**Verification:** GitHub Actions workflow "test" step shows JaCoCo report with ≥80% line coverage on changed packages.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-BRANCH] JaCoCo reports ≥75% branch coverage on all changed modules in CI.
**Verification:** JaCoCo HTML report linked in PR shows ≥75% branch coverage on changed classes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-REGRESS] CI coverage check passes with no coverage regression on existing covered code.
**Verification:** GitHub Actions workflow "coverage-diff" check passes (compares main vs PR branch).  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present using JUnit 5 for all new/changed business logic.
**Verification:** src/test/java/ contains JUnit 5 test classes covering changed business logic classes.  
**Exception:** Tech Lead approval if pure refactor with no logic change (document in PR).

### [ ] [L2] [QA-2.2-INTEGRATION] Integration tests present covering service/database integration points.
**Verification:** src/test/java/ contains @SpringBootTest annotated tests covering changed integration layers.  
**Exception:** Tech Lead approval if change is purely in-memory logic with no I/O (document in PR).

### [ ] [L2] [ENG-6.2-ARCH] Architecture Guild approval documented in PR if change affects architecture, data model, or service contracts.
**Verification:** PR has comment or approval from Architecture Guild member (tagged @arch-guild) if ADR present.  
**Exception:** EM can waive for purely internal refactors (document in PR).

### [ ] [L3] [TEAM-TECHDEBT-01] Tech debt item does not introduce new SonarQube technical debt (Maintainability rating remains A or B).
**Verification:** SonarQube project dashboard shows Technical Debt ratio ≤5.0% and Maintainability Rating = A or B after merge.  
**Exception:** Tech Lead approval if addressing higher-priority security debt (document in ticket).
