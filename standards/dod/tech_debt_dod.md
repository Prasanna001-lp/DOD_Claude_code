## Purpose
This Definition of Done ensures that technical debt work items meet quality, security, and architectural standards before merge. Tech debt items must reduce complexity, improve maintainability, or retire legacy code while maintaining or improving test coverage and system quality.

---

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR approval count shows ≥2 approvals, reviewer list includes ≥1 engineer with "Senior Engineer" or "Tech Lead" role.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit list shows "Verified" badge on all commits in PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-FORMAT] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions workflow "commit-lint" passes. Manual review confirms format: `feat|fix|docs|refactor|test|chore(scope): message`.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR is merged using squash merge strategy only.
**Verification:** GitHub branch protection rule enforces squash merge. Merge button shows "Squash and merge" as only option.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes: cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube dashboard shows Quality Gate status "Passed". No methods exceed complexity threshold 10.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LENGTH] No method exceeds 50 lines of code (verified by SonarQube).
**Verification:** SonarQube code smells report shows 0 violations for rule "Methods should not have too many lines".  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports 0 dead code issues (unreachable, commented-out code removed).
**Verification:** SonarQube issues tab filtered by type "Dead code" shows 0 results.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-6.2-ARCH] Architecture Decision Record (ADR) created in docs/adr/ for architectural changes.
**Verification:** Git diff shows new file matching pattern `docs/adr/NNNN-*.md` with ADR template sections filled.  
**Exception:** EM can grant one-sprint exemption if tech debt is non-structural (e.g., dependency upgrade with no API change). Exemption must be documented in PR description.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥80% line coverage on all changed modules.
**Verification:** GitHub Actions workflow "CI" job shows JaCoCo report with line coverage ≥80% for all modified packages. Build fails if threshold not met.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥75% branch coverage on changed modules.
**Verification:** GitHub Actions workflow "CI" job shows JaCoCo report with branch coverage ≥75% for all modified packages. Build fails if threshold not met.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] No existing covered code has lost coverage (CI build enforces no coverage regression).
**Verification:** GitHub Actions coverage-diff step passes. JaCoCo comparison shows no files with decreased coverage percentage.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present and passing (JUnit 5) for all changed code.
**Verification:** GitHub Actions test report shows all JUnit 5 tests pass. Test files exist in `src/test/java/` matching changed production files.  
**Exception:** EM can grant one-sprint exemption with written justification if tech debt removes code and tests are no longer applicable.

### [ ] [L3] [TEAM-TECH-DEBT-01] No new technical debt introduced (SonarQube Debt Ratio does not increase).
**Verification:** SonarQube overview page shows Technical Debt Ratio for PR ≤ Technical Debt Ratio for target branch. New Code tab shows "0min" or negative debt added.  
**Exception:** Tech Lead approval required if new debt is intentionally deferred. Must create follow-up Jira ticket tagged "tech-debt" with acceptance from EM.

## Security

### [ ] [L1] [SEC-3.1-SNYK] Snyk scan shows 0 Critical or High severity findings.
**Verification:** GitHub Actions workflow "Security Scan" step shows Snyk check passed. Snyk dashboard shows 0 Critical and 0 High vulnerabilities for PR branch.  
**Exception:** No exceptions. Findings must be fixed or have CISO-accepted risk waiver documented in Jira before merge.

### [ ] [L1] [SEC-3.1-SNYK] All Medium severity Snyk findings have tracked Jira tickets before merge.
**Verification:** Snyk dashboard shows Medium findings. Each has linked Jira ticket ID in PR description or Snyk "Ignore" reason field.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2-SECRETS] Gitleaks scan passes with 0 secrets detected in CI.
**Verification:** GitHub Actions workflow "Gitleaks" step status is green. Gitleaks report shows "leaks found: 0".  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] npm audit (React) or mvn dependency:check (Java) produces 0 Critical findings in CI.
**Verification:** GitHub Actions workflow shows `npm audit --audit-level=critical` exit code 0 for React modules. Maven build shows `mvn dependency-check:check` with 0 Critical CVEs for Java modules.  
**Exception:** No exceptions. Critical CVE dependencies must be upgraded or removed before merge.

## Architecture & Governance

### [ ] [L2] [ENG-6.2-ARCH] Architecture Guild review completed and approval documented in PR.
**Verification:** PR has comment from Architecture Guild member (role: "Architecture Guild") with explicit approval statement. Guild member listed as PR approver.  
**Exception:** EM can grant one-sprint exemption if tech debt is scoped to single service with no cross-service impact. Exemption must be documented in PR description.

### [ ] [L3] [TEAM-TECH-DEBT-02] Tech debt retirement tracked: Jira ticket updated with "before" and "after" metrics (e.g., build time, complexity, test count).
**Verification:** Jira ticket description or PR description includes metrics table showing measurable improvement (e.g., "SonarQube complexity reduced from 145 to 87", "Build time reduced from 8m12s to 5m03s").  
**Exception:** Tech Lead approval if metrics not applicable (e.g., code cleanup with no measurable impact). Justification required in PR.

## Documentation

### [ ] [L3] [TEAM-TECH-DEBT-03] Tech debt justification documented in PR: what was paid down, why, and what remains.
**Verification:** PR description includes section "Tech Debt Justification" with: (1) Problem statement, (2) Solution implemented, (3) Remaining debt (if any) with follow-up ticket links.  
**Exception:** Tech Lead approval. Reviewed quarterly.

### [ ] [L2] [IMPLICIT-DOC] Documentation updated for architectural changes (README, runbooks, architecture diagrams).
**Verification:** Git diff shows updates to relevant `docs/` files. If ADR created, it references updated architecture diagrams or runbook sections.  
**Exception:** EM can grant one-sprint exemption with written justification if documentation update is deferred to follow-up ticket.

## CI / Deployment Gate

### [ ] [L1] [IMPLICIT-CI] All CI checks pass in GitHub Actions (build, lint, test, security scans).
**Verification:** GitHub PR checks tab shows all required workflows green: "CI", "Security Scan", "Lint", "SonarQube".  
**Exception:** No exceptions.

### [ ] [L1] [IMPLICIT-LINT] Code passes linting checks (ESLint for React, Checkstyle/SpotBugs for Java).
**Verification:** GitHub Actions workflow "Lint" step passes. ESLint report shows 0 errors for `.js/.jsx` files. Maven build includes Checkstyle/SpotBugs with 0 violations for `.java` files.  
**Exception:** No exceptions.
