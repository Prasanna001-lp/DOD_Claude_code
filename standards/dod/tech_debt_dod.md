## Code Quality

- [ ] **[L1] [ENG-4.1]** PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.  
  **Verification:** GitHub PR page shows 2+ approvals with at least 1 from senior engineer role.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.2-SIGN]** All commits in PR are signed with GPG or SSH key registered in GitHub.  
  **Verification:** GitHub PR shows "Verified" badge on all commits.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.2-CONV]** All commit messages follow Conventional Commits format: type(scope): description.  
  **Verification:** GitHub Actions commitlint check passes.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.2-MERGE]** PR merge strategy set to "Squash and merge". Merge commits are not used on main branch.  
  **Verification:** GitHub PR settings show "Squash and merge" selected.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.3-CYCLO]** SonarQube quality gate passed with cyclomatic complexity ≤ 10 per method.  
  **Verification:** SonarQube status check green in GitHub Actions.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.3-LOC]** No method exceeds 50 lines of code.  
  **Verification:** SonarQube quality gate passes method length check.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.3-DEAD]** SonarQube reports zero dead code issues (unreachable or commented-out code removed).  
  **Verification:** SonarQube quality gate passes dead code check.  
  **Exception:** No exceptions.

- [ ] **[L2] [ENG-6.2-ARCH]** ADR created in docs/adr/ documenting architectural change, data model change, or cross-service contract change if applicable.  
  **Verification:** Git shows new file in docs/adr/ when architectural changes present. GitHub PR has approval from Architecture Guild member.  
  **Exception:** No exceptions for architectural changes.

## Test Coverage & Quality

- [ ] **[L1] [QA-2.1-COV]** JaCoCo reports 80%+ line coverage on all changed modules. No existing covered code has lost coverage.  
  **Verification:** GitHub Actions JaCoCo check passes. Coverage report shows 80% line coverage threshold met with no regression.  
  **Exception:** No exceptions.

- [ ] **[L1] [QA-2.1-COV]** JaCoCo reports 75%+ branch coverage on changed modules.  
  **Verification:** GitHub Actions JaCoCo check passes. Coverage report shows 75% branch coverage threshold met.  
  **Exception:** No exceptions.

- [ ] **[L2] [QA-2.2-UNIT]** Unit tests present using JUnit 5 and Mockito covering all changed code paths.  
  **Verification:** GitHub Actions test results show JUnit tests executed and passed.  
  **Exception:** EM approval required with written justification for one-sprint exemption.

- [ ] **[L3] [TEAM-TECH-DEBT]** SonarQube quality gate shows no increase in technical debt ratio. New code has debt ratio ≤ 5%.  
  **Verification:** SonarQube status check shows technical debt ratio maintained or reduced. New code debt ratio ≤ 5%.  
  **Exception:** Tech Lead approval. Reviewed quarterly.

## Security

- [ ] **[L1] [SEC-3.1-SNYK]** Snyk scan shows 0 Critical or High severity findings. Medium findings acknowledged with tracked Jira ticket.  
  **Verification:** GitHub Actions Snyk check passes. Medium findings have Jira ticket links in PR description.  
  **Exception:** No exceptions.

- [ ] **[L1] [SEC-3.2]** Gitleaks scan in CI pipeline passed with zero secrets detected. All secrets stored in AWS Secrets Manager or GitHub Actions secrets.  
  **Verification:** GitHub Actions Gitleaks check passes. PR description confirms secret storage location when secrets used.  
  **Exception:** No exceptions.

- [ ] **[L1] [SEC-3.3-DEPS]** Maven dependency:check (for Java) or npm audit (for Node.js) ran in CI with zero Critical CVE findings.  
  **Verification:** GitHub Actions Maven dependency:check or npm audit passes showing 0 Critical CVEs.  
  **Exception:** No exceptions.

## Documentation

- [ ] **[L2] [ENG-6.2-ARCH]** Architecture Guild review approval recorded on PR when architectural changes present.  
  **Verification:** GitHub PR has approval from Architecture Guild member when docs/adr/ modified or system architecture affected.  
  **Exception:** No exceptions for architectural changes.

- [ ] **[L3] [TEAM-TECH-DEBT-DOC]** Technical debt item documented with rationale, scope, and measurable improvement in PR description or linked ADR.  
  **Verification:** PR description contains "Technical Debt Context" section with rationale, scope, and success metrics. Or ADR present in docs/adr/.  
  **Exception:** Tech Lead approval. Reviewed quarterly.

- [ ] **[L3] [TEAM-JAVA-SPRING]** JavaDoc updated for all modified public APIs in Java/Spring Boot code.  
  **Verification:** Git diff shows JavaDoc comments present on all modified public methods and classes.  
  **Exception:** Tech Lead approval. Reviewed quarterly.

## CI / Deployment Gate

- [ ] **[L1] [UNIVERSAL-CI]** All GitHub Actions checks pass (lint, build, test, security scan, SonarQube).  
  **Verification:** GitHub PR shows all status checks green.  
  **Exception:** No exceptions.

- [ ] **[L2] [TEAM-TECH-DEBT-CI]** No new SonarQube code smells introduced. Existing code smells in modified files reduced or documented with suppression justification.  
  **Verification:** SonarQube quality gate shows code smell count unchanged or reduced. Suppressions documented in code comments with Jira ticket reference.  
  **Exception:** EM approval for one sprint with written justification.

## Acceptance & Sign-off

- [ ] **[L2] [TEAM-TECH-DEBT-PO]** Tech Lead confirms technical debt item addresses root cause and measurable improvement criteria met.  
  **Verification:** Tech Lead approval on GitHub PR with comment confirming improvement criteria achieved.  
  **Exception:** EM approval for one sprint with written justification.

- [ ] **[L3] [TEAM-TECH-DEBT-VALIDATION]** Before/after metrics captured (e.g., build time, test execution time, SonarQube metrics, deployment frequency).  
  **Verification:** PR description contains "Metrics" section with before/after comparison. Screenshots or CI logs attached.  
  **Exception:** Tech Lead approval. Reviewed quarterly.
