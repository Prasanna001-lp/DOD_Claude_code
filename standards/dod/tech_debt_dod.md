## Overview

This Definition of Done applies to all work items of type **Tech Debt** in the Commerce Platform team backlog.

Tech debt work includes: refactoring, dependency upgrades, architecture improvements, code quality improvements, performance optimization, and removal of deprecated code.

Every criterion is:
- **VERIFIABLE** — binary pass/fail, with named tool or artifact
- **TRACEABLE** — linked to source policy via `[SOURCE-REF]` tag
- **LAYERED** — tagged `[L1]` (universal), `[L2]` (tech debt specific), `[L3]` (team-specific), or `[L4]` (story-specific)

**Override Policy:**
- **[L1]** criteria cannot be overridden. Contact EM + CISO to modify.
- **[L2]** criteria can be exempted for one sprint by EM with written justification.
- **[L3]** criteria require Tech Lead approval. Reviewed quarterly.
- **[L4]** criteria are added by PO or Tech Lead during grooming.
