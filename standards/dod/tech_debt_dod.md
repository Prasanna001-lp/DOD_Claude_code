## Purpose

This checklist defines the **mandatory quality gates** for all tech debt work items in the Commerce Platform team. Every criterion is:

- **Verifiable** — binary pass/fail using named tools
- **Traceable** — linked to source policy or standard
- **Enforceable** — gates CI/CD pipeline or PR merge

**Layer Key:**
- **[L1]** — Universal. Applies to ALL work items. Cannot be overridden.
- **[L2]** — Work-type specific. Applies to ALL tech debt items. EM can grant one-sprint exemption.
- **[L3]** — Team-specific. Based on Commerce Platform tech stack. Tech Lead approval to modify.
- **[L4]** — Story-specific. Added during grooming by PO or Tech Lead.

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR shows 2+ approvals with at least 1 from senior engineer. Branch protection enforces this.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub displays "Verified" badge on all commits in the PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** commitlint GitHub Action passes in CI. All commits match pattern: `feat|fix|refactor|docs|chore(scope): description`.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR is configured for squash merge. Merge commits to main are blocked by branch protection.
**Verification:** GitHub branch protection rules enforce "Require linear history" and PR merge button shows "Squash and merge".  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY/LOC/DEAD] SonarQube quality gate passes: cyclomatic complexity ≤10 per method, no methods >50 lines of code, 0 dead code issues.
**Verification:** SonarQube status check passes in GitHub Actions. SonarQube dashboard shows "Passed" quality gate status.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-6.2-ADR] ADR created in docs/adr/ if change affects system architecture, data model, or cross-service contracts.
**Verification:** New ADR file present in `docs/adr/` following ADR template. ADR number sequential. File named `NNNN-title.md`.  
**Exception:** Tech Lead can waive if change is purely implementation refactoring with no architectural impact. Waiver documented in PR description.

### [ ] [L2] [ENG-6.2-ADR] Architecture Guild approval obtained and documented in PR comments or linked Slack thread.
**Verification:** Architecture Guild member (tagged `@architecture-guild`) has approved the PR, or Slack thread link showing approval is in PR description.  
**Exception:** Tech Lead can waive for implementation-only changes. Waiver documented in PR description.

### [ ] [L3] [TECH-DEBT-SCOPE] Tech debt item does not introduce new technical debt. SonarQube shows technical debt ratio unchanged or improved.
**Verification:** SonarQube technical debt metric in PR analysis shows: (new technical debt minutes) ≤ (removed technical debt minutes).  
**Exception:** No exceptions. Tech debt work must reduce or maintain technical debt, not increase it.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥80% line coverage on changed modules in CI.
**Verification:** JaCoCo GitHub Action passes. Coverage report attached to PR shows line coverage ≥80% for all changed Java classes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥75% branch coverage on changed modules in CI.
**Verification:** JaCoCo GitHub Action passes. Coverage report shows branch coverage ≥75% for all changed Java classes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] CI build verifies no coverage regression: existing covered code maintains or improves coverage.
**Verification:** JaCoCo diff report in CI shows: no existing test file has lost coverage percentage compared to main branch.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present for all new/changed methods using JUnit 5 and Mockito.
**Verification:** Test classes in `src/test/java/` mirror changed production classes. Each new/changed public method has corresponding `@Test` method.  
**Exception:** Tech Lead can waive for pure deletion of code. Waiver documented in PR description.

### [ ] [L3] [TECH-DEBT-REFACTOR] Refactored code maintains 100% of existing test coverage. No existing tests deleted without replacement.
**Verification:** Git diff shows: if test files deleted, new test files provide equivalent coverage. CI test count unchanged or increased.  
**Exception:** Tech Lead approval required if test count decreases. Justification documented in PR description.

## Security

### [ ] [L1] [SEC-3.1-SNYK] Snyk scan reports 0 Critical or High severity findings.
**Verification:** Snyk GitHub Action passes. Snyk dashboard shows 0 Critical and 0 High vulnerabilities for this PR.  
**Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver attached to PR.

### [ ] [L1] [SEC-3.1-SNYK] All Medium severity findings from Snyk have corresponding Jira tickets linked in PR description.
**Verification:** PR description contains Jira ticket links (format: `PROJ-NNNN`) for each Medium finding listed in Snyk report.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2-SECRETS] Gitleaks scan passes in CI with 0 secrets detected.
**Verification:** Gitleaks GitHub Action passes. CI log shows "No leaks found" message.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS-APPROVAL] All new dependencies are listed in approved dependency registry. CI checks compliance.
**Verification:** Custom "check-dependencies" GitHub Action passes. No new entries in `pom.xml` or `package.json` without corresponding entry in `approved-deps.yaml`.  
**Exception:** No exceptions. New dependencies require Security Champion pre-approval before PR merge.

### [ ] [L1] [SEC-3.3-DEPS] mvn dependency:check reports 0 Critical CVE findings in CI.
**Verification:** Maven dependency-check GitHub Action passes. OWASP Dependency-Check report shows 0 Critical CVEs.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-4.2-SECRETS-MGMT] All secrets stored in AWS Secrets Manager or GitHub Actions secrets. Verified by Gitleaks scan.
**Verification:** Gitleaks passes (SEC-03). Code review confirms any new configuration references secrets from AWS Secrets Manager or GitHub encrypted secrets.  
**Exception:** No exceptions.

## Documentation

### [ ] [L2] [TECH-DEBT-JUSTIFICATION] Tech debt ticket contains business justification: what technical debt is being addressed and why.
**Verification:** Jira ticket linked in PR has "Technical Debt Context" section describing: (1) what debt exists, (2) impact if not addressed, (3) benefit of addressing.  
**Exception:** No exceptions.

### [ ] [L2] [TECH-DEBT-SCOPE] PR description documents scope boundaries: what IS and what IS NOT addressed in this refactoring.
**Verification:** PR description contains "Scope" section with bullet points listing: included changes and explicitly excluded changes (if applicable).  
**Exception:** No exceptions.

### [ ] [L3] [TECH-DEBT-METRICS] Before/after metrics documented in PR: lines of code removed, complexity reduced, test coverage improved, or performance gain.
**Verification:** PR description contains "Impact Metrics" section with quantified improvements (e.g., "Removed 347 LOC", "Reduced cyclomatic complexity from 15 to 8", "Improved test coverage from 72% to 85%").  
**Exception:** Tech Lead can waive if metrics are not applicable (e.g., dependency upgrade with no code change). Waiver noted in PR description.

### [ ] [L3] [TECH-DEBT-ADR-UPDATE] If refactoring supersedes a previous architectural decision, existing ADR is marked superseded and links to new ADR (if created).
**Verification:** Existing ADR file updated with "Status: Superseded by ADR-NNNN" at top. New ADR references old ADR in "Context" section.  
**Exception:** Only applies if an ADR existed for the code being refactored. N/A if no relevant ADR exists.

## CI / Deployment Gate

### [ ] [L1] [CI-ALL-CHECKS] All GitHub Actions checks pass: build, lint, unit tests, integration tests, Snyk, Gitleaks, JaCoCo, SonarQube, commitlint.
**Verification:** GitHub PR status shows all checks green. No failing checks. No skipped checks.  
**Exception:** No exceptions.

### [ ] [L3] [TECH-DEBT-BUILD-TIME] Refactoring does not increase CI build time by >10%.
**Verification:** GitHub Actions workflow duration for this PR compared to main branch average (last 10 runs): increase ≤10%.  
**Exception:** Tech Lead can waive if increase is justified (e.g., added integration tests for previously untested code). Justification in PR description.
