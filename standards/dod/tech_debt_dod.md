## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR review page shows 2+ approved reviews, at least 1 reviewer has "Senior Engineer" or "Tech Lead" role visible in GitHub team membership.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-SIGNING] All commits are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit history shows "Verified" badge on all commits in the PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-FORMAT] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** commitlint check passes in GitHub Actions workflow; all commit messages match pattern `^(feat|fix|docs|style|refactor|perf|test|chore)(\(.+\))?: .+`  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR merged using squash merge strategy; no merge commits on main branch.
**Verification:** GitHub branch protection rule enforces squash merge; `git log --merges origin/main` shows no merge commits after this PR merge.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube dashboard shows Quality Gate status = PASSED; Complexity metric shows 0 methods exceeding threshold of 10.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.3-LENGTH] No method exceeds 50 lines of code.
**Verification:** SonarQube code metrics report shows 0 violations for rule "Methods should not have too many lines" (threshold: 50).  
**Exception:** Engineering Manager can grant exemption for single method if justified by business logic complexity and documented in PR.

### [ ] [L1] [ENG-4.3-DEADCODE] SonarQube reports 0 dead code issues; no commented-out code blocks present.
**Verification:** SonarQube dashboard shows 0 issues tagged "unused" or "dead"; manual PR review checklist item confirmed by approver with comment "No commented-out code found".  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-TECH-STACK] No new technical debt introduced: SonarQube technical debt ratio remains ≤5% or decreases.
**Verification:** SonarQube project dashboard shows Technical Debt Ratio metric ≤5.0% after PR merge, or value decreased compared to main branch baseline.  
**Exception:** Tech Lead can approve temporary increase if offset by explicit debt reduction plan documented in Jira epic.

## Architecture & Design

### [ ] [L2] [ENG-6.2-ADR] Architecture Decision Record (ADR) created in docs/adr/ if changes affect system architecture, data model, or cross-service contracts.
**Verification:** New ADR file exists in `docs/adr/` with filename format `NNNN-title.md` following template; ADR includes Context, Decision, Consequences sections.  
**Exception:** Not required if tech debt work is purely internal refactoring with no architectural impact. Tech Lead confirms in PR comment.

### [ ] [L2] [ENG-6.2-ADR] Architecture Guild approval documented in PR for structural changes.
**Verification:** PR has approval from GitHub user with `@commerce-platform/architecture-guild` team membership; approval comment references ADR number.  
**Exception:** Not required if no ADR was needed (see ARCH-01 exception).

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥80% line coverage on all changed modules.
**Verification:** GitHub Actions CI job "Test & Coverage" passes; JaCoCo HTML report (`target/site/jacoco/index.html`) shows line coverage ≥80% for all modified packages.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥75% branch coverage on changed modules.
**Verification:** JaCoCo HTML report shows branch coverage ≥75% for all modified packages; GitHub Actions job "Coverage Check" passes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] CI build verifies no existing covered code has lost coverage (0% coverage regression).
**Verification:** GitHub Actions job "Coverage Diff" passes; workflow comment on PR shows "Coverage regression: 0 files" or "All files maintained or improved coverage".  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present for all changed production code.
**Verification:** JUnit 5 test suite in `src/test/java/` includes test classes matching all modified production classes; test methods cover public methods modified in PR. GitHub Actions "Unit Tests" job shows 0 failures.  
**Exception:** Engineering Manager can grant exemption if code change is purely declarative (e.g., Spring configuration) with no logic to test.

### [ ] [L2] [QA-2.2-INTEGRATION] Integration tests present and passing in CI if tech debt affects integration points.
**Verification:** JUnit 5 integration tests in `src/test/java/**/*IntegrationTest.java` execute in GitHub Actions "Integration Tests" job; all tests pass; PR description documents which integration scenarios are covered.  
**Exception:** Not required if tech debt is isolated to single module with no external dependencies. Tech Lead confirms in PR review.

## Security

### [ ] [L1] [SEC-3.1-SAST] Snyk scan shows 0 Critical or High severity findings.
**Verification:** GitHub Actions "Snyk Security Scan" job passes; Snyk dashboard shows 0 issues with severity Critical or High for this PR branch.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.1-SAST] All Medium severity Snyk findings have tracked Jira tickets attached to PR.
**Verification:** Snyk report lists Medium findings; PR description includes Jira ticket links (format: `PROJ-NNNN`) for each Medium finding; tickets exist in "Security Backlog" with status "Open" or "In Progress".  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2-SECRETS] Gitleaks scan passes with 0 secrets detected in CI.
**Verification:** GitHub Actions "Gitleaks Scan" job status = success; `gitleaks report.json` shows `"findings": []`.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] Dependency vulnerability scan produces 0 Critical CVE findings.
**Verification:** GitHub Actions runs `mvn dependency:check` (Java/Spring Boot) and `npm audit --production` (React); both jobs pass with exit code 0. CI log shows "Found 0 vulnerabilities" or "No known vulnerabilities".  
**Exception:** No exceptions.

### [ ] [L2] [SEC-3.3-DEPS] All new or updated dependencies are listed in approved dependency registry.
**Verification:** PR checklist item "Dependencies approved" checked; `dependencies.yaml` or `pom.xml` diff shows only dependencies present in `approved-dependencies.json`; or PR comment from Tech Lead states "All deps pre-approved".  
**Exception:** Engineering Manager can approve emergency dependency addition with post-merge registry update tracked in Jira.

## Documentation

### [ ] [L2] [ENG-6.1-API] CHANGELOG.md updated with entry under [Unreleased] section if tech debt affects observable behavior.
**Verification:** `git diff main...HEAD -- CHANGELOG.md` shows new entry in `[Unreleased]` section; entry format: `"- Changed: [description]"` or `"- Fixed: [description]"`.  
**Exception:** Not required if tech debt is purely internal refactoring with zero observable behavior change. Tech Lead confirms in PR comment.

### [ ] [L3] [TEAM-TECH-STACK] Inline code documentation (Javadoc for Java, JSDoc for React) updated for modified public methods.
**Verification:** Manual PR review confirms all modified public methods have current Javadoc/JSDoc comments; SonarQube "Documentation" rule shows 0 new violations.  
**Exception:** Tech Lead can approve if public API is deprecated and scheduled for removal within 1 sprint.

## CI / Deployment Gate

### [ ] [L1] [TEAM-CI-TOOL] All GitHub Actions CI checks pass (build, lint, test, security scan).
**Verification:** GitHub PR checks page shows all required status checks green: "Build", "Lint", "Unit Tests", "Integration Tests", "Snyk Scan", "Gitleaks", "SonarQube Analysis".  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-TECH-STACK] Spring Boot application starts successfully in CI environment.
**Verification:** GitHub Actions job "Application Smoke Test" passes; CI log shows "Started Application in X.XXX seconds" without exceptions.  
**Exception:** Not required if tech debt does not affect application startup. Tech Lead confirms in PR comment.

## Acceptance & Sign-off

### [ ] [L2] [TEAM-WORKFLOW] Tech Lead has reviewed and approved reduction in technical debt metrics.
**Verification:** PR has approval from GitHub user with "Tech Lead" role; approval comment explicitly states "Technical debt reduction verified" or references SonarQube debt metric improvement.  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-WORKFLOW] Jira ticket status updated to "Ready for Merge" by QA or Tech Lead.
**Verification:** Jira ticket linked in PR description shows status = "Ready for Merge" and "QA Verified" or "Tech Lead Approved" label present.  
**Exception:** Not required if team does not use Jira ticket workflow gates. Tech Lead confirms alternative approval process followed.
