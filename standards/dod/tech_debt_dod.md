## Code Quality

**[ ] [L1] [ENG-4.1]** PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.  
**Verification:** GitHub PR approvals tab shows 2+ approvals with at least 1 from @senior-engineer or @tech-lead.  
**Exception:** No exceptions.

**[ ] [L1] [ENG-4.2-SIGN]** All commits in PR are signed with GPG or SSH key registered in GitHub.  
**Verification:** GitHub commits view shows "Verified" badge on all commits.  
**Exception:** No exceptions.

**[ ] [L1] [ENG-4.2-CONV]** All commit messages follow Conventional Commits format: type(scope): description.  
**Verification:** GitHub Actions workflow "conventional-commits-check" passes.  
**Exception:** No exceptions.

**[ ] [L1] [ENG-4.2-MERGE]** PR uses squash merge strategy (no merge commits on main).  
**Verification:** GitHub PR merge button shows "Squash and merge" selected. Branch protection rules enforce squash-only.  
**Exception:** No exceptions.

**[ ] [L1] [ENG-4.3-COMPLEX]** SonarQube quality gate passes with cyclomatic complexity ≤10 per method.  
**Verification:** SonarQube CI check reports "Quality Gate: Passed" with 0 methods exceeding complexity threshold of 10.  
**Exception:** No exceptions.

**[ ] [L1] [ENG-4.3-LINES]** No method exceeds 50 lines of code (enforced by SonarQube quality gate).  
**Verification:** SonarQube CI check reports 0 methods exceeding 50 lines.  
**Exception:** No exceptions.

**[ ] [L1] [ENG-4.3-DEAD]** SonarQube reports zero dead code issues (unreachable or commented-out code).  
**Verification:** SonarQube CI check shows 0 issues tagged "dead code" or "unreachable".  
**Exception:** No exceptions.

**[ ] [L2] [ENG-6.2-ADR]** ADR created in docs/adr/ documenting architecture change with context, decision, and consequences.  
**Verification:** Git diff shows new file in docs/adr/ with filename format NNNN-title.md. ADR contains sections: Context, Decision, Consequences.  
**Exception:** Tech Lead can approve skip if change is purely internal refactoring with no architectural impact. Approval must be documented in PR comment.

**[ ] [L2] [ENG-6.2-ADR]** Architecture Guild approval documented on PR (comment or approval from @architecture-guild member).  
**Verification:** GitHub PR shows comment or approval from user with @architecture-guild team membership.  
**Exception:** Tech Lead can approve skip if change is purely internal refactoring with no architectural impact. Approval must be documented in PR comment.

## Test Coverage & Quality

**[ ] [L1] [QA-2.1-COVERAGE-LINE]** JaCoCo reports ≥80% line coverage on all changed modules.  
**Verification:** GitHub Actions workflow "test-coverage" passes. JaCoCo report shows line coverage ≥80% for each changed Java package.  
**Exception:** No exceptions.

**[ ] [L1] [QA-2.1-COVERAGE-BRANCH]** JaCoCo reports ≥75% branch coverage on all changed modules.  
**Verification:** GitHub Actions workflow "test-coverage" passes. JaCoCo report shows branch coverage ≥75% for each changed Java package.  
**Exception:** No exceptions.

**[ ] [L1] [QA-2.1-NO-REGRESSION]** CI coverage check passes with no regression on existing covered code (JaCoCo diff shows no coverage loss).  
**Verification:** GitHub Actions workflow "coverage-diff" passes. Workflow comment shows "No coverage regression detected" or coverage delta ≥0%.  
**Exception:** No exceptions.

**[ ] [L2] [QA-2.2-UNIT]** Unit tests present using JUnit 5 and Mockito covering changed code paths.  
**Verification:** Git diff shows test files in src/test/java/ with @Test annotations. Tests execute in GitHub Actions "unit-tests" workflow with 100% pass rate.  
**Exception:** Engineering Manager can grant one-sprint exemption with written justification if refactoring existing well-covered code. Exemption must be documented in PR description.

**[ ] [L3] [TEAM-TECH-DEBT-01]** No new technical debt introduced: SonarQube reports 0 new code smells, 0 new bugs, 0 new vulnerabilities.  
**Verification:** SonarQube "New Code" tab shows: Code Smells=0, Bugs=0, Vulnerabilities=0.  
**Exception:** Tech Lead approval required. Must document reason and remediation plan in JIRA ticket.

## Security

**[ ] [L1] [SEC-3.1-SNYK]** Snyk scan shows 0 Critical or High severity findings. Medium findings have tracked Jira tickets linked in PR.  
**Verification:** GitHub Actions workflow "snyk-scan" passes. Snyk CI check reports "0 Critical, 0 High". Any Medium findings have JIRA ticket IDs in PR description (format: JIRA-NNNN).  
**Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver documented in JIRA ticket.

**[ ] [L1] [SEC-3.2-SECRETS]** Gitleaks scan passes with 0 secrets detected in CI pipeline.  
**Verification:** GitHub Actions workflow "gitleaks-scan" passes with exit code 0.  
**Exception:** No exceptions.

**[ ] [L1] [SEC-3.3-DEPS]** npm audit and mvn dependency:check produce 0 Critical CVE findings in CI.  
**Verification:** GitHub Actions workflow "dependency-audit" passes. npm audit shows "0 vulnerabilities" for Critical. mvn dependency:check shows no Critical CVEs in console output.  
**Exception:** No exceptions.

**[ ] [L1] [SEC-4.2-SECRETS-MGMT]** No hardcoded secrets in code (Gitleaks enforces). All secrets reference AWS Secrets Manager or GitHub Actions secrets.  
**Verification:** Gitleaks scan passes (SEC-02 verifies this). Code review confirms any new configuration references use process.env.* (Node.js) or System.getenv() (Java) pointing to AWS Secrets Manager ARNs or GitHub Actions secrets.  
**Exception:** No exceptions.

## Documentation

**Exception:** Tech Lead approval required to skip. Approval must state reason (e.g., "Internal refactoring only, no user-facing changes").

**Verification:** Verified by CODE-08 and CODE-09 criteria. No separate verification needed.  
**Exception:** Same as CODE-08, CODE-09.

**Verification:** GitHub PR checks tab shows all workflows with green checkmarks. No red X marks present.

## Acceptance & Sign-off

**[ ] [L3] [TEAM-TECH-DEBT-04]** Tech Lead confirms technical debt reduction is measurable (e.g., SonarQube debt ratio decreased, test coverage increased, cyclomatic complexity reduced).  
**Verification:** Tech Lead approval comment on PR includes statement: "Confirmed debt reduction: [metric improvement]". Example: "Confirmed debt reduction: SonarQube Technical Debt reduced by 2 hours, coverage increased from 72% to 81%".  
**Exception:** Engineering Manager can approve if Tech Lead unavailable. Must document business justification.

**[ ] [L2] [TEAM-TECH-DEBT-05]** Original technical debt ticket (JIRA) updated with resolution notes and closed.  
**Verification:** JIRA ticket referenced in PR description shows Status = "Done" or "Closed". Resolution field populated with summary of changes.  
**Exception:** Engineering Manager can grant one-sprint exemption if debt work spans multiple PRs. Must link to epic or parent ticket.
