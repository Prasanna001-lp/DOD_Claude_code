## Overview

This Definition of Done applies to all work items classified as **API Change** — changes to public API endpoints (REST, GraphQL, event schemas) that affect external consumers or cross-service contracts.

Every criterion must be verified before the pull request is merged to main.

**Legend:**
- **[L1]** = Universal gate (applies to ALL work types, no exceptions without EM + CISO sign-off)
- **[L2]** = Work-type specific (applies to all API Change items, EM can grant one-sprint exemption)
- **[L3]** = Team-specific (based on Commerce Platform tech stack, Tech Lead approval required)
- **[L4]** = Story-specific (added during grooming by PO or Tech Lead)

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR page shows 2+ approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L3] [ENG-4.1-SEC] PR touching security-critical paths (auth, crypto, secrets, IAM, data protection) has additional approval from Security Champion.
**Verification:** GitHub PR shows Security Champion approval when security-critical files modified.  
**Exception:** No exceptions for security-critical changes.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub PR shows "Verified" badge on all commits.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions commitlint check passes.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR merge strategy set to "Squash and merge". Merge commits are not used on main branch.
**Verification:** GitHub PR settings show "Squash and merge" selected.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-CYCLO] SonarQube quality gate passed with cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube status check green in GitHub Actions.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] No method exceeds 50 lines of code.
**Verification:** SonarQube quality gate passes method length check.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports zero dead code issues (unreachable or commented-out code removed).
**Verification:** SonarQube quality gate passes dead code check.  
**Exception:** No exceptions.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COV] JaCoCo reports 80%+ line coverage and 75%+ branch coverage on all changed modules. No existing covered code has lost coverage.
**Verification:** GitHub Actions JaCoCo check passes. Coverage report shows thresholds met.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present using JUnit 5 and Mockito covering all changed code paths.
**Verification:** GitHub Actions test results show JUnit tests executed and passed.  
**Exception:** EM approval required with written justification.

### [ ] [L2] [QA-2.2-INTEG] Integration tests present and passing in CI for API change.
**Verification:** GitHub Actions shows integration test suite execution and pass.  
**Exception:** EM approval for one sprint if integration test environment unavailable.

### [ ] [L2] [From INC-002] API contract test includes all nullable fields documented in OpenAPI spec.
**Verification:** GitHub Actions shows contract test execution. Test code references all nullable fields from api/openapi.yaml.  
**Exception:** EM approval for one sprint with written justification.  
**Incident Reference:** INC-002 (2024-10-03) — Order API returned 500 for null payment method field.

### [ ] [L2] [QA-2.4-PERF] k6 load test included in CI for endpoint handling > 1000 RPS. P95 response time < 500ms and P99 < 2000ms under normal load.
**Verification:** GitHub Actions k6 test results show thresholds met.  
**Exception:** EM approval for one sprint if load test environment unavailable.

### [ ] [L3] [TEAM-KAFKA] If API publishes events to Kafka, schema registry validation test passes with all event fields validated against Avro schema.
**Verification:** GitHub Actions shows Kafka schema registry validation test execution and pass.  
**Exception:** Tech Lead approval. Reviewed quarterly.

## Security

### [ ] [L1] [SEC-3.1-SNYK] Snyk scan shows 0 Critical or High severity findings. Medium findings acknowledged with tracked Jira ticket.
**Verification:** GitHub Actions Snyk check passes. Medium findings have Jira ticket links in PR description.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2] Gitleaks scan in CI pipeline passed with zero secrets detected. All secrets stored in AWS Secrets Manager or GitHub Actions secrets.
**Verification:** GitHub Actions Gitleaks check passes. PR description confirms secret storage location when secrets used.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] Maven dependency:check (for Java) or npm audit (for Node.js) ran in CI with zero Critical CVE findings.
**Verification:** GitHub Actions Maven/NPM check passes showing 0 Critical CVEs.  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-SPRING-SECURITY] If API endpoint requires authentication, Spring Security test verifies 401 Unauthorized response for unauthenticated requests.
**Verification:** GitHub Actions shows Spring Security integration test execution covering authentication requirement.  
**Exception:** Tech Lead approval. Reviewed quarterly.

**Verification:** PR description contains API diff or link to diff artifact (openapi-diff output).

**Exception:** Tech Lead approval. Reviewed quarterly.
