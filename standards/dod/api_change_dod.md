## Overview

This Definition of Done applies to all work items categorized as **API Change**. An API Change includes modifications to:
- REST API endpoints (new endpoints, changed request/response schemas, changed behaviour)
- GraphQL schema changes
- Event schemas (Kafka message formats)
- Public library interfaces exposed to other services

All criteria must be satisfied before the work item can be merged to main and marked as complete.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COVERAGE-LINE] JaCoCo reports ≥80% line coverage on all changed modules.
**Verification:** GitHub Actions JaCoCo report shows line coverage ≥80% for each module with changed code. CI check "coverage/line-coverage" passes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE-BRANCH] JaCoCo reports ≥75% branch coverage on all changed modules.
**Verification:** GitHub Actions JaCoCo report shows branch coverage ≥75% for each module with changed code. CI check "coverage/branch-coverage" passes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-NO-REGRESSION] CI coverage check passes with no regression on existing covered code (JaCoCo diff shows no coverage loss).
**Verification:** GitHub Actions check "coverage/regression-check" passes. JaCoCo diff report attached to PR shows 0 lines with coverage decrease.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present using JUnit 5 and Mockito covering changed code paths.
**Verification:** Test files in `src/test/java/**/*Test.java` exist for each changed class. Tests use `@Test` annotation from JUnit 5 and mock external dependencies using Mockito.  
**Exception:** Tech Lead can exempt pure data transfer objects (DTOs) with no business logic.

### [ ] [L2] [QA-2.2-INTEGRATION] Integration tests present covering service interactions and data flow.
**Verification:** Test files in `src/test/java/**/*IntegrationTest.java` exist covering API endpoints with `@SpringBootTest` annotation. Tests verify request/response flow without mocking database or external service clients.  
**Exception:** Tech Lead can exempt internal refactoring that does not change integration boundaries.

### [ ] [L2] [From INC-002] API contract test includes test cases for all nullable fields documented in OpenAPI spec.
**Verification:** Contract test file in `src/test/java/**/contract/**/*ContractTest.java` contains test methods explicitly setting each nullable field to null and verifying response does not throw NullPointerException or return 500.  
**Exception:** No exceptions.  
**Note:** This criterion was added following escaped defect INC-002 (Order API returned 500 for null payment method field).

### [ ] [L2] [QA-2.4-PERF] k6 load test present in CI for endpoint, reporting P95 < 500ms and P99 < 2000ms under normal load.
**Verification:** k6 test script in `tests/load/*_load.js` exists for changed endpoint. GitHub Actions check "performance/load-test" passes with output showing "p95 < 500ms" and "p99 < 2000ms" for simulated load of 1000 RPS.  
**Exception:** Applies only to endpoints expected to handle >1000 RPS. PO documents exemption in acceptance criteria for low-traffic endpoints.
