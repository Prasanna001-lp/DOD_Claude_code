## Overview

This Definition of Done checklist applies to all work items classified as **API Change** — any modification to a public API endpoint, including:
- New endpoints
- Changed request/response schemas
- Modified authentication/authorization logic
- Endpoint deprecation or removal
- Query parameter or header changes

All criteria must be verified and checked before marking the work item as **Done**.

## Test Coverage & Quality

**Verification:** JaCoCo GitHub Actions check passes with 80%+ line coverage report attached to PR.

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥75% branch coverage on changed modules in CI.
**Verification:** JaCoCo branch coverage report shows 75%+ for changed modules.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] CI build verifies no coverage regression: existing covered code maintains or improves coverage.
**Verification:** JaCoCo diff report shows no coverage decrease on existing code.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-UNIT] Unit tests present for all new/changed methods using JUnit 5 and Mockito.
**Verification:** Test files in src/test/java/ cover new/changed classes. CI runs unit test suite.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [QA-2.2-INTEGRATION] Integration tests present covering service-to-service or service-to-database interactions for changed API endpoints.
**Verification:** Integration test files present in test suite. CI runs integration tests successfully.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [From INC-002] API contract tests include explicit test cases for all nullable fields documented in api/openapi.yaml.
**Verification:** Contract test suite includes test methods that set nullable fields to null and verify 200/4xx response handling.  
**Exception:** No exceptions.  
**⚠️ Escaped Defect:** This criterion prevents recurrence of production incident INC-002 (P2 severity).

### [ ] [L2] [QA-2.4-PERF] If endpoint is expected to handle >1000 RPS, k6 load test is included.
**Verification:** k6 test script present in tests/performance/. Test results attached to PR or visible in CI logs.  
**Exception:** Not applicable if endpoint expected load <1000 RPS.

### [ ] [L2] [QA-2.4-PERF] If k6 test is required, results show P95 response time <500ms and P99 <2000ms under normal load.
**Verification:** k6 test output or CI logs show P95 and P99 latency metrics meeting thresholds.  
**Exception:** Not applicable if previous criterion not applicable.
