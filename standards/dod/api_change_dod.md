## Overview

This Definition of Done applies to all work items involving changes to public or internal API endpoints. This includes:
- Adding new REST API endpoints
- Modifying existing endpoint request/response schemas
- Changing HTTP methods, status codes, or headers
- Deprecating or removing endpoints
- Changing authentication or authorization requirements

**Layer Key:**
- **[L1]** — Universal criteria applied to ALL work items (cannot be overridden)
- **[L2]** — Work type-specific criteria for API changes (EM can grant one-sprint exemption)
- **[L3]** — Team-specific criteria based on Commerce Platform tech stack (Tech Lead approval)
- **[L4]** — Story-specific criteria added during grooming (PO + Tech Lead agreement)

**Verification:** GitHub Actions JaCoCo diff check passes (no red lines in coverage diff report).

### TEST-04 [L2] [QA-2.2-UNIT]
**[ ] Unit tests present using JUnit 5 for all new/changed business logic in API handlers and service layer.**

**Verification:** Test files exist in src/test/java matching changed files in src/main/java. Tests execute in CI and pass.

**Exception:** Engineering Manager can grant one-sprint exemption with written justification if API change is pure data model update with no logic.

---

### TEST-05 [L2] [QA-2.2-INTEGRATION]
**[ ] Integration tests present covering service/database/Kafka integration points affected by API change.**

**Verification:** Integration test class (annotated with @SpringBootTest) exists testing changed API endpoint with real database and Kafka interactions. Test passes in CI.

**Exception:** Engineering Manager can grant one-sprint exemption with written justification if change does not affect integration layer.

---

### TEST-06 [L2] [From INC-002] ⚠️ Production Incident
**[ ] API contract tests include all nullable fields documented in the OpenAPI spec.**

**Verification:** Contract test class exists verifying API behavior for all nullable request/response fields (sending null values and validating response). Test passes in CI.

**Exception:** Engineering Manager can grant one-sprint exemption with written justification if API change does not introduce new nullable fields.

**Incident Context:** Order API returned 500 for null payment method field. Root cause: OpenAPI contract not updated to reflect nullable field. (INC-002, 2024-10-03, P2)

---

### TEST-07 [L2] [QA-2.4-PERF]
**[ ] k6 load test included in CI for endpoints expecting >1000 RPS, verifying P95 <500ms and P99 <2000ms under load.**

**Verification:** k6 test script exists in tests/load/ for changed endpoint. GitHub Actions k6 check passes showing P95 and P99 metrics within thresholds.

**Exception:** Engineering Manager can grant one-sprint exemption if endpoint is internal-only or expected load <1000 RPS. Must document expected RPS in PR.
