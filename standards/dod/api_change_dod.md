## Overview

This Definition of Done applies to all work items classified as **API Change** in Jira. An API Change is any modification to a public API endpoint, request/response schema, status codes, or cross-service contract.

All criteria are **mandatory** unless explicitly marked as conditional. Every criterion must be verified before marking the story as "Done" in Jira.

**Layer Legend:**
- **[L1]** — Universal gate. Applies to ALL work items. Cannot be overridden. EM + CISO sign-off to modify.
- **[L2]** — Work-type gate. Applies to ALL API Change items. EM can grant one-sprint exemption with written justification.
- **[L3]** — Team-specific gate. Based on tech stack. Tech Lead approval. Reviewed quarterly.
- **[L4]** — Story-specific gate. Added by PO/TL during grooming. Must not contradict L1-L3.

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR review tab shows ≥2 approvals, with at least 1 from engineer with "Senior" or "Tech Lead" role.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.1-SEC] PR touching security-critical code has approval from Security Champion in addition to standard approvals.
**Verification:** GitHub PR shows approval from user tagged as Security Champion if PR touches auth, payment, PII, or external integrations.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L1] [ENG-4.2] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit list shows "Verified" badge on every commit in PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions check "commitlint" passes in CI workflow.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2] PR merged using squash merge (no merge commits on main).
**Verification:** GitHub PR merge button set to "Squash and merge". Branch protection rules enforce this.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3] SonarQube quality gate passes with cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube status check in GitHub Actions shows "Passed" with 0 complexity violations.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3] No method exceeds 50 lines of code (SonarQube check).
**Verification:** SonarQube status check in GitHub Actions shows 0 "Method too long" issues.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.3] No dead code (unreachable, commented-out) present in changed files.
**Verification:** SonarQube analysis shows 0 "Dead code" or "Commented-out code" issues in PR diff.  
**Exception:** Tech Lead approval. Reviewed quarterly.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1] JaCoCo reports 80%+ line coverage on all changed modules in CI.
**Verification:** GitHub Actions job "test-coverage" shows JaCoCo line coverage ≥80% for changed Java classes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1] JaCoCo reports 75%+ branch coverage on all changed modules in CI.
**Verification:** GitHub Actions job "test-coverage" shows JaCoCo branch coverage ≥75% for changed Java classes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1] No existing covered code has lost coverage (CI fails on coverage regression).
**Verification:** GitHub Actions job "test-coverage" compares coverage against main branch and fails if any previously covered line becomes uncovered.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-API] Unit tests present for API endpoint logic (JUnit 5).
**Verification:** Test files in `src/test/java/` include `@Test` methods covering new/changed endpoint methods. Maven test output shows tests executed.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [QA-2.2-API] Integration tests present for API endpoint (JUnit 5).
**Verification:** Test files in `src/test/java/` include `@SpringBootTest` annotated tests calling endpoint via MockMvc or RestTemplate. Maven test output shows integration tests executed.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [From INC-002] API contract test includes all nullable fields documented in OpenAPI spec (JUnit 5).
**Verification:** Contract test in `src/test/java/` explicitly sends null values for each nullable field listed in `api/openapi.yaml` and asserts 2xx response.  
**Exception:** EM can grant one-sprint exemption with written justification.  
**Note:** This criterion was added due to escaped defect INC-002 (Order API 500 error on null payment method field).

### [ ] [L2] [QA-2.4] k6 load test present for API endpoints expected to handle > 1000 RPS.
**Verification:** k6 script in `tests/performance/` targets endpoint with 1000+ virtual users. Test exists in PR if endpoint expected to handle high traffic.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [QA-2.4] k6 test confirms P95 response time < 500ms under normal load.
**Verification:** k6 test output shows `http_req_duration` P95 metric < 500ms when run against staging environment.  
**Exception:** EM can grant one-sprint exemption with written justification.
