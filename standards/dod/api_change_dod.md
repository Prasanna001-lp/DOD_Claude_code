## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub branch protection rules enforce 2 required reviews. GitHub PR shows at least 1 approval from user with "Senior Engineer" or "Tech Lead" role.  
**Exception:** No exceptions.

### [ ] [L2] [ENG-4.1-SEC] PRs modifying authentication, authorization, payment, or PII handling paths include Security Champion approval.
**Verification:** GitHub PR includes approval from user with "Security Champion" designation. Code paths identified via CODEOWNERS file entries for security-critical directories.  
**Exception:** EM can grant one-sprint exemption with written justification if Security Champion unavailable and risk assessment completed.

### [ ] [L1] [ENG-4.2a] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub commit list shows "Verified" badge on all commits. GitHub Actions workflow checks commit signature status.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2b] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions workflow runs commitlint check and passes. Example types: feat, fix, chore, docs, style, refactor, test.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2c] PR merged via squash merge (no merge commits on main).
**Verification:** GitHub branch protection rules enforce squash merge only. Git history on main shows linear commit graph.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3a] SonarQube quality gate passes with cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube dashboard shows Quality Gate status = PASSED. No methods with complexity > 10 in changed files.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3b] No method exceeds 50 lines of code (verified by SonarQube).
**Verification:** SonarQube code smells report shows 0 violations for "Methods should not be too long" rule.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3c] No dead code present (unreachable code, commented-out code removed).
**Verification:** SonarQube dashboard shows 0 "Dead Store" and 0 "Commented Out Code" issues in changed files.  
**Exception:** No exceptions.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1a] JaCoCo reports ≥80% line coverage on all changed modules.
**Verification:** GitHub Actions JaCoCo report shows line coverage >= 80% for all modified packages. CI check passes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1b] JaCoCo reports ≥75% branch coverage on all changed modules.
**Verification:** GitHub Actions JaCoCo report shows branch coverage >= 75% for all modified packages. CI check passes.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1c] CI build verifies no existing covered code has lost coverage (coverage delta ≥ 0).
**Verification:** GitHub Actions coverage report shows coverage change = 0% or positive for all previously covered files.  
**Exception:** No exceptions.

### [ ] [L2] [QA-2.2-API] Unit tests present for all API endpoint logic.
**Verification:** JUnit 5 test suite includes unit tests for all controller methods handling changed endpoints. Tests mock dependencies and verify business logic.  
**Exception:** Tech Lead approval. Reviewed quarterly.

### [ ] [L2] [QA-2.2-API] Integration tests present covering full request/response cycle for changed endpoints.
**Verification:** JUnit 5 integration test suite includes tests that start Spring Boot context, send HTTP requests to changed endpoints, and verify responses including status codes, headers, and body structure.  
**Exception:** Tech Lead approval. Reviewed quarterly.

### [ ] [L2] [From INC-002] API contract tests include validation for all nullable fields documented in OpenAPI spec.
**Verification:** JUnit 5 contract test suite includes explicit tests with null values for all nullable fields in OpenAPI spec. Tests verify API handles null correctly without 500 errors. All tests pass in CI.  
**Exception:** No exceptions.  
**Note:** Motivated by escaped defect INC-002 (P2 severity) - API 500 error on null field.

### [ ] [L2] [QA-2.4] k6 load test verifies P95 <500ms and P99 <2000ms for endpoints expected to handle >1000 RPS.
**Verification:** k6 test results show p95 < 500ms and p99 < 2000ms under simulated 1000+ RPS load. Test script present in tests/performance/ directory.  
**Exception:** Tech Lead approval if endpoint RPS expected <1000. Document exemption reasoning in PR.

### [ ] [L3] [TEAM-KAFKA] Kafka consumer/producer integration tests present if API change involves event publishing or consumption.
**Verification:** JUnit 5 integration tests with embedded Kafka verify event schema, serialization, and message delivery for changed API endpoints that interact with Kafka.  
**Exception:** Tech Lead approval. Reviewed quarterly.

## Security

### [ ] [L1] [SEC-3.1] Snyk scan shows 0 Critical or High severity findings. Medium findings have tracked Jira tickets.
**Verification:** GitHub Actions Snyk check passes. Snyk dashboard shows 0 Critical/High issues. PR description lists Jira tickets for any Medium findings.  
**Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver.

### [ ] [L1] [SEC-3.2] Gitleaks scan passes with 0 secrets detected.
**Verification:** GitHub Actions Gitleaks check status = passed. No secrets detected in commit history or PR diff.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3] mvn dependency:check and npm audit produce 0 Critical CVE findings. All dependencies in approved registry.
**Verification:** CI runs mvn dependency:check showing 0 Critical CVEs. CI runs npm audit showing 0 Critical vulnerabilities. Dependencies match approved-dependencies.yaml.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-4.2] No secrets in version control (Gitleaks passes). All secrets in AWS Secrets Manager or GitHub Actions secrets.
**Verification:** Gitleaks scan passes. Code review confirms secrets referenced via environment variables sourced from AWS Secrets Manager or GitHub Actions secrets.  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-SPRING-SEC] Spring Security configuration reviewed for changed endpoints (authentication, authorization, CORS).
**Verification:** Code review confirms Spring Security annotations (@PreAuthorize, @Secured) present on controller methods. SecurityConfig.java updated if authorization rules changed. CORS configuration reviewed if cross-origin access required.  
**Exception:** Tech Lead approval. Reviewed quarterly.

## Documentation

### [ ] [L2] [ENG-6.1a] OpenAPI specification file (api/openapi.yaml) updated to reflect all endpoint changes.
**Verification:** Git diff shows changes in api/openapi.yaml matching PR code changes. OpenAPI validator passes (run via swagger-cli validate).  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [ENG-6.1b] CHANGELOG.md updated with entry under [Unreleased] section describing API change.
**Verification:** Git diff shows new entry in CHANGELOG.md under ## [Unreleased] heading. Entry includes: endpoint path, HTTP method, change type (added/changed/deprecated/removed), breaking change flag if applicable.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L2] [ENG-6.1c] API diff generated and attached to PR showing before/after comparison.
**Verification:** PR description or comment includes OpenAPI diff output (generated via openapi-diff or oasdiff tool). Diff highlights added/changed/removed endpoints, parameters, and response schemas.  
**Exception:** EM can grant one-sprint exemption with written justification.

### [ ] [L3] [TEAM-POSTMAN] Postman collection updated with example requests for new/changed endpoints.
**Verification:** Git diff shows updates to postman/commerce-platform.postman_collection.json. Collection includes example requests with sample payloads for changed endpoints.  
**Exception:** Tech Lead approval. Reviewed quarterly.

## Acceptance & Sign-off

### [ ] [L3] [TEAM-API-REVIEW] API change reviewed by at least one backend engineer not on the feature team.
**Verification:** GitHub PR shows approval from engineer outside immediate feature team. Review comment confirms API design, naming conventions, versioning strategy, and backward compatibility reviewed.  
**Exception:** Tech Lead approval. Reviewed quarterly.

### [ ] [L3] [TEAM-CONSUMER] Breaking changes communicated to known API consumers with migration timeline (if applicable).
**Verification:** Slack message sent to #api-consumers channel documenting breaking change. Email sent to registered consumer teams. Migration guide included in PR or linked documentation.  
**Exception:** Not required for non-breaking changes. Tech Lead approval. Reviewed quarterly.
