## 📋 Overview

This Definition of Done applies to all **infrastructure** work items including:
- Terraform infrastructure-as-code changes
- AWS resource provisioning and configuration
- Kubernetes cluster configuration
- Database infrastructure changes (PostgreSQL, RDS)
- Message queue infrastructure (Kafka)
- Network and security group configuration
- Monitoring and observability infrastructure

Every infrastructure change must satisfy **all applicable criteria** below before merge to main.

## 🔧 Code Quality & Review

### [ ] CODE-01 [L1] [ENG-4.1]
**PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.**

- **Verification:** GitHub PR shows ≥2 approvals with at least 1 from senior engineer (visible in PR reviewers list).
- **Exception:** No exceptions.

---

### [ ] CODE-02 [L1] [ENG-4.2-SIGN]
**All commits in PR are signed with GPG or SSH key registered in GitHub.**

- **Verification:** GitHub displays "Verified" badge on all commits in PR.
- **Exception:** No exceptions.

---

### [ ] CODE-03 [L1] [ENG-4.2-CONV]
**All commit messages follow Conventional Commits format: type(scope): description.**

- **Verification:** commitlint GitHub Action passes in CI workflow.
- **Exception:** No exceptions.

---

### [ ] CODE-04 [L2] [SEC-4.1-TERRAFORM]
**terraform plan output attached to PR shows no unintended resource deletions.**

- **Verification:** `terraform plan` command output posted as PR comment or attached as artifact; reviewer confirms no unexpected resource destruction.
- **Exception:** No exceptions. Any resource deletion must be explicitly documented in PR description with business justification.

---

### [ ] CODE-05 [L2] [SEC-4.1-TERRAFORM]
**Platform Engineering team approval obtained.**

- **Verification:** Platform Engineering team member tagged in PR and has approved (visible in GitHub PR reviewers section).
- **Exception:** No exceptions.

---

### [ ] CODE-06 [L2] [ENG-6.2-ADR]
**ADR created in docs/adr/ if change affects system architecture, data model, or cross-service contracts.**

- **Verification:** ADR file present in `docs/adr/` directory with status "Accepted" and linked in PR description.
- **Exception:** No exceptions for architectural changes. Skip if change is purely operational (e.g., resource scaling without design change).

---

### [ ] CODE-07 [L2] [ENG-6.2-ADR]
**Architecture Guild approval obtained if ADR was required.**

- **Verification:** Architecture Guild member approval documented in PR comments or Slack thread link provided in PR.
- **Exception:** Skip if no ADR was required per CODE-06.

## 🔒 Security & Compliance

### [ ] SEC-01 [L1] [SEC-3.1-SNYK]
**Snyk scan reports 0 Critical or High severity findings.**

- **Verification:** Snyk CI check passes in GitHub Actions workflow with status "passed".
- **Exception:** No exceptions. Critical/High findings must be fixed before merge.

---

### [ ] SEC-02 [L1] [SEC-3.1-SNYK]
**All Medium severity findings from Snyk have corresponding Jira tickets linked in PR.**

- **Verification:** PR description includes Jira ticket links for each Medium finding reported by Snyk.
- **Exception:** No exceptions. All Medium findings must be tracked.

---

### [ ] SEC-03 [L1] [SEC-3.2-SECRETS]
**Gitleaks scan passes in CI with 0 secrets detected.**

- **Verification:** Gitleaks GitHub Actions check shows status "passed" with zero secrets found.
- **Exception:** No exceptions.

---

### [ ] SEC-04 [L1] [SEC-4.2-SECRETS-MGMT]
**All secrets stored in AWS Secrets Manager or GitHub Actions secrets. Verified by Gitleaks scan.**

- **Verification:** Gitleaks passes (SEC-03) and manual code review confirms no hardcoded credentials in .tf files or scripts.
- **Exception:** No exceptions.

---

### [ ] SEC-05 [L1] [SEC-3.3-DEPS-APPROVAL]
**All new dependencies listed in approved dependency registry. CI checks compliance.**

- **Verification:** Custom GitHub Action (dependency-check) passes, confirming all Terraform modules and providers are in approved registry.
- **Exception:** No exceptions. New dependencies require Security Champion approval before adding to registry.

---

### [ ] SEC-06 [L2] [SEC-4.1-TERRAFORM]
**tfsec scan passes with 0 HIGH or CRITICAL findings.**

- **Verification:** tfsec GitHub Actions check shows status "passed" with no HIGH or CRITICAL severity issues.
- **Exception:** No exceptions. HIGH/CRITICAL findings must be fixed or have CISO-signed risk acceptance.

## 🧪 Testing & Validation

### [ ] TEST-01 [L2] [QA-3.1-RELEASE]
**Infrastructure change validated in staging or non-production environment before production deployment.**

- **Verification:** Terraform apply executed successfully in staging environment; `terraform plan` output from staging attached to PR.
- **Exception:** No exceptions for production-impacting changes. Skip only for dev/sandbox environment changes.

---

### [ ] TEST-02 [L3] [TEAM-KAFKA]
**Kafka topic configurations validated: partition count, replication factor, and retention policies align with capacity planning.**

- **Verification:** `kafka-topics.sh --describe` output attached to PR showing topic configuration; Platform team confirms alignment with standards.
- **Exception:** Skip if change does not affect Kafka infrastructure.

---

### [ ] TEST-03 [L3] [TEAM-POSTGRES]
**PostgreSQL schema changes tested with realistic data volume (minimum 10K rows for affected tables).**

- **Verification:** Migration script execution logs attached showing successful run against staging database with realistic data.
- **Exception:** Skip if change does not affect PostgreSQL schema.

## 📚 Documentation & Runbooks

### [ ] DOC-01 [L2] [QA-3.1-RELEASE]
**Runbook updated in Confluence if operational procedures changed.**

- **Verification:** Confluence runbook page shows "Last modified" date matching or after PR creation date; link to updated runbook provided in PR.
- **Exception:** Skip if change does not affect operational procedures (e.g., resource tag updates).

---

### [ ] DOC-02 [L2] [QA-3.1-RELEASE]
**Rollback plan documented in runbook and tested successfully in staging.**

- **Verification:** Rollback procedure documented in Confluence runbook with test execution evidence (screenshots or logs) from staging environment.
- **Exception:** No exceptions for production-impacting changes. Skip for dev/sandbox only changes.

---

### [ ] DOC-03 [L3] [TEAM-COMMERCE]
**README.md in infrastructure repository updated to reflect new resources, modules, or configuration changes.**

- **Verification:** README.md file modified in PR with updated architecture diagram or resource inventory if applicable.
- **Exception:** Skip if change is purely operational with no new resources added.

---

### [ ] DOC-04 [L2] [ENG-6.2-ADR]
**Terraform module documentation updated if public module interface changed.**

- **Verification:** Module README.md shows updated input/output variable documentation; terraform-docs output matches actual module code.
- **Exception:** Skip if no modules were modified.

## 🛡️ Disaster Recovery & Resilience

### [ ] DR-01 [L3] [TEAM-DR]
**Disaster recovery impact assessed: change does not degrade RTO or RPO targets.**

- **Verification:** DR impact analysis documented in PR description or linked Confluence page; Platform Engineering confirms no DR degradation.
- **Exception:** Skip for non-production environments. Required for all production infrastructure changes.

### [ ] DR-02 [L3] [TEAM-DR]
**Backup and restore procedures tested if change affects data storage resources.**

- **Verification:** Backup/restore test execution logs attached; successful restore from backup confirmed in staging.
- **Exception:** Skip if change does not affect databases, object storage, or persistent volumes.
