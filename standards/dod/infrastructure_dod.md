## Overview

This Definition of Done applies to all infrastructure work items including:
- Terraform configuration changes
- AWS resource provisioning
- Network and security group modifications
- Container orchestration updates
- CI/CD pipeline infrastructure
- Monitoring and observability infrastructure

Every infrastructure story must satisfy ALL applicable criteria before being marked as Done.

## Code Quality

### CODE-01 [L1] [ENG-4.1]
**[ ] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.**

**Verification:** GitHub PR approval count shows ≥2 approvals with at least 1 from senior engineer role.

**Exception:** No exceptions.

---

### CODE-02 [L1] [ENG-4.2]
**[ ] All commits in PR are signed with GPG or SSH key registered in GitHub.**

**Verification:** GitHub shows verified badge on all commits in PR.

**Exception:** No exceptions.

---

### CODE-03 [L1] [ENG-4.2]
**[ ] All commit messages follow Conventional Commits format: type(scope): description.**

**Verification:** GitHub Actions commit-lint check passes in CI.

**Exception:** No exceptions.

---

### CODE-04 [L2] [ENG-6.2]
**[ ] Architecture Decision Record (ADR) created in docs/adr/ for architecture/data model/contract changes.**

**Verification:** New ADR file present in docs/adr/ with date prefix and numbered sequence.

**Exception:** Not required for trivial config changes (firewall rule addition). EM discretion.

---

### CODE-05 [L2] [ENG-6.2]
**[ ] Architecture Guild review completed and approval documented in PR.**

**Verification:** GitHub PR comment from Architecture Guild member with explicit approval statement.

**Exception:** Can be async within 2 business days if Guild unavailable. Documented in PR.

## Test Coverage & Quality

### TEST-01 [L2] [SEC-4.1]
**[ ] terraform plan produces clean output with no unintended resource deletions.**

**Verification:** terraform plan output attached to PR shows 0 resources to destroy or explicit justification for deletions.

**Exception:** Intended deletions must have EM sign-off comment in PR.

**Verification:** GitHub Actions workflow step "terraform validate" passes with exit code 0.

### TEST-03 [L3] [TEAM-INFRA-02]

**Verification:** DR runbook steps executed in staging with screenshots or logs attached to PR.

**[ ] Infrastructure smoke test passes post-apply in staging.**

**Verification:** Automated smoke test script in ci/infra-smoke-test.sh exits with code 0.

## Security

### SEC-01 [L1] [SEC-3.1]
**[ ] Snyk scan shows 0 Critical or High severity findings.**

**Verification:** Snyk CI check in GitHub Actions passes with status "No vulnerabilities found" or "All issues resolved".

**Exception:** No exceptions.

---

### SEC-02 [L1] [SEC-3.1]
**[ ] Snyk Medium severity findings have tracked Jira tickets before merge.**

**Verification:** Snyk report shows 0 Medium findings OR each Medium finding has Jira ticket ID in PR description.

**Exception:** No exceptions.

---

### SEC-03 [L1] [SEC-3.2 / SEC-4.2]
**[ ] Gitleaks scan passes with 0 secrets detected in CI.**

**Verification:** GitHub Actions gitleaks check passes with exit code 0.

**Exception:** No exceptions.

---

### SEC-04 [L1] [SEC-3.3]
**[ ] npm audit (Node.js) or mvn dependency:check (Java) reports 0 Critical CVE findings in CI.**

**Verification:** GitHub Actions dependency check step passes showing 0 Critical vulnerabilities.

**Exception:** No exceptions.

---

### SEC-05 [L2] [SEC-4.1]
**[ ] Platform Engineering team review completed and documented in PR.**

**Verification:** GitHub PR has approval from member of @acme-engineering/platform-team with review comment.

**Exception:** No exceptions.

---

### SEC-06 [L2] [SEC-4.1]
**[ ] tfsec scan passes with 0 HIGH or CRITICAL findings.**

**Verification:** GitHub Actions tfsec check passes or tfsec report shows only LOW/MEDIUM with Jira tickets.

**Exception:** MEDIUM findings permitted with tracked tickets. HIGH/CRITICAL blocked.

---

### SEC-07 [L2] [SEC-4.2]
**[ ] All new secrets stored in AWS Secrets Manager or GitHub Actions secrets.**

**Verification:** No hardcoded credentials in .tf files. New secrets referenced via data.aws_secretsmanager_secret or GitHub Actions secrets syntax.

**Exception:** No exceptions.

---

### SEC-08 [L3] [TEAM-INFRA-04]
**[ ] Network security group rules reviewed for least-privilege access.**

**Verification:** PR description includes security group rule justification for any 0.0.0.0/0 ingress rules.

**Exception:** Load balancers and CDN-facing resources may use 0.0.0.0/0 with Tech Lead approval.

**Exception:** No exceptions.

## CI / Deployment Gate

### CI-01 [L1] [CI-GATE-01]
**[ ] All GitHub Actions checks pass (lint, validate, security scan, plan).**

**Verification:** GitHub PR checks tab shows all required checks green.

**Exception:** No exceptions.

---

### CI-02 [L3] [TEAM-INFRA-09]
**[ ] Terraform state lock released if apply failed.**

**Verification:** No active state locks in DynamoDB state lock table or documented resolution in PR.

**Exception:** No exceptions.

---

### CI-03 [L3] [TEAM-INFRA-10]
**[ ] Rollback plan documented in PR description.**

**Verification:** PR description includes "Rollback Plan" section with step-by-step revert instructions.

**Exception:** Not required for additions-only changes (new resources, no modifications). Tech Lead approval.

## Acceptance & Sign-off

### ACC-01 [L2] [TEAM-INFRA-11]
**[ ] Platform Engineering Lead sign-off obtained for production changes.**

**Verification:** GitHub PR has explicit approval comment from Platform Engineering Lead (@platform-lead) for prod environment changes.

**Exception:** Not required for dev/staging environments. Production only.

---

### ACC-02 [L3] [TEAM-INFRA-12]
**[ ] Change implemented during approved maintenance window.**

**Verification:** PR merge timestamp falls within scheduled maintenance window or emergency change ticket attached.

**Exception:** Non-disruptive changes (tags, monitoring, new resources) exempt. Disruptive changes require window.
