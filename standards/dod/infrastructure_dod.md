## Code Quality & Review

### CODE-01 [L1] [ENG-4.1]
**Criterion:**  
☐ PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.

**Verification:**  
GitHub PR shows 2+ approvals with at least 1 from senior engineer (visible in PR approval section).

**Exception:**  
No exceptions.

---

### CODE-02 [L2] [ENG-4.1-SEC]
**Criterion:**  
☐ Security-critical PRs have approval from Security Champion documented in PR comments.

**Verification:**  
Security Champion GitHub username visible in PR approvals or explicit approval comment present.

**Exception:**  
EM can grant one-sprint exemption with written justification if Security Champion unavailable.

---

### CODE-03 [L1] [ENG-4.2-SIGNING]
**Criterion:**  
☐ All commits are signed with GPG or SSH key registered in GitHub.

**Verification:**  
All commits in PR display "Verified" badge in GitHub commit history.

**Exception:**  
No exceptions.

---

### CODE-04 [L1] [ENG-4.2-FORMAT]
**Criterion:**  
☐ All commit messages follow Conventional Commits format: type(scope): description.

**Verification:**  
commitlint check passes in GitHub Actions CI workflow; manual review confirms all commits match pattern.

**Exception:**  
No exceptions.

---

### CODE-05 [L2] [SEC-4.1-IAC]
**Criterion:**  
☐ Platform Engineering team approval documented in PR.

**Verification:**  
GitHub PR shows approval from member of @platform-engineering team.

**Exception:**  
EM can grant one-sprint exemption with written justification for emergency hotfixes.

## Infrastructure as Code

### IAC-01 [L2] [SEC-4.1-IAC]
**Criterion:**  
☐ Terraform plan executed and shows no unintended resource deletions.

**Verification:**  
terraform plan output attached to PR; manual review confirms no unexpected resource deletions or modifications.

**Exception:**  
Intentional deletions must be explicitly documented in PR description with justification.

---

### IAC-02 [L2] [SEC-4.1-IAC]
**Criterion:**  
☐ tfsec scan passes with 0 HIGH or CRITICAL findings in CI.

**Verification:**  
tfsec check passes in GitHub Actions workflow; scan output shows 0 HIGH/CRITICAL severity issues.

**Exception:**  
No exceptions. Findings must be fixed or have documented CISO risk acceptance.

---

### IAC-03 [L3] [TEAM-INFRA-01]
**Criterion:**  
☐ All Terraform changes include state backend configuration pointing to Commerce Platform S3 bucket.

**Verification:**  
Terraform backend configuration in code references s3://acme-terraform-state-commerce-platform bucket.

**Exception:**  
No exceptions. Reviewed quarterly by Tech Lead.

---

### IAC-04 [L3] [TEAM-INFRA-02]
**Criterion:**  
☐ Infrastructure changes affecting PostgreSQL or Kafka include migration plan and rollback procedure.

**Verification:**  
PR description includes migration steps and rollback plan; reviewed by Platform Engineering during approval.

**Exception:**  
Not applicable if change does not touch database or message broker infrastructure.

## Security & Secrets

### SEC-01 [L1] [SEC-3.1-SAST]
**Criterion:**  
☐ Snyk scan shows 0 Critical or High severity findings.

**Verification:**  
Snyk security check passes in GitHub Actions CI workflow; Snyk dashboard shows 0 Critical/High issues for this PR.

**Exception:**  
No exceptions.

---

### SEC-02 [L1] [SEC-3.1-SAST]
**Criterion:**  
☐ All Medium severity Snyk findings have tracked Jira tickets attached to PR.

**Verification:**  
PR description contains Jira ticket links for each Medium severity finding reported by Snyk.

**Exception:**  
No exceptions. Medium findings may be merged with tracked tickets; Critical/High must be fixed.

---

### SEC-03 [L1] [SEC-3.2-SECRETS]
**Criterion:**  
☐ Gitleaks scan passes with 0 secrets detected in CI.

**Verification:**  
Gitleaks check passes in GitHub Actions workflow; no secrets detected in commit history.

**Exception:**  
No exceptions.

---

### SEC-04 [L2] [SEC-4.2-SECRETS]
**Criterion:**  
☐ All secrets stored in AWS Secrets Manager or GitHub Actions secrets; documented in PR if new secrets added.

**Verification:**  
PR description documents any new secrets added and confirms storage location (AWS Secrets Manager or GitHub Actions secrets).

**Exception:**  
EM can grant one-sprint exemption for non-production environments with written justification.

---

### SEC-05 [L1] [SEC-3.3-DEPS]
**Criterion:**  
☐ npm audit (for React) or mvn dependency:check (for Java) produces 0 Critical CVE findings in CI.

**Verification:**  
Dependency check passes in GitHub Actions CI; npm audit or mvn dependency:check reports 0 Critical vulnerabilities.

**Exception:**  
No exceptions. Critical CVEs must be fixed or dependencies removed within 5 business days.

---

### SEC-06 [L2] [SEC-3.3-DEPS]
**Criterion:**  
☐ All dependencies listed in approved dependency registry.

**Verification:**  
PR checklist confirms all new dependencies are in approved registry; manual review by senior engineer during approval.

**Exception:**  
EM can grant one-sprint exemption for new dependencies pending security review.

## Test Coverage & Quality

### TEST-01 [L3] [TEAM-INFRA-03]
**Criterion:**  
☐ Infrastructure validation tests present and passing in CI.

**Verification:**  
terraform validate passes; custom validation scripts (if present in tests/ directory) execute successfully in GitHub Actions.

**Exception:**  
Not applicable if infrastructure change is configuration-only with no testable logic.

---

### TEST-02 [L3] [TEAM-INFRA-04]
**Criterion:**  
☐ Disaster recovery procedure verified in staging environment before production deployment.

**Verification:**  
Runbook includes DR verification steps; PR description documents staging DR test results with timestamp.

**Exception:**  
Not applicable for non-critical infrastructure changes (e.g., monitoring dashboards, documentation).

## Documentation & Runbooks

### DOC-01 [L2] [ENG-6.2-ADR]
**Criterion:**  
☐ Architecture Decision Record (ADR) created in docs/adr/ for structural changes.

**Verification:**  
New ADR file present in docs/adr/ directory with sequential number; follows ADR template; reviewed by Architecture Guild.

**Exception:**  
Not applicable if change does not alter system architecture, data model, or cross-service contracts.

---

### DOC-02 [L2] [ENG-6.2-ADR]
**Criterion:**  
☐ Architecture Guild approval documented in PR before merge.

**Verification:**  
GitHub PR shows approval from member of @architecture-guild team; or explicit approval comment from Architecture Guild member.

**Exception:**  
EM can grant one-sprint exemption if change is time-sensitive and does not affect critical paths.

---

### DOC-03 [L3] [TEAM-INFRA-05]
**Criterion:**  
☐ Runbook updated with operational procedures if deployment or monitoring workflows changed.

**Verification:**  
Runbook in docs/runbooks/ directory updated; changes highlighted in PR description; Platform Engineering approval confirms completeness.

**Exception:**  
Not applicable if operational procedures unchanged.

---

### DOC-04 [L3] [TEAM-INFRA-06]
**Criterion:**  
☐ Infrastructure diagram updated if topology or network boundaries changed.

**Verification:**  
Infrastructure diagram in docs/diagrams/ updated; diff visible in PR; Mermaid or PlantUML source committed.

**Exception:**  
Not applicable if no topology changes (e.g., configuration updates, version bumps).

**Criterion:**  
☐ All GitHub Actions checks pass (lint, build, security scan, IaC validation).

**Verification:**  
GitHub PR checks section shows all required workflows green; no failing checks present.

**Exception:**  
No exceptions.

---

### CI-02 [L2] [TEAM-INFRA-07]
**Criterion:**  
☐ Deployment plan includes blue-green or canary strategy for production changes affecting live traffic.

**Verification:**  
Deployment script or GitHub Actions workflow includes blue-green or canary deployment logic; documented in PR description.

**Exception:**  
Not applicable for infrastructure changes that do not affect live traffic (e.g., monitoring, logging).
