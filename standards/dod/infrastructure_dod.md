## Purpose

This Definition of Done applies to **infrastructure** work items in Jira/ADO. Every criterion must be met before a pull request can be merged to `main` and deployed to production.

**Criterion Format:**
- **[L1]** = Universal gate (applies to ALL work types, no exceptions)
- **[L2]** = Work-type-specific gate (applies to all infrastructure items)
- **[L3]** = Team-specific gate (Commerce Platform tech stack and practices)
- **[L4]** = Story-specific gate (added by PO/Tech Lead during grooming)

## Code Quality & Review

### CODE-01 [L1] [ENG-4.1]
**[ ] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.**

- **Verification:** GitHub PR page shows 2+ approvals, at least 1 marked as senior engineer or tech lead in approval list.
- **Exception:** No exceptions.

---

### CODE-02 [L2] [SEC-4.1-TERRAFORM]
**[ ] Platform Engineering team approval documented in PR comments.**

- **Verification:** GitHub PR comments contain explicit approval from at least 1 member of Platform Engineering team.
- **Exception:** EM can grant one-sprint exemption for emergency hotfixes with written justification in PR.

---

### CODE-03 [L1] [ENG-4.2]
**[ ] All commits are signed with GPG or SSH key registered in GitHub.**

- **Verification:** GitHub commit history shows "Verified" badge on all commits in the PR.
- **Exception:** No exceptions.

---

### CODE-04 [L1] [ENG-4.2-CONV]
**[ ] All commit messages follow Conventional Commits format: type(scope): description.**

- **Verification:** GitHub Actions commitlint check passes. All commits match pattern: `feat|fix|chore|docs|refactor(scope): description`.
- **Exception:** No exceptions.

---

### CODE-05 [L1] [ENG-4.2-MERGE]
**[ ] Branch merged to main using squash merge (no merge commits).**

- **Verification:** GitHub branch protection rules enforce squash merge. Merge button shows "Squash and merge" as only option.
- **Exception:** No exceptions.

## Infrastructure-as-Code

### IFC-01 [L2] [SEC-4.1-TERRAFORM]
**[ ] terraform plan output attached to PR showing no unintended resource deletions.**

- **Verification:** PR description or comments contain `terraform plan` output. Output shows Plan summary with 0 resources to destroy, or all destroy operations are intentional and documented.
- **Exception:** EM can grant one-sprint exemption with written justification if plan contains intended deletions.

---

### IFC-02 [L2] [ENG-6.2-ADR]
**[ ] Architecture Decision Record (ADR) created in docs/adr/ for architectural changes.**

- **Verification:** New `.md` file exists in `docs/adr/` directory following ADR template. File is included in PR file changes.
- **Exception:** Tech Lead approval. Reviewed quarterly. Skip if change is operational-only with no architectural impact.

---

### IFC-03 [L2] [ENG-6.2-ADR]
**[ ] Architecture Guild review approval documented in PR comments.**

- **Verification:** GitHub PR comments contain explicit approval from at least 1 Architecture Guild member. Approval references ADR document number.
- **Exception:** Tech Lead approval. Skip if no ADR required (operational changes only).

---

### IFC-04 [L3] [TEAM-TECH-STACK]
**[ ] All infrastructure changes affect only PostgreSQL, Kafka, or supporting AWS services.**

- **Verification:** Terraform plan shows resource changes only for `aws_db_instance`, `aws_msk_cluster`, `aws_*`, or related networking/security resources. No changes to unsupported services.
- **Exception:** Tech Lead approval required for new service introductions. Must update approved tech stack list.

## Security

### SEC-01 [L1] [SEC-3.1-SNYK]
**[ ] Snyk scan shows 0 Critical or High severity findings in GitHub Actions CI.**

- **Verification:** GitHub Actions workflow "Security Scan" step shows Snyk check passed. Snyk dashboard shows 0 Critical/High vulnerabilities for this PR.
- **Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver documented in Jira.

---

### SEC-02 [L1] [SEC-3.1-SNYK]
**[ ] Medium severity findings from Snyk have tracked Jira tickets linked in PR description.**

- **Verification:** PR description contains "Related Issues: JIRA-XXX" for each Medium finding. Jira tickets exist and are in Backlog or higher priority.
- **Exception:** No exceptions. Medium findings must be acknowledged with tracking ticket.

---

### SEC-03 [L1] [SEC-3.2-SECRETS]
**[ ] Gitleaks scan passes in GitHub Actions CI with zero secrets detected.**

- **Verification:** GitHub Actions workflow "Secrets Scan" step shows Gitleaks check passed with exit code 0.
- **Exception:** No exceptions. Any detected secrets must be rotated immediately and removed from Git history.

---

### SEC-04 [L1] [SEC-3.3-DEPS]
**[ ] mvn dependency:check runs in GitHub Actions CI and reports zero Critical CVE findings.**

- **Verification:** GitHub Actions workflow "Dependency Check" step shows `mvn dependency:check` passed. Output contains "0 Critical vulnerabilities found".
- **Exception:** No exceptions. Critical CVEs must be patched or dependencies removed.

---

### SEC-05 [L1] [SEC-3.3-DEPS]
**[ ] All new third-party dependencies are listed in approved dependency registry.**

- **Verification:** PR description documents any new dependencies added to `pom.xml` or `package.json`. Dependencies match entries in `confluence.acme.com/approved-dependencies` or have approval comment from Security Champion.
- **Exception:** No exceptions. Unapproved dependencies must be removed or get Security Champion approval before merge.

---

### SEC-06 [L2] [SEC-4.1-TERRAFORM]
**[ ] tfsec scan passes in GitHub Actions CI with zero HIGH or CRITICAL findings.**

- **Verification:** GitHub Actions workflow "tfsec" step shows check passed. tfsec output shows 0 HIGH and 0 CRITICAL issues.
- **Exception:** EM can grant one-sprint exemption with written justification. Medium/Low findings acknowledged with tracked ticket.

---

### SEC-07 [L1] [SEC-4.2-SECRETS-MGMT]
**[ ] All secrets stored in AWS Secrets Manager or GitHub Actions secrets.**

- **Verification:** PR description documents location of any new secrets (AWS Secrets Manager ARN or GitHub Actions secret name). No hardcoded credentials in code verified by Gitleaks.
- **Exception:** No exceptions. All secrets must use centralized secret management.

## Testing & Validation

### TEST-01 [L3] [TEAM-INFRA-DR]
**[ ] Disaster recovery capability verified for data-layer changes.**

- **Verification:** If Terraform changes affect `aws_db_instance` or `aws_msk_cluster`, PR includes test execution log showing successful backup restore in staging environment. Document in PR comment with timestamp and environment.
- **Exception:** Tech Lead approval. Skip if changes are non-data-layer (networking, IAM, monitoring only).

---

### TEST-02 [L3] [TEAM-INFRA-MONITORING]
**[ ] Infrastructure monitoring alerts configured for new resources.**

- **Verification:** If new AWS resources added, PR includes CloudWatch alarms configuration or links to Datadog dashboard with alarms for resource health, capacity, and performance. Document in PR description.
- **Exception:** Tech Lead approval. Reviewed quarterly. Skip for temporary/test resources.

---

## CI / Deployment Gate

### CI-01 [L1] [TEAM-CI-GATE]
**[ ] All GitHub Actions checks pass (lint, security scan, tfsec, dependency check).**

- **Verification:** GitHub PR page shows green checkmarks for all required status checks. No red X or yellow pending states.
- **Exception:** No exceptions. All checks must pass before merge is enabled.

## Documentation

### DOC-01 [L2] [TEAM-INFRA-RUNBOOK]
**[ ] Runbook published in docs/runbooks/ for operational procedure changes.**

- **Verification:** If infrastructure change affects deployment, scaling, or incident response procedures, new or updated runbook `.md` file exists in `docs/runbooks/` directory. File is included in PR.
- **Exception:** EM can grant one-sprint exemption with written justification if no operational procedure change.

---

### DOC-02 [L3] [TEAM-INFRA-DIAGRAM]
**[ ] Architecture diagram updated in docs/architecture/ for structural changes.**

- **Verification:** If Terraform changes add/remove AWS services or modify network topology, updated `.png` or `.drawio` file in `docs/architecture/` shows new state. File is included in PR.
- **Exception:** Tech Lead approval. Reviewed quarterly. Skip if change is configuration-only with no structural impact.

## Acceptance & Sign-off

### ACC-01 [L2] [TEAM-INFRA-EM-SIGN-OFF]
**[ ] Engineering Manager sign-off documented for production infrastructure changes.**

- **Verification:** PR comment contains explicit "Approved for production deployment" statement from Engineering Manager if Terraform changes target production workspace/account.
- **Exception:** EM can grant one-sprint exemption for non-production environment changes. Staging/dev changes do not require EM sign-off.
