## Code Quality

**[ ] [L1] [ENG-4.1]** PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.  
**Verification:** GitHub PR page shows 2+ approvals with at least 1 from user with "Senior Engineer" or "Tech Lead" role.  
**Exception:** No exceptions.

**[ ] [L3] [ENG-4.1-SEC]** PR touching security-critical paths (IAM policies, security groups, KMS keys, secrets configuration) has additional approval from Security Champion.  
**Verification:** GitHub PR shows approval from user tagged as Security Champion when terraform files under modules/iam/, modules/security/, or modules/kms/ are modified.  
**Exception:** No exceptions for security-critical infrastructure changes.

**[ ] [L1] [ENG-4.2-SIGN]** All commits in PR are signed with GPG or SSH key registered in GitHub.  
**Verification:** GitHub PR shows "Verified" badge on all commits.  
**Exception:** No exceptions.

**[ ] [L1] [ENG-4.2-CONV]** All commit messages follow Conventional Commits format: type(scope): description.  
**Verification:** GitHub Actions commitlint check passes.  
**Exception:** No exceptions.

**[ ] [L1] [ENG-4.2-MERGE]** PR merge strategy set to "Squash and merge". Merge commits are not used on main branch.  
**Verification:** GitHub PR settings show "Squash and merge" selected before merge.  
**Exception:** No exceptions.

## Infrastructure as Code

**[ ] [L2] [SEC-4.1-TF-PLAN]** Terraform plan executed and reviewed. No unintended resource deletions present.  
**Verification:** GitHub Actions workflow shows terraform plan output attached to PR. PR description confirms plan review. Plan shows no DELETE operations for critical resources (databases, stateful services, data stores).  
**Exception:** No exceptions for infrastructure changes.

**[ ] [L2] [SEC-4.1-TF-PLAN]** Platform Engineering team approval recorded on PR.  
**Verification:** GitHub PR shows approval from user with "Platform Engineering" team membership.  
**Exception:** No exceptions for infrastructure changes.

**[ ] [L2] [SEC-4.1-TF-PLAN]** tfsec scan passed with zero HIGH or CRITICAL findings.  
**Verification:** GitHub Actions tfsec check passes showing 0 HIGH and 0 CRITICAL severity findings.  
**Exception:** No exceptions for infrastructure changes.

**[ ] [L2] [ENG-6.2-ARCH]** ADR created in docs/adr/ documenting architectural change, data model change, or cross-service contract change.  
**Verification:** Git diff shows new file matching pattern docs/adr/NNNN-description.md with completed ADR template.  
**Exception:** No exceptions for architectural infrastructure changes.

**[ ] [L2] [ENG-6.2-ARCH]** Architecture Guild review approval recorded on PR.  
**Verification:** GitHub PR shows approval from user with "Architecture Guild" team membership.  
**Exception:** No exceptions for architectural infrastructure changes.

**[ ] [L3] [TEAM-INFRA-DR]** Disaster recovery impact assessed. Changes to stateful resources (RDS, S3, EBS) include backup verification.  
**Verification:** PR description contains DR impact section. For stateful resources, terraform code includes backup configuration and retention policy. GitHub Actions shows backup test execution in staging.  
**Exception:** Tech Lead approval required with written justification for non-critical dev/test resources.

## Security

**[ ] [L1] [SEC-3.1-SNYK]** Snyk scan shows 0 Critical or High severity findings. Medium findings acknowledged with tracked Jira ticket.  
**Verification:** GitHub Actions Snyk check passes. Medium findings have Jira ticket links in PR description following format "JIRA-NNN".  
**Exception:** No exceptions.

**[ ] [L1] [SEC-3.2-SECRETS]** Gitleaks scan in CI pipeline passed with zero secrets detected. All secrets stored in AWS Secrets Manager or GitHub Actions secrets.  
**Verification:** GitHub Actions Gitleaks check passes. PR description confirms secret storage location when new secrets required (format: "Secrets stored in: AWS Secrets Manager / path/to/secret").  
**Exception:** No exceptions.

**[ ] [L1] [SEC-3.3-DEPS]** Terraform provider dependency check ran in CI with zero Critical CVE findings.  
**Verification:** GitHub Actions terraform-compliance check passes showing 0 Critical CVEs in provider versions.  
**Exception:** No exceptions.

## Documentation

**[ ] [L2] [QA-3.1-RUNBOOK]** Runbook updated if operational procedures changed. Update confirmed by PR commit.  
**Verification:** Git diff shows docs/runbooks/*.md modified when infrastructure changes affect operational procedures (new services, changed ports, modified access patterns, updated monitoring). PR description confirms runbook review.  
**Exception:** No exceptions when operational procedures change.

**[ ] [L3] [TEAM-INFRA-README]** Terraform module README.md updated with input variables, outputs, and usage examples.  
**Verification:** Git diff shows terraform/modules/*/README.md updated when module variables or outputs change. README includes: required variables table, optional variables table, outputs table, usage example code block.  
**Exception:** Tech Lead approval for cosmetic-only changes not affecting module interface.

**[ ] [L3] [TEAM-INFRA-DIAGRAM]** Architecture diagram updated in docs/architecture/ when infrastructure topology changes.  
**Verification:** Git diff shows docs/architecture/*.png or docs/architecture/*.drawio modified when new services added, network topology changed, or service relationships modified.  
**Exception:** Tech Lead approval for internal implementation changes not affecting service boundaries.

## CI / Deployment Gate

**[ ] [L1] [CI-GATE]** All GitHub Actions checks green (terraform validate, terraform fmt, tfsec, Snyk, Gitleaks, commitlint).  
**Verification:** GitHub PR page shows all required status checks passed.  
**Exception:** No exceptions.

**[ ] [L2] [TEAM-INFRA-APPLY]** Terraform apply executed successfully in staging environment before production deployment.  
**Verification:** GitHub Actions workflow "terraform-apply-staging" completed successfully. PR description links to staging apply run.  
**Exception:** EM approval for emergency hotfix with documented rollback plan.

## Acceptance & Sign-off

**[ ] [L2] [TEAM-INFRA-VALIDATION]** Infrastructure changes validated in staging. Validation test results attached to PR.  
**Verification:** PR description contains validation test results section. For compute changes: service health check passes. For network changes: connectivity test passes. For data changes: data integrity test passes.  
**Exception:** EM approval for infrastructure changes that cannot be validated in staging (production-only resources).

**[ ] [L3] [TEAM-INFRA-MONITORING]** Monitoring and alerting configured for new infrastructure resources.  
**Verification:** Terraform code includes CloudWatch alarms, metrics, and dashboards for new resources. PR description confirms alert routing to on-call channel.  
**Exception:** Tech Lead approval for non-critical dev/test resources.
