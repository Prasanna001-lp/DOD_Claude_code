## Overview

This Definition of Done applies to all work items tagged as **Infrastructure** in the Commerce Platform team backlog. Infrastructure work includes:
- Terraform / IaC changes
- Cloud resource provisioning (AWS)
- Network configuration
- CI/CD pipeline infrastructure
- Monitoring and observability setup
- Disaster recovery implementation

Every criterion below must be met before an infrastructure work item can be considered "Done" and merged to main.

## Code Quality & Review

**[ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.**
- **Verification:** GitHub PR approvals section shows ≥2 approvals. At least 1 approver has "Senior Engineer" or "Tech Lead" GitHub role or team membership.
- **Exception:** No exceptions.

**[ ] [L2] [ENG-6.2a] ADR created in docs/adr/ documenting infrastructure change with context, decision, and consequences.**
- **Verification:** Git diff shows new file docs/adr/NNNN-{title}.md following ADR template. File contains Context, Decision, Consequences, and Status sections.
- **Exception:** EM can grant one-sprint exemption for minor configuration-only changes with written justification.

**[ ] [L2] [ENG-6.2b] PR approved by at least one Architecture Guild member.**
- **Verification:** GitHub PR shows approval from user listed in .github/CODEOWNERS under Architecture Guild designation or docs/adr/ path ownership.
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L2] [SEC-4.1] PR approved by at least one Platform Engineering team member.**
- **Verification:** GitHub PR shows approval from user with "Platform Engineering" team membership in GitHub organization.
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L1] [ENG-4.2a] All commits in PR are signed with GPG or SSH key registered in GitHub.**
- **Verification:** GitHub commit list displays "Verified" badge on all commits. GitHub Actions workflow "verify-commits" check passes.
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.2b] All commit messages follow Conventional Commits format: type(scope): description.**
- **Verification:** GitHub Actions commitlint workflow passes. Commit messages use valid types: feat, fix, chore, docs, refactor, ci, infra.
- **Exception:** No exceptions.

## Infrastructure as Code

**[ ] [L2] [SEC-4.1] terraform plan executed and produces clean plan with no unintended resource deletions.**
- **Verification:** PR description or comment includes terraform plan output. Plan shows only intended creates/updates. No destroy operations unless explicitly documented in ticket.
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L2] [SEC-4.1] tfsec scan passes with 0 HIGH or CRITICAL findings.**
- **Verification:** GitHub Actions tfsec workflow status = passed. tfsec report shows 0 HIGH and 0 CRITICAL severity issues.
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L3] [TEAM-INFRA-01] Terraform state is managed in remote backend (AWS S3 with DynamoDB locking).**
- **Verification:** Terraform configuration includes backend "s3" block with bucket and dynamodb_table specified. No local state files committed.
- **Exception:** Tech Lead approval. Reviewed quarterly.

**[ ] [L3] [TEAM-INFRA-02] Infrastructure changes tested in non-production environment before production apply.**
- **Verification:** PR description includes evidence of successful terraform apply in staging or dev environment with validation results.
- **Exception:** Tech Lead approval. Reviewed quarterly.

**[ ] [L3] [TEAM-INFRA-03] Disaster recovery procedure verified for all stateful resources (databases, storage, queues).**
- **Verification:** Runbook includes DR section with backup verification timestamps. DR test results attached to PR or referenced in ticket.
- **Exception:** Tech Lead approval. Reviewed quarterly.

## Security

**[ ] [L1] [SEC-3.1] Snyk scan shows 0 Critical or High severity findings. Medium findings have tracked Jira tickets.**
- **Verification:** GitHub Actions Snyk workflow status = passed. Snyk dashboard shows 0 Critical and 0 High issues. PR description lists Jira ticket IDs for any Medium findings.
- **Exception:** No exceptions. Findings must be fixed or have CISO-accepted risk waiver.

**[ ] [L1] [SEC-3.2] Gitleaks scan passes with 0 secrets detected.**
- **Verification:** GitHub Actions Gitleaks workflow status = passed. No secrets, API keys, tokens, or credentials detected in commit history or PR diff.
- **Exception:** No exceptions.

**[ ] [L1] [SEC-4.2] No secrets in version control (Gitleaks passes). All secrets stored in AWS Secrets Manager or GitHub Actions secrets.**
- **Verification:** Gitleaks scan passes. Code review confirms all secrets referenced via environment variables sourced from AWS Secrets Manager ARNs or GitHub Actions secrets.
- **Exception:** No exceptions.

**[ ] [L3] [TEAM-SEC-01] AWS IAM roles follow least-privilege principle with documented justification for all permissions.**
- **Verification:** Terraform IAM policy documents include inline comments justifying each permission. No wildcard (*) actions unless explicitly approved by Security Champion.
- **Exception:** Tech Lead approval. Reviewed quarterly.

**[ ] [L3] [TEAM-SEC-02] Network security groups and firewall rules allow only required ports and CIDR blocks.**
- **Verification:** Terraform security group rules include description field documenting purpose. No 0.0.0.0/0 ingress rules unless load balancer or explicitly approved.
- **Exception:** Tech Lead approval. Reviewed quarterly.

## Documentation

**[ ] [L2] [INFRA-DOC-01] Runbook updated or created documenting deployment procedure, rollback steps, and troubleshooting.**
- **Verification:** Git diff shows updates to docs/runbooks/{service}-runbook.md or new runbook created. Runbook includes Deployment, Rollback, Troubleshooting, and Monitoring sections.
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L2] [INFRA-DOC-02] README.md or docs/ updated to reflect infrastructure changes (architecture diagram, dependencies, endpoints).**
- **Verification:** Git diff shows updates to README.md or docs/ directory. Changes document new resources, modified endpoints, or updated architecture diagrams.
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L3] [TEAM-DOC-01] Terraform modules include README.md with inputs, outputs, and usage examples.**
- **Verification:** Each Terraform module directory contains README.md documenting all input variables, output values, and at least one usage example.
- **Exception:** Tech Lead approval. Reviewed quarterly.

## CI / Deployment Gate

**[ ] [L1] [CI-GATE-01] All GitHub Actions CI checks pass (lint, terraform validate, terraform plan, tfsec, Snyk, Gitleaks).**
- **Verification:** GitHub PR checks section shows all required workflows with green checkmarks. No failing or skipped required checks.
- **Exception:** No exceptions.

**[ ] [L2] [CI-INFRA-01] terraform fmt check passes (code formatted according to Terraform style conventions).**
- **Verification:** GitHub Actions terraform-fmt workflow status = passed. No formatting differences detected.
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L2] [CI-INFRA-02] terraform validate passes (configuration is syntactically valid and internally consistent).**
- **Verification:** GitHub Actions terraform-validate workflow status = passed. All Terraform modules pass validation.
- **Exception:** EM can grant one-sprint exemption with written justification.

## Acceptance & Sign-off

**[ ] [L2] [INFRA-ACC-01] Infrastructure changes deployed to staging and validated before production deployment.**
- **Verification:** PR description includes staging deployment timestamp and validation checklist (health checks pass, metrics normal, logs clean).
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L2] [INFRA-ACC-02] Rollback plan documented and verified in staging environment.**
- **Verification:** PR description or linked document includes rollback procedure with step-by-step instructions. Staging rollback test results attached.
- **Exception:** EM can grant one-sprint exemption with written justification.

**[ ] [L3] [TEAM-ACC-01] Monitoring and alerting configured for new infrastructure resources.**
- **Verification:** Terraform code includes CloudWatch alarms, dashboards, or equivalent monitoring resources. Alert thresholds documented in runbook.
- **Exception:** Tech Lead approval. Reviewed quarterly.
