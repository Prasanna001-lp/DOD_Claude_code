## Purpose

This Definition of Done checklist ensures all infrastructure changes meet Commerce Platform's quality, security, and operational standards before merging to main and deploying to production.

Every criterion is:
- **VERIFIABLE** — binary pass/fail with specific tool or artifact
- **TRACEABLE** — linked to source policy or standard
- **LAYERED** — tagged [L1], [L2], [L3], or [L4] per governance model

---

## Layer Definitions

| Layer | Scope | Override Policy |
|---|---|---|
| **[L1]** | Universal — applies to ALL work items | Cannot be overridden. EM + CISO sign-off to modify. |
| **[L2]** | Work-type specific — applies to ALL infrastructure items | EM can grant one-sprint exemption with written justification. |
| **[L3]** | Team-specific — based on Commerce Platform tech stack and domain | Tech Lead approval. Reviewed quarterly. |
| **[L4]** | Story-specific — added by PO or Tech Lead during grooming | PO + Tech Lead agreement. Must not contradict L1–L3. |

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR page shows 2+ approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L3] [ENG-4.1-SEC] PRs touching security-critical infrastructure paths include approval from designated Security Champion.
**Verification:** GitHub PR shows approval from user with Security Champion role for changes to IAM, networking, or secrets management resources.  
**Exception:** EM can waive for non-production environments with documented justification.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub PR commit list shows "Verified" badge on all commits.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions commitlint check passes in CI pipeline.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR uses squash merge strategy. No merge commits permitted on main branch.
**Verification:** GitHub branch protection rules enforce squash merge. PR merge button shows "Squash and merge" only.  
**Exception:** No exceptions.

## Infrastructure-Specific

### [ ] [L2] [SEC-4.1-IAC] terraform plan output attached to PR shows clean plan with no unintended resource deletions.
**Verification:** terraform plan output file attached as PR comment or artifact. Plan contains only expected creates/updates/deletes matching PR description.  
**Exception:** No exceptions.

### [ ] [L2] [SEC-4.1-IAC] PR includes approval from Platform Engineering team member.
**Verification:** GitHub PR shows approval from user in Platform Engineering team.  
**Exception:** No exceptions.

### [ ] [L2] [SEC-4.1-IAC] tfsec scan passes in CI with 0 HIGH or CRITICAL findings.
**Verification:** GitHub Actions tfsec job shows green status with 0 HIGH/CRITICAL severity findings in output.  
**Exception:** No exceptions. Findings must be fixed or have CISO-accepted risk waiver.

### [ ] [L2] [ENG-6.2-ADR] Architecture Decision Record (ADR) created in docs/adr/ for any architecture, data model, or cross-service contract change.
**Verification:** Git diff shows new ADR file in docs/adr/ directory following ADR template format.  
**Exception:** Not required for configuration-only changes with no architectural impact. Tech Lead approval required for exemption.

### [ ] [L2] [ENG-6.2-ADR] Architecture Guild approval documented in PR (comment or approval from Architecture Guild member).
**Verification:** GitHub PR shows approval or explicit comment from Architecture Guild member.  
**Exception:** EM can waive for minor infrastructure changes with documented justification.

### [ ] [L3] [TEAM-INFRA-DR] Disaster recovery procedure verified in non-production environment.
**Verification:** Test execution log or runbook document shows successful restore test from backup/snapshot in staging environment.  
**Exception:** Not required for non-critical infrastructure (dev environments). Tech Lead approval required.

### [ ] [L3] [TEAM-INFRA-RB] Runbook document created or updated in docs/runbooks/ covering operational procedures.
**Verification:** Git diff shows new or updated runbook file in docs/runbooks/ with deployment steps, monitoring, rollback procedure.  
**Exception:** Not required for pure code changes with no operational impact. Tech Lead approval required for exemption.

## Security

### [ ] [L1] [SEC-3.1-SAST] Snyk scan passes in CI with 0 Critical or High severity findings.
**Verification:** GitHub Actions Snyk job shows green status with 0 Critical/High severity vulnerabilities in scan results.  
**Exception:** No exceptions. Findings must be fixed or have CISO-accepted risk waiver.

### [ ] [L1] [SEC-3.1-SAST] All Medium severity Snyk findings acknowledged with tracked Jira ticket linked in PR.
**Verification:** PR description or comment contains Jira ticket links for each Medium severity finding. Jira tickets are in Open or In Progress state.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2-SECRETS + SEC-4.2-CREDS] Gitleaks scan passes in CI with 0 secrets detected (covering tokens, API keys, passwords, credentials).
**Verification:** GitHub Actions Gitleaks job shows green status with 0 secrets found in scan output.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] All third-party dependencies present in approved dependency registry or explicitly approved in PR.
**Verification:** All new dependencies listed in PR description with approval comment from Tech Lead or Security Champion.  
**Exception:** No exceptions for production infrastructure. Dev/test dependencies can be added with Tech Lead approval only.

### [ ] [L1] [SEC-3.3-DEPS] mvn dependency:check (Java) or npm audit (React) passes in CI with 0 Critical CVE findings.
**Verification:** GitHub Actions dependency check job shows green status with 0 Critical severity CVEs in output.  
**Exception:** No exceptions. Critical CVEs must be upgraded or removed.

### [ ] [L3] [SEC-4.2-CREDS] All application secrets stored in AWS Secrets Manager or GitHub Actions secrets (verified in deployment config).
**Verification:** Terraform code or GitHub Actions workflow shows secrets referenced from AWS Secrets Manager ARNs or GitHub secrets variables. No plaintext secrets in config files.  
**Exception:** No exceptions for production infrastructure.
