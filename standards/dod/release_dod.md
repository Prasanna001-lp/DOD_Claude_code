## Code Quality & Standards

**[ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.**
- **Verification:** GitHub PR shows 2+ approvals with at least 1 from senior engineer (title or team role visible).
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.2] All commits are signed with GPG or SSH signing key registered in GitHub.**
- **Verification:** GitHub commit history shows "Verified" badge on all commits in the release branch.
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.2-CONV] All commit messages follow Conventional Commits format: type(scope): description.**
- **Verification:** GitHub Actions workflow "commit-lint" passes. All commits match regex: `^(feat|fix|docs|style|refactor|perf|test|chore)(\(.+\))?: .+$`
- **Exception:** No exceptions.

**[ ] [L1] [ENG-4.2-MERGE] PR merged using squash merge strategy only; merge commits prohibited on main branch.**
- **Verification:** GitHub branch protection rules enforce squash merge. Git log shows single squash commit per PR.
- **Exception:** No exceptions.

## Test Coverage & Quality Assurance

**[ ] [L2] [QA-3.1-REGRESSION] Full regression test suite passes in staging and pre-prod environments before release.**
- **Verification:** GitHub Actions workflow "regression-suite" shows green status for both staging and pre-prod runs. Test report attached to release issue.
- **Exception:** No exceptions.

**[ ] [L2] [QA-3.1-SMOKE] Smoke test suite passes in production environment post-deployment.**
- **Verification:** GitHub Actions workflow "smoke-tests-prod" shows green status within 5 minutes of deployment completion.
- **Exception:** No exceptions.

**[ ] [L3] [TEAM-KAFKA-01] Kafka consumer lag monitoring confirms all consumers are caught up (lag <100 messages) post-deployment.**
- **Verification:** DataDog dashboard "Kafka Consumer Lag" shows all consumer groups with lag <100 for 5 consecutive minutes post-deploy.
- **Exception:** Tech Lead can approve if specific consumer group is known to have expected backlog (documented in release notes).

**[ ] [L3] [TEAM-DB-01] PostgreSQL database migration scripts tested successfully in pre-prod with rollback verification.**
- **Verification:** Migration log in pre-prod shows successful forward migration + successful rollback test. Logs attached to release PR.
- **Exception:** No exceptions for schema changes. Not applicable if release contains zero database migrations.

## Security & Compliance

**[ ] [L1] [SEC-3.1] Snyk scan shows 0 Critical or High severity findings in CI before merge to main.**
- **Verification:** GitHub Actions workflow "snyk-security-scan" passes with exit code 0. Snyk dashboard shows 0 Critical/High issues for release branch.
- **Exception:** No exceptions.

**[ ] [L1] [SEC-3.1] All Medium severity findings from Snyk acknowledged with tracked Jira ticket referenced in PR.**
- **Verification:** Snyk report lists Medium findings. PR description contains Jira ticket links for each Medium finding (format: JIRA-NNNN).
- **Exception:** No exceptions.

**[ ] [L1] [SEC-3.2] Gitleaks scan passes in CI with zero secrets detected before merge to main.**
- **Verification:** GitHub Actions workflow "gitleaks-scan" passes with exit code 0. No secrets detected in scan output.
- **Exception:** No exceptions.

**[ ] [L1] [SEC-3.3-APPROVED] All third-party dependencies are listed in approved dependency registry.**
- **Verification:** GitHub Actions workflow "dependency-check" passes. Script compares package.json + pom.xml against approved-dependencies.yaml and reports 0 unapproved entries.
- **Exception:** No exceptions.

**[ ] [L1] [SEC-3.3-CVE] No dependencies with Critical CVEs older than 5 business days present.**
- **Verification:** npm audit (React) and mvn dependency:check (Java) run in CI and report 0 Critical CVEs with disclosure date >5 business days ago.
- **Exception:** No exceptions.

**[ ] [L1] [SEC-3.3-AUDIT] npm audit (for React) and mvn dependency:check (for Java) run in CI and report 0 Critical findings.**
- **Verification:** GitHub Actions workflow "dependency-audit" passes. npm audit --audit-level=critical and mvn dependency:check both exit 0.
- **Exception:** No exceptions.

## Documentation & Communication

**[ ] [L2] [QA-3.1-NOTES] Release notes prepared in CHANGELOG.md and approved by Engineering Manager.**
- **Verification:** CHANGELOG.md updated with [Unreleased] section moved to version number. PR has approval comment from Engineering Manager stating "Release notes approved for vX.Y.Z".
- **Exception:** No exceptions.

**[ ] [L2] [QA-3.1-ROLLBACK] Rollback plan documented in runbook and tested successfully in staging environment.**
- **Verification:** Runbook file docs/runbooks/release-vX.Y.Z-rollback.md present in repository. Staging rollback test documented with timestamp and success confirmation in PR comment.
- **Exception:** No exceptions.

**[ ] [L2] [QA-3.1-RUNBOOK] Runbook updated if operational procedures changed.**
- **Verification:** Git diff shows changes to docs/runbooks/ if deployment procedures, monitoring, or incident response steps modified. If no operational changes, PR comment states "No runbook updates required".
- **Exception:** Not applicable if zero operational procedure changes.

**[ ] [L3] [TEAM-COMM-01] Release announcement posted in #engineering-releases Slack channel with deployment window and on-call engineer tagged.**
- **Verification:** Slack message in #engineering-releases contains: version number, deployment start time, expected duration, on-call engineer @mention, link to release notes.
- **Exception:** No exceptions for production releases. Not applicable for staging-only releases.

## CI/CD & Deployment Gates

**[ ] [L1] [CI-ALL] GitHub Actions workflows pass: lint, build, unit tests, integration tests, security scans.**
- **Verification:** GitHub PR status checks show all required workflows green: "lint", "build-java", "build-react", "test-unit", "test-integration", "snyk-scan", "gitleaks-scan".
- **Exception:** No exceptions.

**[ ] [L3] [TEAM-BUILD-01] Docker images built and pushed to ECR with semantic version tags (vX.Y.Z) and "latest" tag.**
- **Verification:** GitHub Actions workflow "docker-build-push" completes successfully. ECR repository shows new image tags: vX.Y.Z and latest, both with matching digest.
- **Exception:** No exceptions.

**[ ] [L3] [TEAM-DEPLOY-01] Staging deployment completed successfully with zero failed pods for 10 minutes post-deploy.**
- **Verification:** kubectl get pods -n commerce-platform-staging shows all pods in Running state with 0 restarts for 10+ minutes. Kubernetes dashboard screenshot attached to release issue.
- **Exception:** No exceptions.

## Acceptance & Sign-off

**[ ] [L2] [QA-3.1-NOTES] Engineering Manager sign-off documented in release PR or release issue.**
- **Verification:** GitHub PR or release issue contains comment from Engineering Manager with exact text: "Approved for production release - EM sign-off for vX.Y.Z" with timestamp.
- **Exception:** No exceptions.

**[ ] [L3] [TEAM-PO-01] Product Owner verification completed for all user-facing changes included in release.**
- **Verification:** Release issue contains PO approval comment listing all user-facing features verified in staging, with format: "PO verification complete: [list of features]".
- **Exception:** Not applicable if release contains zero user-facing changes (backend/infrastructure only).

**[ ] [L3] [TEAM-ONCALL-01] On-call engineer confirmed available for 2 hours post-deployment and has access to rollback procedure.**
- **Verification:** Release issue contains on-call engineer comment: "Available for monitoring from [time] to [time+2h]. Rollback procedure reviewed."
- **Exception:** No exceptions for production releases.
