## Code Quality

### CODE-01 [L1] [ENG-4.1]
**[ ]** PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.

**Verification:** GitHub PR shows 2+ approvals with at least 1 from engineer with "Senior" or "Lead" role in CODEOWNERS.

**Exception:** No exceptions.

---

### CODE-02 [L1] [ENG-4.2]
**[ ]** All commits are signed with GPG or SSH key registered in GitHub.

**Verification:** GitHub commit history shows "Verified" badge on all commits in the release PR.

**Exception:** No exceptions.

---

### CODE-03 [L1] [ENG-4.2-CONV]
**[ ]** All commit messages follow Conventional Commits format: type(scope): description.

**Verification:** GitHub Actions commitlint check passes in CI pipeline.

**Exception:** No exceptions.

## Test Coverage & Quality

### TEST-01 [L2] [QA-3.1-RELEASE]
**[ ]** Full regression test suite passes in staging environment with 100% pass rate.

**Verification:** GitHub Actions workflow "regression-suite-staging" shows all tests passed. Test report artifact attached to release PR.

**Exception:** No exceptions. All regression tests must pass before release.

---

### TEST-02 [L2] [QA-3.1-RELEASE]
**[ ]** Full regression test suite passes in pre-prod environment with 100% pass rate.

**Verification:** GitHub Actions workflow "regression-suite-preprod" shows all tests passed. Test report artifact attached to release PR.

**Exception:** No exceptions. All regression tests must pass before release.

---

### TEST-03 [L2] [QA-3.1-RELEASE]
**[ ]** Smoke test suite passes in production environment post-deploy with 100% pass rate.

**Verification:** GitHub Actions workflow "smoke-tests-production" shows all tests passed after deployment. Post-deploy verification comment added to release PR.

**Exception:** No exceptions. Smoke tests must pass to confirm production health.

---

### TEST-04 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** End-to-end order flow test passes in production (cart → checkout → payment → confirmation).

**Verification:** Playwright E2E test "e2e-order-flow-production" passes in post-deploy verification. Test result attached to release PR.

**Exception:** No exceptions for releases touching order or payment services.

---

### TEST-05 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** Kafka event publishing verified for all order state transitions (created, confirmed, shipped, delivered).

**Verification:** Integration test logs show successful event publication to Kafka topics. Event schema validation passes. Evidence attached to release PR.

**Exception:** EM approval required if release does not touch order state machine.

## Security

### SEC-01 [L1] [SEC-3.1-SNYK]
**[ ]** Snyk scan reports 0 Critical or High severity findings.

**Verification:** GitHub Actions Snyk scan job passes with exit code 0. Snyk dashboard shows 0 Critical/High findings for release branch.

**Exception:** No exceptions. Critical/High findings must be remediated or have CISO risk waiver before release.

---

### SEC-02 [L1] [SEC-3.1-SNYK]
**[ ]** All Medium severity findings have tracked Jira tickets created and referenced in release PR.

**Verification:** Release PR description includes Jira ticket links for all Medium findings from Snyk scan. Tickets visible in Jira backlog.

**Exception:** No exceptions.

---

### SEC-03 [L1] [SEC-3.2-SECRETS]
**[ ]** Gitleaks scan passes with 0 secrets detected in CI.

**Verification:** GitHub Actions Gitleaks job passes with exit code 0. No secrets flagged in scan output.

**Exception:** No exceptions.

---

**Verification:** GitHub Actions job "maven-dependency-check" passes. dependency-check-report.html shows 0 Critical vulnerabilities.

**Exception:** No exceptions. Critical CVEs must be upgraded or removed.

---

### SEC-05 [L1] [SEC-3.3-DEP]
**[ ]** npm audit (React modules) reports 0 Critical CVE findings.

**Verification:** GitHub Actions job "npm-audit" passes with exit code 0. npm audit output shows 0 Critical vulnerabilities.

**Exception:** No exceptions. Critical CVEs must be upgraded or removed.

## Documentation

### DOC-01 [L2] [QA-3.1-RELEASE]
**[ ]** Release notes prepared and approved by Engineering Manager.

**Verification:** RELEASE_NOTES.md file present in release PR with EM approval comment. Document includes: version number, release date, features added, bugs fixed, breaking changes, migration steps.

**Exception:** No exceptions.

---

### DOC-02 [L2] [QA-3.1-RELEASE]
**[ ]** Runbook updated if operational procedures have changed.

**Verification:** docs/runbooks/ directory shows updated files with timestamp matching release PR. Changes reviewed by on-call engineer.

**Exception:** EM confirmation comment required in PR if no runbook changes needed.

---

### DOC-03 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** API changelog updated if any REST or GraphQL endpoints changed.

**Verification:** CHANGELOG.md under [Unreleased] section includes all API changes with endpoint paths, HTTP methods, request/response schema changes.

**Exception:** No exceptions if API changes present in release.

---

### DOC-04 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** Database migration scripts documented with rollback instructions.

**Verification:** docs/migrations/ directory contains migration script and rollback script for release version. Scripts tested in staging.

**Exception:** No exceptions if database schema changes present in release.

## Deployment & Rollback Readiness

### DEPLOY-01 [L2] [QA-3.1-RELEASE]
**[ ]** Rollback plan documented and tested in staging environment.

**Verification:** ROLLBACK_PLAN.md file present in release PR. Document includes: rollback trigger criteria, rollback steps, data rollback procedure, verification steps. Evidence of successful staging rollback test attached to PR.

**Exception:** No exceptions.

---

### DEPLOY-02 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** Blue-green deployment configuration verified (both slots healthy before traffic switch).

**Verification:** Deployment logs show both blue and green slots responding to health checks. Load balancer ready for traffic switch. Evidence attached to release PR.

**Exception:** Tech Lead approval required if using rolling deployment instead of blue-green.

---

### DEPLOY-03 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** Kafka consumer lag verified <1000 messages across all consumer groups before deployment.

**Verification:** Kafka monitoring dashboard screenshot attached to release PR showing consumer lag <1000 for all groups. Timestamp within 1 hour of deployment.

**Exception:** EM approval required if lag >1000 with documented mitigation plan.

---

### DEPLOY-04 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** Database connection pool settings verified for new traffic load (if pool size changed).

**Verification:** application.yml or application.properties diff shows connection pool configuration. Load test results attached to PR confirming pool settings handle expected RPS.

**Exception:** No exceptions if release changes database connection pool configuration.

## Acceptance & Sign-off

### ACCEPT-01 [L2] [QA-3.1-RELEASE]
**[ ]** Engineering Manager approval documented in release PR.

**Verification:** GitHub PR shows approval from user with "Engineering Manager" role. Approval comment includes: "Release approved for production deployment."

**Exception:** No exceptions. EM sign-off mandatory for all production releases.

---

### ACCEPT-02 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** Product Owner sign-off obtained if release includes customer-facing features or breaking changes.

**Verification:** GitHub PR comment from PO stating: "PO approval granted for release." Present if release notes include customer-facing changes.

**Exception:** EM can waive PO sign-off for internal-only or hotfix releases with written justification in PR.

---

### ACCEPT-03 [L3] [TEAM-COMMERCE-PLATFORM]
**[ ]** On-call engineer notified and confirmed available during deployment window.

**Verification:** Slack thread link in release PR showing on-call confirmation message. Message timestamp within 24 hours of planned deployment.

**Exception:** No exceptions for production releases.
