## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR approval count shows ≥2 approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key verified by GitHub.
**Verification:** GitHub shows "Verified" badge on all commits in the PR.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MSG] All commit messages follow Conventional Commits format verified by CI lint.
**Verification:** GitHub Actions workflow "commitlint" passes with 0 failures.  
**Exception:** No exceptions.

**Verification:** GitHub merge button shows "Squash and merge" selected. Branch protection rule enforces squash-only.  
**Exception:** No exceptions.

## Security

### [ ] [L1] [SEC-3.1-SNYK] Snyk scan shows 0 Critical or High severity findings in GitHub Actions CI.
**Verification:** GitHub Actions workflow "snyk-security-scan" passes. Snyk dashboard shows 0 Critical and 0 High severity vulnerabilities for the release branch.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.1-SNYK] All Medium severity Snyk findings have tracked Jira tickets linked in PR description.
**Verification:** PR description contains Jira ticket links for all Medium findings listed in Snyk scan output.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2-SECRETS] Gitleaks scan passes in GitHub Actions CI with 0 secrets detected.
**Verification:** GitHub Actions workflow "gitleaks-scan" passes with exit code 0. Gitleaks report shows 0 secrets found.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] All new dependencies listed in approved dependency registry before merge.
**Verification:** All dependencies in package.json (npm) and pom.xml (Maven) match entries in approved-dependencies.yaml in the repository.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] npm audit and mvn dependency:check report 0 Critical CVE findings in CI.
**Verification:** GitHub Actions runs "npm audit --audit-level=critical" and "mvn dependency:check -DfailBuildOnCVSS=9". Both commands exit with code 0.  
**Exception:** No exceptions.

## Documentation

### [ ] [L2] [QA-3.1-NOTES] Release notes prepared in CHANGELOG.md and approved by Engineering Manager (documented approval in release PR or ticket).
**Verification:** CHANGELOG.md contains release notes under version heading. PR or Jira ticket shows approval comment from Engineering Manager with text "Release notes approved".  
**Exception:** No exceptions.

### [ ] [L2] [QA-3.1-ROLLBACK] Rollback plan documented in release runbook and verified in staging environment.
**Verification:** File docs/runbooks/release-{version}-rollback.md exists with steps. Staging deployment log shows successful rollback test execution.  
**Exception:** No exceptions.

### [ ] [L2] [QA-3.1-RUNBOOK] Runbook updated if release changes operational procedures (deployment, monitoring, incident response).
**Verification:** If deployment process, monitoring dashboards, or incident response procedures changed: docs/runbooks/operations.md updated with changes and reviewed by on-call engineer.  
**Exception:** Exception permitted if no operational procedures changed. Document "No runbook changes required" in PR description.

### [ ] [L3] [TEAM-COMMERCE-KAFKA] Kafka schema registry changes documented with backward compatibility verification.
**Verification:** If Kafka schema changed: schema-registry-changelog.md updated. Confluent Schema Registry compatibility check passes with "BACKWARD" or "FULL" compatibility mode.  
**Exception:** Exception permitted if no Kafka schema changes in this release. Document "No schema changes" in PR description.

## CI / Deployment Gate

### [ ] [L1] [CI-UNIVERSAL] All GitHub Actions CI checks pass (build, lint, test, security scan).
**Verification:** GitHub PR status shows all required checks green. No workflow failures in "Checks" tab.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes with cyclomatic complexity ≤10 per method.
**Verification:** SonarQube dashboard shows "Passed" quality gate status. Complexity metrics show 0 methods exceeding complexity 10.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LOC] SonarQube reports no methods exceeding 50 lines of code.
**Verification:** SonarQube "Code Smells" tab shows 0 violations for rule "Methods should not have too many lines".  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports 0 dead code findings in changed files.
**Verification:** SonarQube "Code Smells" tab shows 0 violations for rules "Unused private method" and "Dead store" in files changed by this release.  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-COMMERCE-DB] PostgreSQL database migration scripts tested in staging with rollback verified.
**Verification:** If db/migrations/ contains new files: staging deployment log shows migration success. Rollback script tested by executing down migration in staging clone database.  
**Exception:** Exception permitted if no database migrations in this release. Document "No database changes" in PR description.

## Acceptance & Sign-off

### [ ] [L2] [QA-3.1-NOTES] Engineering Manager approval documented in release PR.
**Verification:** GitHub PR shows approval from Engineering Manager account. Approval comment includes "Production release approved".  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-COMMERCE-RELEASE] Product Owner notified of release and accepts release scope.
**Verification:** Slack message in #commerce-releases channel shows PO acknowledgment with thumbs-up emoji or "Approved" text. Message includes release version and CHANGELOG link.  
**Exception:** No exceptions.

### [ ] [L3] [TEAM-COMMERCE-RELEASE] On-call engineer notified 24 hours before production deployment.
**Verification:** PagerDuty or Slack message to on-call engineer sent ≥24 hours before deployment. Message includes deployment window, runbook link, and rollback plan link.  
**Exception:** Exception permitted for hotfix releases (P1 incidents). Document "Hotfix - on-call notified immediately" in PR.
