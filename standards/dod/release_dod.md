## Overview

This Definition of Done applies to **Release** work items. A release is considered DONE when all criteria below are met and verified. Releases must pass through staging and pre-prod environments before production deployment, with full regression testing and smoke testing post-deploy.

**Layer Legend:**
- **[L1-UNIVERSAL]** — Applies to ALL work items, no exceptions
- **[L2-WORKTYPE]** — Applies to ALL releases
- **[L3-TEAM]** — Commerce Platform team-specific criteria
- **[L4-STORY]** — Release-specific additions (defined during planning)

## Code Quality

### [ ] [L1] [ENG-4.1] PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.
**Verification:** GitHub PR page shows 2+ approvals with at least 1 from senior engineer role.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-SIGN] All commits in PR are signed with GPG or SSH key registered in GitHub.
**Verification:** GitHub PR commits page shows "Verified" badge on all commits.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-FORMAT] All commit messages follow Conventional Commits format: type(scope): description.
**Verification:** GitHub Actions commit-lint check passes in CI pipeline.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.2-MERGE] PR is merged using squash merge strategy only.
**Verification:** GitHub merge button configured to squash-only; main branch history shows squashed commits.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-COMPLEXITY] SonarQube quality gate passes: cyclomatic complexity ≤ 10 per method.
**Verification:** SonarQube dashboard shows Quality Gate status = PASSED with 0 complexity violations.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-LENGTH] No method exceeds 50 lines of code (verified by SonarQube).
**Verification:** SonarQube dashboard shows 0 "method too long" issues.  
**Exception:** No exceptions.

### [ ] [L1] [ENG-4.3-DEAD] SonarQube reports 0 dead code issues (unreachable, commented-out code removed).
**Verification:** SonarQube dashboard shows 0 dead code violations.  
**Exception:** No exceptions.

### [ ] [L2] [IMPLICIT-LINT] Code passes linting checks (ESLint for React, Checkstyle/SpotBugs for Java).
**Verification:** GitHub Actions lint job passes; no linting errors in CI logs.  
**Exception:** No exceptions.

## Test Coverage & Quality

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥80% line coverage on all changed modules.
**Verification:** JaCoCo report in GitHub Actions shows line coverage ≥80% for modified packages.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] JaCoCo reports ≥75% branch coverage on changed modules.
**Verification:** JaCoCo report in GitHub Actions shows branch coverage ≥75% for modified packages.  
**Exception:** No exceptions.

### [ ] [L1] [QA-2.1-COVERAGE] No existing covered code has lost coverage (CI build enforces no coverage regression).
**Verification:** JaCoCo diff report shows 0 lines of previously covered code now uncovered.  
**Exception:** No exceptions.

### [ ] [L2] [QA-3.1-REGRESSION-SUITE] Full regression test suite passes in staging and pre-prod environments.
**Verification:** GitHub Actions regression-tests job shows 100% pass rate in both staging and pre-prod workflow runs.  
**Exception:** No exceptions.

### [ ] [L2] [QA-3.1-SMOKE] Smoke test suite passes in production environment post-deploy.
**Verification:** GitHub Actions smoke-tests job shows 100% pass rate in production workflow run after deployment completes.  
**Exception:** No exceptions.

### [ ] [L2] [QA-3.1-ROLLBACK] Rollback plan documented and tested successfully in staging environment.
**Verification:** Runbook contains rollback procedure; staging rollback test executed and documented in release ticket with timestamp and outcome.  
**Exception:** No exceptions.

## Security

### [ ] [L1] [SEC-3.1-SNYK] Snyk scan shows 0 Critical or High severity findings.
**Verification:** Snyk check in GitHub Actions passes with 0 Critical/High vulnerabilities reported.  
**Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver.

### [ ] [L1] [SEC-3.1-SNYK] All Medium severity Snyk findings have tracked Jira tickets before merge.
**Verification:** Snyk report shows 0 Medium findings OR each Medium finding has a linked Jira ticket number in PR description.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.2][SEC-4.2] Gitleaks scan passes with 0 secrets detected in CI. All secrets stored in AWS Secrets Manager or GitHub Actions secrets (no hardcoded credentials).
**Verification:** Gitleaks check in GitHub Actions passes; code review confirms no hardcoded API keys, tokens, or passwords.  
**Exception:** No exceptions.

### [ ] [L1] [SEC-3.3-DEPS] npm audit (React) or mvn dependency:check (Java) produces 0 Critical findings in CI.
**Verification:** GitHub Actions dependency-check job passes; npm audit and mvn dependency:check show 0 Critical CVEs.  
**Exception:** No exceptions.

## Documentation

### [ ] [L2] [QA-3.1-NOTES] Release notes prepared and approved by Engineering Manager (documented in PR or release ticket).
**Verification:** Release notes document exists in release ticket or CHANGELOG.md; EM approval comment present on release PR or ticket.  
**Exception:** No exceptions.

### [ ] [L2] [QA-3.1-RUNBOOK] Runbook updated if operational procedures changed (documented in PR or release ticket).
**Verification:** If operational changes exist, runbook file updated in Git with commit SHA referenced in release ticket.  
**Exception:** Permitted exception: No runbook update required if no operational procedures changed.

### [ ] [L3] [COMMERCE-PLATFORM-STANDARD] CHANGELOG.md updated with all user-facing changes under [Unreleased] section, then version-tagged.
**Verification:** CHANGELOG.md file contains entry for this release version with dated heading; all merged feature/bug PR entries present.  
**Exception:** No exceptions.

## CI / Deployment Gate

### [ ] [L1] [IMPLICIT-CI] All CI checks pass in GitHub Actions (build, lint, test, security scans).
**Verification:** GitHub Actions workflow status shows all required checks green (build, test, lint, Snyk, Gitleaks, SonarQube).  
**Exception:** No exceptions.

### [ ] [L3] [COMMERCE-PLATFORM-KAFKA] Kafka consumer lag monitored post-deploy; no critical lag (>10k messages) detected.
**Verification:** Kafka lag monitoring dashboard checked 15 minutes post-deploy; all consumer groups show lag <10k messages.  
**Exception:** Permitted exception: Lag spike allowed if acknowledged by on-call engineer with mitigation plan.

### [ ] [L3] [COMMERCE-PLATFORM-DB] PostgreSQL migration scripts executed successfully in pre-prod before production release.
**Verification:** Database migration job logs in pre-prod show 0 errors; schema version matches expected version in release notes.  
**Exception:** No exceptions.

### [ ] [L2] [QA-3.1-NOTES] Engineering Manager sign-off obtained (documented in release ticket or PR).
