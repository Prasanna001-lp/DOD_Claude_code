## Code Quality

**[L1-UNIVERSAL]** These criteria apply to every release, no exceptions.

- [ ] **[L1] [ENG-4.1]** PR has minimum 2 approvals from engineers other than the author, including 1 from a senior engineer or tech lead.  
  **Verification:** GitHub PR approval count shows ≥ 2 approvals. At least 1 approval from an engineer with "Senior Engineer" or "Tech Lead" role in GitHub team settings.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.2-SIGN]** All commits are signed with GPG or SSH key registered in GitHub.  
  **Verification:** GitHub shows "Verified" badge on all commits in the PR. CI enforces commit signature verification.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.2-CONV]** All commit messages follow Conventional Commits format: type(scope): description.  
  **Verification:** GitHub Actions runs commitlint check. CI passes with zero commit message violations.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.2-MERGE]** PR merged using squash merge strategy (no merge commits on main).  
  **Verification:** GitHub PR settings enforce "Squash and merge" only. Main branch protection rule blocks merge commits.  
  **Exception:** No exceptions.

## Test Coverage & Quality

**[L2-WORKTYPE]** These criteria are mandatory for all release work items.

- [ ] **[L2] [QA-3.1-RELEASE-REGRESSION]** Full regression test suite passes in staging and pre-prod environments.  
  **Verification:** GitHub Actions workflow shows successful regression test run in both staging and pre-prod environments. All tests passed. Test report attached to release PR.  
  **Exception:** No exceptions.

- [ ] **[L2] [QA-3.1-RELEASE-SMOKE]** Smoke test suite passes in production environment post-deploy.  
  **Verification:** GitHub Actions post-deploy workflow shows successful smoke test run in production. All critical paths verified. Smoke test report available in workflow artifacts.  
  **Exception:** No exceptions.

- [ ] **[L2] [QA-3.1-RELEASE-ROLLBACK]** Rollback plan documented and tested successfully in staging environment.  
  **Verification:** Rollback procedure documented in `release/rollback-{version}.md`. GitHub Actions workflow shows successful rollback test execution in staging with all services restored to previous version.  
  **Exception:** No exceptions.

**[L3-TEAM]** Commerce Platform team-specific quality gates.

- [ ] **[L3] [TEAM-KAFKA]** Event schema compatibility verified for all Kafka topics modified in this release.  
  **Verification:** Schema Registry compatibility check passes. All consumers confirmed compatible with new event schemas. Test results attached to PR.  
  **Exception:** Tech Lead approval required if backward-incompatible schema change is required with documented consumer migration plan.

## Security

**[L1-UNIVERSAL]** Security gates enforced on every release.

- [ ] **[L1] [SEC-3.1-SNYK]** Snyk scan shows 0 Critical or High severity findings.  
  **Verification:** Snyk CI check passes in GitHub Actions workflow. Scan report shows zero Critical/High findings.  
  **Exception:** No exceptions. Findings must be fixed or have a CISO-accepted risk waiver.

- [ ] **[L1] [SEC-3.1-SNYK]** All Medium severity findings from Snyk have tracked Jira tickets.  
  **Verification:** Jira ticket references present in PR description for all Medium findings shown in Snyk report.  
  **Exception:** No exceptions.

- [ ] **[L1] [SEC-3.2-SECRETS]** Gitleaks scan passes in CI with zero secrets detected.  
  **Verification:** Gitleaks CI check passes in GitHub Actions workflow. Build log shows zero secrets detected.  
  **Exception:** No exceptions.

- [ ] **[L1] [SEC-3.3-DEPS]** No dependencies with Critical CVEs older than 5 business days.  
  **Verification:** Snyk dependency check passes. No Critical CVEs with age > 5 business days shown in scan report.  
  **Exception:** No exceptions.

- [ ] **[L1] [SEC-3.3-AUDIT]** mvn dependency:check (Java) and npm audit (React) produce 0 Critical findings in CI.  
  **Verification:** Maven and npm CI checks pass. Build logs show zero Critical dependency vulnerabilities.  
  **Exception:** No exceptions.

**[L3-TEAM]** Commerce Platform team-specific security requirements.

- [ ] **[L3] [TEAM-POSTGRES]** Database migration scripts reviewed for SQL injection vulnerabilities and include rollback DDL.  
  **Verification:** All migration scripts in `db/migrations/` use parameterized queries. Rollback scripts present with `_rollback` suffix. Security Champion approval recorded on PR.  
  **Exception:** Tech Lead approval if schema change cannot be rolled back (documented in migration comments).

**[L1-UNIVERSAL]** CI quality gates enforced on every release.

- [ ] **[L1] [ENG-4.3-COMPLEXITY]** SonarQube quality gate passes: cyclomatic complexity ≤ 10 per method.  
  **Verification:** SonarQube CI check passes. Quality gate shows zero methods with complexity > 10.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.3-LOC]** No method exceeds 50 lines of code (SonarQube enforces).  
  **Verification:** SonarQube CI check passes. Quality gate shows zero methods with LOC > 50.  
  **Exception:** No exceptions.

- [ ] **[L1] [ENG-4.3-DEAD]** SonarQube reports zero dead code issues (unreachable, commented-out code removed).  
  **Verification:** SonarQube CI check passes. Quality gate shows zero dead code issues.  
  **Exception:** No exceptions.

**[L3-TEAM]** Commerce Platform CI/CD requirements.

- [ ] **[L3] [TEAM-JUNIT]** All JUnit 5 tests pass in CI with zero flaky tests in last 10 runs.  
  **Verification:** GitHub Actions test workflow passes. CI test history shows zero test failures or retries in last 10 runs.  
  **Exception:** Tech Lead approval if flaky test cannot be fixed before release with documented suppression ticket.

  **Verification:** GitHub Actions Playwright workflow passes against pre-prod. Test report shows zero test retries or flakiness.
